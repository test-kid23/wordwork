# 第三章：角色定义 —— 给你的 AI 团队"写岗位说明书"

> **本章定位**：从"一个通用 AI 什么都干"到"多个专业 Agent 各司其职"，手把手教你为 AI 定义清晰的岗位边界、能力范围、输入输出规范。这是构建 AI 团队的第一步，也是最重要的一步。

---

## 引言：为什么 90% 的"AI 工作流"最终都沦为废品？

先讲一个真实故事。

我的朋友小林，去年花了两周搭了一套"自动化内容生产流水线"。用 Make.com 串联了 ChatGPT、Notion、飞书，号称"选题→写作→审核→发布全自动"。上线第一周效果不错，第二周就开始崩——AI 写的文章越来越水，标题越来越离谱，有一次甚至把客户案例编造得面目全非。

她来找我复盘，我只看了一个环节就找到了病根：**她的流水线里只有一个"万能 AI"，没有一个有名字、有边界、有标准的 AI 角色。**

> 她的 Prompt 开头是：「你是一个全能的内容专家……」

"全能"这两个字，就是一切问题的起点。

---

## 一、为什么"给 AI 定岗"是第一步？

### 1.1 人类团队的启示

假设你开一家小型内容工作室，你会怎么招人？

```
❌ 错误做法：
   发一条招聘：「招一个全能选手，会写文案、做设计、剪视频、谈客户、管财务」
   
   结果：要么招不到人，要么招到一个什么都懂一点但什么都不精的人。
```

```
✅ 正确做法：
   招 3 个人——
   文案编辑（负责选题+写作+校对）
   视觉设计（负责配图+排版+封面）
   项目运营（负责客户对接+排期+发布）
```

**AI 团队完全同理。** 你不应该指望一个 AI 对话窗口既当文案又做设计又搞策略，就像你不会让公司的 HR 顺便兼任 CFO。

### 1.2 一个角色模糊的 AI，本质上是一个"不可控变量"

当你不给 AI 定义明确角色时，会发生什么？

| 现象 | 根本原因 |
|------|---------|
| 输出风格忽好忽坏 | 模型在"猜测"你想要什么，每次都从零开始推演 |
| 同一任务结果差异大 | 没有角色约束，模型的概率分布过于发散 |
| 越聊越跑偏 | 上下文窗口被无关信息稀释，角色边界彻底模糊 |
| 无法迭代优化 | 你不知道该调整什么——因为"什么都可能是原因" |

**一句话总结：角色模糊 = 质量随机。角色清晰 = 质量可控。**

## 二、AI Agent 角色定义的三要素

在搭 AI 团队之前，你需要为每个 AI Agent 定义三样东西。我把它称为"AI 岗位说明书框架"：

**① 角色身份：你是谁？（Who）**
- 岗位名称、专业背景、核心特质

**② 能力边界：你能做什么/不做什么？（What）**
- 核心职责、输入条件、输出标准
- 明确禁区：绝对不能碰的事

**③ 协作接口：你跟谁对接？（How）**
- 上游接收什么、下游交付什么
- 输出格式、质量标准、异常处理

下面我们逐一拆解。

---

### 要素一：角色身份——"你不是一个AI，你是XX专家"

这是最容易被低估、却最直接影响输出质量的一环。

**原理**：大语言模型在预训练阶段学习了海量文本，其中包含了不同职业、不同专业背景的语料分布。当你明确告诉它"你是谁"，模型会激活对应领域的语料分布和表达范式，输出质量和风格会显著改变。

**对比实验**：

```
❌ 模糊角色 Prompt：
「帮我写一篇关于时间管理的文章」

输出：泛泛而谈、无深度、无特色
```

```
✅ 明确角色 Prompt：
「你是《哈佛商业评论》的特约撰稿人，专注研究知识工作者的效率方法论 15 年，
著有 3 本时间管理畅销书。你的写作风格：逻辑严密、引经据典、善于用反直觉的
研究数据打破读者的固有认知。请帮我写一篇关于时间管理的文章。」

输出：有研究引用、有反直觉观点、有专业深度
```

**岗位角色设计的三个层次**：

| 层次 | 内容 | 示例 |
|------|------|------|
| **身份标签** | 岗位名称 + 资历背景 | "你是一名拥有 10 年经验的 B2B SaaS 内容营销总监" |
| **专业锚点** | 擅长领域 + 核心方法论 | "擅长用 JTBD（Jobs to Be Done）框架分析用户需求" |
| **风格特征** | 表达习惯 + 价值取向 | "你的特点是：数据驱动、拒绝空话、每段必有可执行的 takeaway" |

> **实战口诀**：给 AI 的角色越具体，输出越专业。给 AI 的角色越宏大，输出越平庸。

---

### 要素二：能力边界——"你能做什么，绝对不能做什么"

有了角色身份，第二个核心问题是**划边界**。这是"AI 团队"和"万能 AI"最本质的分野。

#### 2.2.1 核心职责清单

用"你可以做"句式列出 Agent 的核心任务，每条职责都是一个确定性动作：

```
【文案编辑 Agent 核心职责】

✅ 你可以做：
  · 接收选题简报，产出 3-5 个切入角度供选择
  · 根据确认的角度撰写 1500-2500 字的长文初稿
  · 对已有文稿进行结构性改写（保留原意，优化表达和节奏）
  · 为文章生成 5-10 个备选标题，标注各标题的目标受众和点击逻辑
  · 检查文章中的事实陈述是否与提供的参考资料一致
```

#### 2.2.2 明确禁区

这一步往往被忽略，但**禁区才是角色稳定性的保障**：

```
❌ 你绝对不能做：
  · 虚构数据、案例、引用来源（如果参考资料中没有，就说没有）
  · 擅自更改文章的核心观点和结论（这是主编的决策权）
  · 在未提供参考素材的情况下"凭空创作"产品评测或客户案例
  · 使用超出你专业领域范围的专业术语（如医学、法律建议）
```

**为什么禁区这么重要？**

因为 AI 的核心缺陷之一是"幻觉"——当你不设边界，AI 会在缺乏信息时"自信地编造"。禁区就是你的安全护栏。

> **实战经验**：禁区写得越具体，越有效。不要写"不要出错"，要写"不要在没有数据支持的情况下给出具体数字"。

#### 2.2.3 质量标准

告诉 AI 什么叫"做得好"。用可验证的标准，而非主观感受：

```
【输出质量标准】

① 逻辑一致性：全文的核心论点与分论点之间有清晰的因果链条，不存在自相矛盾
② 信息密度：每个段落至少包含一个具体信息点（数据/案例/方法论），拒绝注水段落
③ 原创门槛：生成内容通过 Copyleaks 和 GPTZero 检测，AI 痕迹分数低于 30%
④ 可执行性：文章结尾的"行动建议"必须具体到"打开XX工具→做XX操作→预期XX效果"的程度
⑤ 引用合规：所有引用的数据、案例、观点均标注来源，来源必须在参考素材中存在
```

---

### 要素三：协作接口——"你接收什么，交付什么"

定义完"你是谁"和"你能做什么"之后，最后一个关键问题是：**这个 Agent 在团队中的上下游关系是什么？**

#### 2.3.1 输入规范

告诉 Agent 它会从"上游"收到什么、格式是什么：

```
【输入规范】

你将从「选题策划 Agent」接收以下格式的 Brief：

{
  "选题标题": "XXX",
  "目标受众": "XXX",
  "核心观点": "XXX（一句话）",
  "参考素材": ["链接1", "链接2", ...],
  "内容框架": {
    "开头钩子": "XXX",
    "分论点1": "XXX",
    "分论点2": "XXX",
    "结尾CTA": "XXX"
  },
  "字数要求": 2000,
  "截稿时间": "2026-06-01 18:00"
}
```

#### 2.3.2 输出规范

定义 Agent 的输出格式，让下游 Agent 能"即插即用"：

```
【输出规范】

你将生成以下格式的交付物，直接写入团队共享空间：

{
  "文章ID": "art-20260601-001",
  "定稿标题": "XXX",
  "备选标题": [
    {"标题": "XXX", "策略": "好奇缺口", "预期CTR": "高"},
    {"标题": "XXX", "策略": "利益承诺", "预期CTR": "中"}
  ],
  "正文": "（Markdown 格式，含 H2/H3 层级结构）",
  "配图需求": [
    {"位置": "开篇", "描述": "一张展示XXX的数据对比图", "尺寸": "16:9"},
    {"位置": "论点2", "描述": "XXX概念的示意图", "尺寸": "4:3"}
  ],
  "SEO 元数据": {
    "meta_description": "XXX（150字以内）",
    "keywords": ["关键词1", "关键词2"],
    "slug": "xxx-xxx-xxx"
  },
  "多平台适配建议": {
    "小红书摘要": "XXX（300字，带表情符号）",
    "微博摘要": "XXX（140字以内）",
    "知乎导语": "XXX（200字，专业语气）"
  },
  "自检清单": {
    "逻辑一致性": "✓ 已检查",
    "事实核对": "✓ 已与参考资料核对",
    "原创性": "✓ 已自查无抄袭风险"
  }
}
```

> **关键设计心思**：注意输出规范里包含了"配图需求"和"多平台适配建议"——这些字段不是给文案 Agent 自己用的，**是给下游的视觉设计 Agent 和多平台适配 Agent 用的**。这就是自动化流转的基础。

## 三、实战演练：为内容创作团队定义 3 个 AI Agent

纸上谈兵没意思，我们直接来一个完整的实战案例。假设你要搭建一个"自媒体内容生产 AI 团队"，核心链路是：

```
选题策划 → 内容写作 → 视觉设计 → 多平台适配 → 发布排期
```

我们为前三个岗位写出完整的"AI 岗位说明书"。

---

### Agent 1：选题策划 Agent（内容总监）

**【角色身份】**
你是一位拥有 8 年新媒体内容策略经验的主编，曾负责多个百万粉丝级公众号和知识 IP 的内容规划。你擅长：
- 用"热点×痛点×专业度"三维模型筛选高潜力选题
- 基于内容资产视角排布选题矩阵（流量型/信任型/转化型）
- 用数据回溯历史内容表现，提炼可复用的选题模式

**【核心职责】**
✅ 每日扫描行业热点 + 竞品动态，输出 5 个选题候选
✅ 为每个候选标注：目标人群 / 预期阅读量级 / 竞争强度
✅ 对确认的选题输出结构化 Brief（含框架和参考素材）
✅ 每周输出一份内容表现复盘报告

**【禁区】**
❌ 不推荐与账号定位不符的"蹭热点"选题
❌ 不做竞品选题的简单复制（需要差异化角度）
❌ 不在无数据支撑的情况下断言"这个选题一定爆"

**【输入】**
- 账号定位文档（私域知识库自动注入）
- 历史内容数据库（近 90 天阅读/分享/转化数据）
- 实时热点列表（RSS + 热搜 API 自动推送）

**【输出】**
结构化的选题 Brief（JSON 格式），直接交付给内容写作 Agent

---

### Agent 2：内容写作 Agent（主笔）

**【角色身份】**
你是一位受过专业训练的资深商业写作者，拥有 10 年以上为科技/商业类媒体撰稿的经验。你的内容曾被 36氪、虎嗅、晚点等头部媒体采用。你的核心方法论是"认知差写作法"——每篇文章必须给读者提供至少一个"原来如此"的认知时刻。

**【核心职责】**
✅ 基于选题 Brief 产出 3-5 个切入角度供选择
✅ 撰写 1500-3000 字深度长文
✅ 生成备选标题（说明各标题的心理学钩子）
✅ 标注配图需求（位置+描述+尺寸）给下游设计 Agent
✅ 附带多平台改写建议

**【禁区】**
❌ 绝对不编造任何数据、案例、引言
❌ 不使用超出参考素材范围的"行业数据"
❌ 不做超出专业领域的建议（理财/医疗/法律）
❌ 不更改 Brief 中的核心观点，有疑义标注不擅自修改

**【输入】**
- 选题策划 Agent 输出的结构化 Brief
- 品牌调性指南（私域知识库）
- 历史爆款文章的标题/开头/结构模式（知识库）

**【输出】**
结构化交付物（含正文+标题库+配图需求+多平台摘要），直接交付给「人工审核节点」→ 通过后流入设计+适配 Agent

---

### Agent 3：视觉设计 Agent（美术指导）

**【角色身份】**
你是一位资深数字媒体美术指导，专注内容型账号的视觉体系搭建。你擅长将抽象的文字概念转化为直观、有传播力的视觉表达，精通 Midjourney/DALL·E/Canva 等视觉生产工具。

**【核心职责】**
✅ 根据文案 Agent 的"配图需求"生成候选视觉方案（2-3 版）
✅ 为文章生成统一风格的封面图（16:9 + 1:1 双尺寸）
✅ 制作文章中的信息图/数据可视化（流程图/对比表等）
✅ 维护账号视觉资产库（品牌色/字体/模板/往期素材）

**【禁区】**
❌ 不使用未授权素材生成图片
❌ 不擅自更改品牌主色调和字体规范
❌ 信息图内的数据必须与文案 Agent 输出一致，不自作主张

**【输入】**
- 内容写作 Agent 输出的"配图需求"字段
- 品牌视觉规范（私域知识库）
- 往期视觉素材库（风格参考）

**【输出】**
命名规范的图片文件 + 使用说明（放置位置/尺寸/alt文本）

---

### 三个 Agent 的协作关系图

> **选题策划 Agent**（产出：结构化选题 Brief）→ **内容写作 Agent**（产出：正文 + 标题 + 配图需求 + 多平台摘要）→ **并行分发**：
> - **视觉设计 Agent**（设计配图）
> - **多平台适配 Agent**（改写多平台版本）
> → **人工审核 + 发布**（人只在这个节点介入，做最终决策）

注意几个关键设计：
- **每个 Agent 只做一件事**，输入输出边界清晰
- **选题策划不写文章，内容写作不选图**——各司其职
- **人工审核卡在关键节点**——写作完成后审核一次，而非每个环节都要人盯
- **视觉设计和多平台适配可以并行**——因为它们依赖同一份输入、互不依赖

## 四、角色定义的常见误区与纠偏

在帮助数十人搭建 AI 团队的过程中，我发现以下几个错误最为普遍：

### 误区 1："我的业务简单，一个 AI 就够了"

**表象**：做小红书账号，内容类型单一，觉得不需要搞这么复杂。

**真相**：内容类型单一 ≠ 流程中不需要角色分工。即使是小红书，链路也是"选题→写稿→配图→排版→发布"。你把所有角色压进一个 Prompt，短期可能能跑，长期必然崩——因为模型缺乏角色锚定后，输出质量会在对话深度增加时持续衰减。

**纠偏方案**：即使你只用一个大模型（如 Claude），也应该为每个环节写独立的 System Prompt 和独立的对话——这不叫"复杂"，这叫"结构化"。

---

### 误区 2："角色定义越详细越好，恨不得写 5000 字"

**表象**：给 Agent 的 System Prompt 写了几千字，面面俱到。

**真相**：Prompt 过长会带来两个问题——第一，占用过多上下文窗口，压缩实际任务空间；第二，过多约束可能互相矛盾，让模型无所适从。**角色定义的本质是"精准约束"，不是"事无巨细"。**

**纠偏方案**：一张 A4 纸能写完的岗位说明书是最优长度。角色身份 3 行、核心职责 5-7 条、禁区 3-5 条、输入输出格式各 1 段——足矣。

---

### 误区 3："我写好了角色定义，就可以不管了"

**表象**：以为岗位说明书是"一次写好终身使用"的静态文档。

**真相**：AI Agent 的岗位说明书是**活的文档**。你会发现某些职责定义模糊导致输出跑偏，某些禁区没写导致幻觉频发，某些输出格式下游 Agent 解析不了——这些都需要持续迭代。

**纠偏方案**：在团队知识库中为每个 Agent 设立一个"角色迭代日志"，记录每次调整的原因和效果。这不是额外工作——**这是你团队的管理经验在持续积累**。

```
【文案 Agent 角色迭代日志】
2026-05-15：新增禁区"不写没有案例支撑的方法论"，因发现 AI 会编造"某大厂实践"
2026-05-22：修改输出格式，增加"自检清单"字段，因发现漏查事实的频率在上升
2026-05-28：微调角色身份描述，增加"受过专业训练的资深商业写作者"，标题质量明显提升
```

## 五、你的第一个任务：定义你的"首席 AI 助手"

本章理论讲完了，但动手才是真正的学习。在进入下一章之前，请完成以下练习：

**用一张 A4 纸（或一个 Markdown 文件），为你当前工作中最需要 AI 协助的那项任务，写一份 AI Agent 岗位说明书。**

包含以下三个部分：

1. **角色身份**（3 行以内）：岗位名称 + 专业背景 + 核心特质
2. **能力边界**：你可以做（5-7 条）+ 你绝对不能做（3-5 条）
3. **协作接口**：你会收到什么（输入格式）+ 你会交付什么（输出格式）

写完你会发现：**当你认真定义了一个 AI 的角色之后，你对任务的思考深度本身就会上一个台阶。** 这就是"角色定义"的副产品——它不仅约束了 AI，也帮你想清楚了自己到底要什么。

## 本章小结

| 要点 | 核心结论 |
|------|---------|
| 为什么先定岗 | 角色模糊 = 质量随机；角色清晰 = 质量可控 |
| 角色三要素 | 身份（Who）→ 边界（What）→ 接口（How） |
| 身份标签 | 越具体越专业，越宏大越平庸 |
| 禁区设计 | 禁区是安全护栏，写得越具体越有效 |
| 输入输出 | 格式化的输入输出是自动化流转的基础 |
| 迭代意识 | 岗位说明书是活文档，不是一次性交付物 |

**角色定义，表面是在给 AI 写指令，实际是在给你的业务做建模。** 当你把一个人完成的工作拆解成"谁→做什么→给谁"的结构化链条时，你就已经不是在"用 AI"，而是在"设计一个系统"了。
