🤖 AI 团队建设

AI 团队搭好了
但怎么知道它在退步？

长期运维指南

📝 写在前面：我有一套 AI 团队跑了半年，最大的感受是——搭起来只需要一个周末。让它持续好用，需要你像管真人团队一样管它。真人团队你会看绩效、做 1v1、调组织架构。AI 团队也一样——它会悄悄退化，而等你"感觉不对劲"的时候，可能已经退步三个月了。这篇不讲新架构，只讲一件事：怎么监控、怎么迭代、怎么控制成本。

━━━━━━━━━━━━━━

1 你的 Agent 在悄悄退步吗？

别靠感觉。用量化指标。

📝 写作 Agent 看这三个数

📊 人工修改率
怎么量：你改动超过 30% 的初稿比例
⚠️ 警觉线：连续 3 篇 > 30%

📊 标题点击率
怎么量：实际点击 / 曝光（平台后台数据）
⚠️ 警觉线：连续 5 篇低于你近期的均值

📊 AI 输出 vs 你的终稿差异
怎么量：核心观点是否有偏差
⚠️ 警觉线：出现 2 次以上立场漂移

写作 Agent 最容易出的问题是"风格漂移"——刚开始产出的文章有你的味道，三个月后变成了 Claude 的"平均脸"。因为你可能悄悄进化了写作风格，但 Agent 的 Prompt 没跟上。解法：每 10 篇把你自己写的 3 篇喂给知识库，让它重新校准。

💻 编码 Agent 看这两个数

📊 人工修改行数占比
怎么量：PR 中你改的行数 / 总行数
⚠️ 警觉线：连续 3 个 PR > 40%

📊 一次通过率
怎么量：你 Review 无实质修改就合并的 PR 比例
⚠️ 警觉线：连续 5 个 < 30%

💡 真相：有时候编码 Agent 的"变差"不是它的问题——是你的项目变复杂了，代码规范变了，但 Agent 的 System Prompt 还是半年前的。它没变，是你进步了，它没跟上。

🔍 审查 Agent 看一个数就够了

漏报率：你发现了审查 Agent 没发现的问题。连续 2 个 PR 有漏报 → 立即检查 Prompt。

⚠️ 注意：审查 Agent 是最容易被忽视的退化点。它不直接产出代码，你不会天天看它的输出。但它是你的最后一道防线——防线悄悄变薄了，你可能要出了 Bug 上线了才知道。

━━━━━━━━━━━━━━

2 建立你的"迭代日历"
别想起来才改

📅 每周（5 分钟）
☐ 扫一眼 Agent 产出，有没有明显的退步迹象
☐ 看一条 AI 领域新闻（模型更新、工具上新）

📅 每月（30 分钟）
☐ 跑一次质量基准测试——用固定测试用例对比各 Agent 输出
☐ 清理知识库：去重、过期标记
☐ 翻 Prompt CHANGELOG，删掉上个月被证明无效的改动
☐ 检查 API 账单：有没有任务能用更便宜的模型？

📅 每季度（2 小时）
☐ 模型选型评估：有没有性价比更高的新模型可替换
☐ 工作流重构：有没有更简洁的方式完成同样的事
☐ Agent 大扫除：删掉/合并没用或低效的 Agent
☐ 能力对齐：你的水平进步了，Prompt 需要升级

💡 一句话记住：关键不在于"做得到多好"，在于持续做。每周 5 分钟 + 每月半小时，累计一年，和那种"搭完就不管了"的差别，不是一个量级。

━━━━━━━━━━━━━━

3 Prompt 怎么管才不乱？

三个月前写的 Prompt，现在想改——但旧版本已经丢了。改完之后发现质量不如以前，但已经覆盖了原文件。

这种事我发生两次之后，建了一个最简单的版本管理体系：

📁 Prompt 版本目录结构

prompts/
├── writing-agent/
│   ├── v1.0.0-system.md（初始版）
│   ├── v1.1.0-system.md（加多样性约束，解决选题同质化）
│   └── v1.2.0-system.md（优化标题逻辑）
├── CHANGELOG.md（每个版本改了啥、为什么）
└── test-cases/
       └── benchmark.md（10 个固定测试 Brief）

📌 三条铁律

① 改 Prompt 必建新版本。
直接覆盖原文件 = 永远回不去。

② 每次改动写清楚原因。
"优化了一下"不算。要写："因为选题 Agent 连续推荐同质话题，在 Prompt 中加了多样性约束。"

③ 改前后跑同一组测试 Brief。
对比输出质量，别靠"感觉变好了"。

━━━━━━━━━━━━━━

4 什么时候该换模型？

不是越新越好。模型更新 ≠ 你的 Prompt 适配新模型。很多人的 AI 团队"衰退"，起因就是换了新模型但没调 Prompt。

🔔 新模型发布（如 Claude 4）
➜ 先在非关键 Agent 上试 1 周，对比基准用例

🔔 当前模型产出持续下降
➜ 先检查 Prompt 是不是该调了——模型不会自己变差，可能是你变了

🔔 API 费用超出预算
➜ DeepSeek 做 Fallback，非关键任务先切

🔔 某任务新模型显著优于当前
➜ 跑 A/B 盲评——同样 Brief 新旧各出一版，你蒙眼打分。连续 5 次优→切

━━━━━━━━━━━━━━

5 成本控制：你的 API 账单里
至少 40% 是冤枉钱

打开你的 API 账单看一眼。如果所有任务都在用 Claude Sonnet，好消息是你有省钱空间。

数据格式化、渠道改写、标签生成——这些任务用 Claude Haiku（成本 1/10）或 GPT-4o-mini 完全够。只有深度写作、复杂推理、策略分析才需要 Sonnet。

💰 以月产 30 篇文章为例：

全 Sonnet：¥200-300
Haiku 做渠道改写 + DeepSeek 做备选写作：¥80-120

💡 一句话记住：省下的钱够你再开一个 Midjourney 订阅。

━━━━━━━━━━━━━━

写在最后

AI 团队不是搭完就可以放羊的系统。

它像一个新入职的员工——第一个月你会仔细看他的产出、慢慢教他你的标准、定期做绩效评估。AI 团队需要的是一模一样的管理节奏。

区别在于：这个"员工"不会主动要求涨薪，不会跳槽，也不会在你骂他的时候委屈。但他会悄悄退步——而等你发现的时候，已经晚了。

每周 5 分钟，每月半小时。这点投入，换来的是一个持续变好而不是持续变差的 AI 团队。
