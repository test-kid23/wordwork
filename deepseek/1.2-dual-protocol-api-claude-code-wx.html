1 先分清三种 API 形态

DeepSeek 目前同时提供三套接口，选错容易绕远路。

① OpenAI Chat Completions（老接口）

🔹 兼容性最好，几乎所有 OpenAI 生态工具都能直接接

🔹 model 填 deepseek-v4-pro 自动指向最新正式版

🔹 适合已有 OpenAI 代码、只想换模型的情况

② OpenAI Responses API（新接口）

🔹 端点：https://api.deepseek.com/v1

🔹 用 client.responses.create() 调用

🔹 适合新写的代码，官方推荐的现代化写法

③ Anthropic API 协议（新接口）

🔹 端点：https://api.deepseek.com

🔹 价值最大的一点：Claude Code 及整个 Claude 生态工具，改两行环境变量即可接入

🔹 这也是这篇的重点

一句话总结：写新代码选 Responses API，接现有工具链选 Anthropic 协议，老项目懒动就继续用 Chat Completions。

2 切换实操：真的只要两行

以 Claude Code 为例，核心配置就两个环境变量：

export ANTHROPIC_BASE_URL="https://api.deepseek.com"
export ANTHROPIC_AUTH_TOKEN="sk-你的DeepSeek密钥"

（Windows 下用 setx 永久设置，macOS/Linux 用 export 写入 shell 配置。）

设置完成，在项目目录敲 claude，跑的就是 deepseek-v4-pro 了。模型默认走正式版，也可以用 --model 参数显式指定。

完整三步：

1️⃣ 在 DeepSeek 开放平台申请 API Key（sk- 开头）

2️⃣ 配置上面两个环境变量

3️⃣ 进项目目录启动 claude，正常干活

整个切换不动任何项目配置、不装新工具、不重建工作流——这就是 Anthropic 协议兼容的价值。

3 但先别高兴太早：三个差异必须知道

切换简单，不等于零成本。DeepSeek 的思考实现与 Claude 原生机制并不完全一致，实测中有三处差异值得提前了解。

差异一：思考内容的字段不同

Claude 流式输出中，思考过程走 thinking 字段；DeepSeek 流式输出中，思考内容在 reasoning_content 字段。Claude Code 客户端内部做了适配，用户无感知；但自研代码直接解析流式结果时，字段对不上，会拿不到思考内容，需要单独处理。

差异二：推理强度控制方式不同

Claude 用 thinking 参数控制思考模式（开/关 + 预算）；DeepSeek 用 reasoning_effort 控制推理强度，共三档：

⚙️ none：不思考，直出 → 翻译、改写、格式化
⚙️ high：深度推理 → 写代码、改 Bug、长文分析
⚙️ max：极致推理 → 复杂架构、Agent 长任务

日常使用建议：简单任务 none，主力任务 high，疑难杂症 max。盲目开 max 不会更聪明，只会更慢更贵。

差异三：工具调用的兼容边界

标准工具调用（读文件、写文件、跑命令）基本无感；但个别 Claude 特有交互（部分权限确认、hook 机制）在 DeepSeek 端没有对应实现。迁移前最好把项目里用到的工具和钩子列一份，逐项验证。

4 迁移前测试清单

正式切换前，建议按这份清单过一遍，几分钟就能测完：

✅ 基础对话：问一个项目相关问题，确认回答正常
✅ 文件读写：让它在项目里实际改一个文件
✅ 命令执行：让它跑一条终端命令
✅ 长上下文：丢一个超过 10 万字符的文件，问其中的细节
✅ 工具调用：跑一个走 MCP 或自定义工具的流程
✅ 流式思考：用 API 直连方式确认 reasoning_content 字段的格式

5 切换后省多少：算一笔真实账

费用是多数人最关心的问题。以 V4-Pro 正式版定价为准：

💰 输入：¥3 / 百万 token（缓存未命中），¥0.025 / 百万 token（缓存命中）
💰 输出：¥6 / 百万 token

⚠️ 注意：以上是当前旧价，新价格已公布，8 月 17 日 00:00 起生效，采用峰谷定价。高峰时段（9:00-12:00、14:00-18:00）Pro 输出涨到 ¥27/M，空闲时段 ¥13.5/M。当前旧价（输出 ¥6/M）只剩最后几天窗口。

对比同档闭源模型，旧价这个量级通常低一个数量级。缓存命中的输入价格更是低到可以忽略——同样的对话反复问、Agent 多轮工具调用，命中缓存后成本趋近于零，这是长上下文 Agent 场景最值钱的一条。

⚠️ 再叠加一个现实：DeepSeek 官方已公布新价格方案，8 月 17 日 00:00 起生效，Pro 高峰输出涨到 ¥27/M（旧价 ¥6/M 的 4.5 倍）。
✅ 旧价窗口只剩最后几天——现在跑通流程、固化方案，比涨价后再折腾划算得多。涨价后，时间策略（把重活安排在空闲时段）会成为新的省钱命门。

6 什么时候不建议切

这是迁移文章里少有人写的一段，但对决定是否动手很关键。

1️⃣ 重度依赖 Claude 独家能力的项目
比如大量使用 extended thinking 特殊写法、深度绑定 hook 生态的团队，建议保留 Claude 原版。

2️⃣ 自研代码直连流式接口的
需要先完成 reasoning_content 字段的适配，否则收不到思考内容。

3️⃣ 稳定性要求极高、不愿当小白鼠的场景
V4 Pro 刚转正式版，可以等一两个小版本迭代稳定后再全面迁移。

迁移不是"二选一"的非此即彼。更务实的做法是：把重活（成本大头）切过去，把依赖 Claude 独有能力的场景留在原处，两边并行跑一个月，用真实数据做决定。
