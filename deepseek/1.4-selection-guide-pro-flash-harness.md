# 选型指南：V4-Pro、V4-Flash、Harness 怎么组合最划算

> DeepSeek 系列 · 第 4 篇（第一部分完结篇）
>
> 模型有了、接口通了、框架也开源了——那到底怎么组合最省钱？这篇给出三套可抄的方案。

---

## 写在前面

前三篇讲完了 V4 Pro 正式版、双协议 API、Harness 开源。信息很多，但很多读者真正的困惑是同一个：**这些东西摆在我面前，我该选哪个、怎么组合、花多少钱？**

这篇就是来解决这个问题的。先把三件套的角色说清，再给出三套可直接套用的方案（个人 / 团队 / 高并发），最后算一笔真实账。

先给结论：**Pro 干重活、Flash 跑量、Harness 当躯干——三件套各司其职，混用才是省钱的关键。**

---

## 一、先分清三件套的定位

**DeepSeek V4-Pro**：旗舰模型。写复杂代码、深度推理、长上下文分析、疑难 Bug，这些"重活"是它的主场。1.6T 参数、1M 上下文、DeepSWE 62.7，都是它的名片。

**DeepSeek V4-Flash**：轻量模型。定位是"量大管饱"：简单任务、批量处理、翻译改写、日常问答。质量够用，价格便宜一个量级，并发上限还高得多。

**DeepSeek Harness（DSH）**：不是模型，是 Agent 框架。负责把上面的模型接到真实世界——读文件、改代码、跑命令、编排多个 Agent。选什么模型不冲突，Harness 都能驱动。

三件套的关系打个比方：**Pro 是高级技工，Flash 是流水线工人，Harness 是包工头。** 高级技工不能天天干流水线，流水线工人干不了精细活，包工头负责按活分人——各司其职，效率最高，成本最低。

几个关键判断：

1. **Flash 输出是 Pro 的三分之一**（旧价），新价高峰时段 Flash ¥9/M vs Pro ¥27/M，比例不变——同量级任务，Flash 依然便宜 3 倍；
2. **缓存命中的价格仍是"地板价"**：Pro 空闲缓存命中 ¥0.15/M，虽然比旧价涨了 6 倍，但比高峰未命中 ¥4.5/M 仍便宜 30 倍。**同样的内容反复用、对话上下文重复传，命中缓存后成本依然趋近于零**——这是 Agent 多轮工具调用场景的省钱命门；
3. **Pro 并发只有 500**，Flash 有 2500——高并发批量场景，Flash 是唯一现实选项；
4. **时间策略成为新变量**：高峰 vs 空闲差价一倍，把重活安排在空闲时段（深夜、凌晨、午休），能直接省一半。

## 三、方案 A：个人写作自动化（预算最低）

**画像**：独立创作者、自媒体人，用 AI 写稿、改写、排版，偶尔让 AI 读长文档。

**组合**：V4-Flash 为主 + V4-Pro 做精修

- 初稿、改写、翻译、摘要 → 全部走 Flash，量大利薄；
- 长文档分析、关键稿件精修、复杂结构设计 → 切 Pro，贵但必要；
- Harness 用 Headless 形态跑脚本，把"取素材 → 初稿 → 校对 → 排版"串成流水线。

**月成本估算**：以每天写 3000 字、读 5 篇长文计，Flash 承担 80% 量、Pro 只精修。旧价下月支出通常在 **几十元以内**；新价生效后（8 月 17 日），若安排在空闲时段，月支出预计在 **百元左右**，仍远低于同档闭源模型。

**关键词**：少用 Pro，善用缓存，让 Flash 扛大旗。

## 四、方案 B：团队研发助手（质量优先）

**画像**：中小团队，用 AI Agent 辅助开发：读代码、改 Bug、跑测试、代码审查。

**组合**：V4-Pro 为主 + Harness Web UI 多 Agent + Flash 做外围

- 核心开发任务（改 Bug、写模块、代码审查）→ 全部 Pro，质量优先；
- Harness 起 Web UI 工作台，多 Agent 分工：一个搜代码、一个改文件、一个跑测试；
- 文档生成、日志分析、临时脚本 → Flash 兜底，别浪费 Pro 的额度。

**月成本估算**：5 人团队、每天 20 个 Agent 会话计，依赖缓存命中率高（同一个项目反复读）。旧价下月支出通常在 **几百元量级**；新价生效后，若安排在空闲时段，月支出预计在 **千元左右**，对比同档闭源模型仍具优势。

**关键词**：Pro 保质量，缓存提效率，Harness 把团队工作流固化下来。

## 五、方案 C：高并发批处理（吞吐优先）

**画像**：批量内容生产、数据清洗、客服话术、大规模文本处理。

**组合**：V4-Flash 全量 + 多 Key 分流 + Headless 脚本

- 全部任务走 Flash：2500 并发上限，够开几十个并行任务；
- 多个 API Key 分流，进一步摊平并发压力；
- Harness Headless 模式写批处理脚本，定时任务自动跑；
- 质量敏感的任务单独抽出来走 Pro 抽样质检，不用全量。

**月成本估算**：以每天处理 100 万 token 文本量计，旧价下 Flash 输出 ¥2/M，月支出在 **百元量级**；新价生效后，Flash 空闲输出 ¥4.5/M，月支出预计在 **二百元左右**，仍远低于 Pro 成本。

**关键词**：Flash 全量 + 并发吃满 + Pro 只做质检抽检。

## 六、一句话决策口诀

把三种方案压缩成一张速查：

| 场景 | 主力 | 辅助 | 核心思路 |
|------|------|------|----------|
| 个人写作 | Flash | Pro 精修 | 少用 Pro，缓存兜底 |
| 团队研发 | Pro | Flash 外围 | 质量优先，工作流固化 |
| 高并发批处理 | Flash | Pro 质检 | 并发吃满，抽检兜质量 |

**口诀：重活 Pro，跑量 Flash，编排用 Harness；缓存是命门，窗口期要珍惜。**

不管哪种方案，有三条铁律通用：

1. **能命中缓存就命中缓存**——同一个项目、同一批素材反复用，缓存命中价是地板价；
2. **Pro 只干 Pro 该干的活**——简单任务丢给 Flash，别让高配做杂活；
3. **时间策略是涨价后的新命门**——把重活安排在空闲时段（深夜、凌晨、午休），直接省一半；
4. **旧价窗口只剩最后几天**——8 月 17 日 00:00 新价生效，现在跑通方案，涨价后才有确定性。
