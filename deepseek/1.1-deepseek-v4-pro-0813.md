## 一、深夜的一场静默升级

事情发生在**前一天的深夜**。

没有任何预告，DeepSeek 官网的"模型 & 价格"页面悄然更新：模型名称从 `deepseek-v4-pro-preview` 变成了 `deepseek-v4-pro-0813`，定价保持不变。API 文档同步更新，模型参数、基准测试数据全部换新。

最戏剧化的一幕是：官方随后发布了一份公告，但**不到 24 小时又被撤回了**。目前 API 文档中仍显示 0813 版本，官方公告却已从官网消失。

这种"深夜发布、公告撤回"的操作，在业界并不常见。有几种解读：

1. **版本校验还没完成**——发现数据或兼容性问题，先撤下公告，等修好再重新发布；
2. **刻意低调**——后训练驱动的迭代，不需要像新架构那样大张旗鼓；
3. **渠道冲突**——同期 Harness 开源抢了风头，公告策略临时调整。

无论真实原因是什么，一个事实很清楚：**DeepSeek V4 Pro 正式版已经上线，API 里填 `deepseek-v4-pro` 就会自动指向这个最新版本**。

## 二、不是换发动机，是换调校

先搞清楚一个关键事实：**这次升级不是新架构，架构和参数量几乎没变。**

V4 Pro 依然是：
- 总参数 **1.6T**，MoE 架构，每 token 激活约 **49B**；
- 上下文 **1M token**，最大输出 **384K token**；
- 注意力采用 **CSA（压缩稀疏注意力）+ HCA（高度压缩注意力）** 的混合方案。

相比 V3.2，V4 系列在推理时的 FLOPs 降至约 **27%**，KV Cache 需求降至约 **10%**——这套架构从设计之初就是为"低成本大规模推理"服务的。

那 0813 到底改了哪？答案是**针对性后训练**（post-training）。

打个比方：发动机没换，但 ECU 程序、调校参数、训练数据都换了一轮。同样的硬件，跑出来的性能判若两车。

具体到推理方式上，V4 Pro 提供了三档推理强度，通过 `reasoning_effort` 参数控制：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| `none` | 非思考模式，直出结果 | 翻译、改写、格式化等低难度任务 |
| `high` | 深度思考，充分推理 | 复杂编程、数学、长文档分析 |
| `max` | 极致思考，长时间推理 | 最难的 Agent 任务、竞赛级问题 |

这一步的升级，直接反映在了 Agent 能力上。

## 三、Agent 能力暴涨 390%：数字背后是什么

官方给出了三组关键的内部基准对比（预览版 → 0813 正式版）：

| 基准 | 预览版 | 0813 | 涨幅 |
|------|--------|------|------|
| DeepSWE（软件工程 Agent 任务） | 12.8 | **62.7** | +390% |
| NL2Repo（自然语言生成代码仓库） | 38.5 | **61.5** | +60% |
| DSBench-Hard（全栈高难度编码） | ~33 | **67.2** | 约翻倍 |

**390% 的涨幅，翻译成人话是：上一版模型在"自主完成软件工程任务"这件事上几乎等于不会，这一版终于学会了。** 从 12.8 到 62.7，是从"不可用"到"勉强可用"再到"开始好用"的跨越。

再来看第三方独立的 BenchLM 数据（V4 Pro 的 `high` 推理模式）：

- 编程：SWE-bench Verified **79.4%**、LiveCodeBench COT **89.8%**、Codeforces Rating **2919**
- 推理：GPQA Diamond **89.1%**
- 长上下文：MRCR 1M token **83.3%**
- 智能体：BrowseComp **80.4%**
- 数学：HMMT **94.0%**

几个值得注意的点：

1. **编程能力是第一梯队**。SWE-bench 79.4%、Codeforces 2919 分，这两个数字已经摸到闭源顶级模型的门槛。
2. **长上下文是杀手锏**。1M token 下的 MRCR 83.3%，意味着把整本书、整个中型代码仓库直接喂进去，依然能精准检索并回答。
3. **Agent 能力不只是"会写代码"**。BrowseComp 80.4% 说明模型在"打开网页、找信息、给出结论"这类自主任务上同样能打。

但也要冷静：**DeepSWE 是官方内部基准，外部复现数据有限**。第三方实测中，有观点认为 Pro 相对上个月的 Flash（DeepSWE 54.4）提升幅度没有官方数字那么夸张。所以对 390% 这个数字，正确的姿势是：**方向可信，幅度打折看**。

## 四、这次改动最大的其实是接口

如果说模型能力是"软升级"，那接口就是"硬升级"——**这次 V4 Pro 带来的最大实际变化，是 API 协议兼容性。**

之前 DeepSeek 只提供 OpenAI 风格的 Chat Completions 接口。而现在，新增了两套协议：

1. **OpenAI Responses API**：`base_url="https://api.deepseek.com/v1"`，用 `client.responses.create()` 直接调用；
2. **Anthropic API 协议**：`base_url="https://api.deepseek.com"`，**可以直接兼容 Claude Code 等基于 Anthropic 协议的工具**。

这意味着什么？**一大批基于 Anthropic 协议的生态工具，现在理论上只需要改 `base_url` 和 API Key，就能接到 DeepSeek 上跑。**

对 Claude Code 用户来说，这是一件大事：不用换工具、不用改工作流，改两行配置就能用上 `deepseek-v4-pro`，费用直接降一个量级。

标准 OpenAI Chat Completions 接口依然保留，`model` 填 `deepseek-v4-pro` 自动指向最新版本。

⚠️ 一个需要留意的地方：DeepSeek 的 thinking 实现与 Claude 的 extended thinking 并不完全相同，流式输出时 `reasoning_content` 字段的格式有差异。**大厂 Agent 框架做了协议适配，但自研代码直接对接时，这块需要单独处理。**

## 五、价格没涨，但 8 月 17 日起新价生效

这次上线，定价暂时维持旧价，但**新价格已公布，将于 8 月 17 日 00:00 生效**。官方采用**峰谷定价**：高峰时段（北京时间 9:00-12:00、14:00-18:00）为全价，其余为空闲时段，价格为高峰时段的一半。

> "We plan to raise the overall pricing for DeepSeek API services in the near future, with a significant increase expected."
> （我们计划在近期上调 DeepSeek API 服务的整体定价，预计涨幅会相当大。）

空闲时段价格相对温和（Pro 空闲输出 ¥13.5/M，是旧价的 2.25 倍），但高峰时段涨幅高达 350%。这意味着**时间策略会成为省钱的关键**——把重活安排在空闲时段（深夜、凌晨、午休），能省一半。

叠加 Anthropic 协议兼容性，一个很现实的操作是：**趁旧价还在（8 月 17 日前），把现有 Claude 生态的工具链迁过来试用，在涨价前跑通、评估、锁定方案。** 涨价后，时间策略（空闲时段跑重活）会成为新的省钱命门。

## 六、现在该做什么

说了这么多，落地到行动上，建议分三步：

**第一步：先跑一个真实任务。**
不用换工作流，直接用现有的 Claude Code 或 Codex，改 `base_url` 和 Key，拿手头一个真实的中型项目试一遍。重点看三件事：Agent 任务完成度、长上下文表现、`high`/`max` 推理档位下的输出质量。

**第二步：算一笔账。**
拿过去一个月的真实用量，套用 V4-Pro 的价格表算一遍。如果每月 API 支出能省 50% 以上，迁移价值就非常大——尤其在官方涨价之前。

**第三步：盯住两个时间点。**
一是 **8 月 17 日 00:00 新价生效日**（生效前是最后的低成本窗口期），二是 Harness 的迭代（DeepSeek 自己的 Agent 框架刚开源，属于开发者预览版，后续很可能快速演进）。

**一句话总结这次升级：**
> 模型还是那个模型，但调校换了、接口开了、Agent 能力翻了几倍。DeepSeek 明显在下一盘大棋——用最低的成本把模型接进一切现有的 Agent 生态。V4 Pro 正式版，就是这盘棋的关键落子。
