DeepSeek Harness 开源
它终于有了自己的 Vibe Coding 入口

模型是大脑，Harness 是身体——这次 DeepSeek 把"壳"也开源了

📝 写在前面：很多人问：DeepSeek 模型这么强，为什么没有一个像 Claude Code 那样的官方编程入口？每次都要借别人的壳（比如改 base_url 来接 DeepSeek）？

DeepSeek 给的答案不是"做一个 Claude Code 复刻"，而是更野的一步：直接把"壳"开源了。

DeepSeek Harness（DSH）深夜发布，官方定位是 Agent 执行框架——不是新模型、不是 API 客户端，而是把模型接到文件系统、终端、网页、代码工具和其他 Agent 的"身体"。

这篇讲清楚三件事：Harness 到底是什么、5 分钟怎么跑起来、它和 Claude Code 的区别。

1 Harness 是什么：模型是大脑，Harness 是身体

先纠正一个常见误解：Harness 不是模型。

它是运行 Agent 的"外壳"或"骨架"——负责组织上下文、调度工具调用、管理任务执行。模型负责"想"，Harness 负责"干"：

🔹 读项目文件、定位代码 → 模型说"我要看这个文件" → Harness 去读

🔹 修改代码、跑命令 → 模型说"这样改" → Harness 去执行

🔹 报错了 → 模型说"再看一眼日志" → Harness 继续跑

本质区别一句话：没有 Harness，模型只能聊天；有了 Harness，模型才能干活。

这套设计有一个很"DeepSeek"的特点：Everything is a plugin（一切皆插件）。Harness 建立在 Cordis 之上，模型适配器、工具注册、Session Log，甚至 Agent Loop 本身（驱动 Agent 不断"思考→行动→观察"的主循环）都是可替换插件。

这意味着什么？别的框架的"功能"，在 Harness 里是"零件"。换模型、换工具、换循环逻辑，都不需要动主体。

2 5 分钟跑起来：真没骗人

上手门槛低得不像一个刚开源的框架。环境要求：Node.js（新版本）+ 一个 DeepSeek API Key。

三步启动：

# 1. 安装并启动 Web UI
npx @deepseek-ai/dsh web

# 2. 浏览器打开 http://localhost:3574
# 3. 填入 API Key（或配环境变量 DEEPSEEK_API_KEY），选择模型和 Agent Preset

npx @deepseek-ai/dsh web 一条命令，起的是一整个本地 Agent 工作台：可以在里面打开项目、让它读代码、改文件、跑命令、根据报错继续修——像把 Claude Code 的交互界面搬到了浏览器里。

但 Web UI 只是其中一种形态。Harness 一共提供六种使用方式：

🖥 Web UI：浏览器工作台 → 日常开发
🖥 TUI：终端界面 → 命令行重度用户
⚙️ Headless：无界面脚本 → 自动化、CI/CD
⚙️ ACP：Agent Client Protocol → 接入外部 Agent 平台
⚙️ JSON-RPC：标准远程调用 → 服务端集成
⚙️ Python SDK：编程调用 → Python 生态

一条命令就能跑，六种形态按需切换——这设计思路，是奔着"人人都能用、处处都能接"去的。

3 它和 Claude Code 的区别：成品 vs 零件箱

既然有了官方入口，很多人会拿它和 Claude Code 对比。这里说清楚定位差异：

Claude Code 是"封装好的产品"：开箱即用，交互、权限、体验都打磨好了，但内部逻辑是黑盒，不能改。

Harness 是"可组装的零件箱"：什么都给你零件，但"怎么组装"的自由度和工作量都在自己手上。

📋 模型：Claude Code 绑定 Claude ｜ Harness 任意模型（适配器可换）
📋 定制性：Claude Code 低，黑盒 ｜ Harness 高，一切皆插件
📋 使用形态：Claude Code CLI 为主 ｜ Harness 六种形态
📋 上手成本：Claude Code 极低 ｜ Harness 低（Web UI）到中等（自研插件）
📋 适合人群：想拿来就用的人 ｜ 想深度控制 Agent 的人

所以这不是"谁替代谁"的关系：Harness 想做的，是像 Linux 之于操作系统那样，成为 Agent 世界的底层框架。模型层已经开源，框架层也开源了，剩下的是生态。

4 真正的杀手锏：多 Agent 编排与可观测性

如果只是"又一个编程入口"，Harness 不值得单开一篇。它真正值得关注的是两个设计：

① 多 Agent 编排

Harness 支持主 Agent 拆分子 Agent：主 Agent 接到任务后，可以分派给多个子 Agent 并行干活（一个查资料、一个写代码、一个跑测试），最后汇总结果。

这不是"套壳聊天"，而是把复杂任务拆成流水线的能力。团队里的"AI 员工"从此可以分工协作。

② Session Log 可观测性

Harness 会把 Agent 的一举一动记录成 Session Log——模型当时看到了什么、调用了什么工具、拿到了什么结果，全部可回放。

价值在出问题的时候：Agent 干砸了，能像复盘录像一样，一步步看它当时是怎么想的、哪一步走错了。这对生产环境审计和调试是刚需。

5 现实提醒：这是 Developer Preview

说完了亮点，说几句冷静话。

Harness 目前是 Developer Preview（开发者预览版），官方原文明确提示：后续迭代可能出现破坏兼容性的修改（breaking changes）。翻译一下：现在适合玩、适合研究、适合搭个人工作流，但别急着拿它支撑生产级业务，等版本稳定。

⚠️ 另外，Harness 目前主要面向代码任务（读项目、改文件、跑命令），"多 Agent 编排 + 长任务"这些高阶能力还在快速演进中。跟着版本迭代走，是现在最合理的姿势。

6 组合拳怎么打：V4 Pro + Harness 的完整图景

把这两天的事放在一起看，DeepSeek 的组合拳就很清晰了：

🔹 V4 Pro 正式版：更强的模型（DeepSWE 12.8 → 62.7）

🔹 双协议 API：接进一切现有生态（Claude Code 改两行配置就能用）

🔹 Harness 开源：自己的 Agent 执行框架，从模型到框架全链路开源

这三步合起来，DeepSeek 在讲的故事是：用开源把 Agent 技术栈的每一层都握在自己手里——模型层、协议层、框架层。这和当年 Linux + Apache + MySQL + PHP 组合拳的路线如出一辙。

💡 对普通用户最直接的收益：现在有一整套从模型到框架都开源、成本还低的 Agent 技术栈可以随便玩。
