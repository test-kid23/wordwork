DeepSeek 把 Agent 装进了桌面软件

Harness v0.2 实测——免 Node 环境、免申请 API Key，插件和定时任务全搬进了图形界面

📝 写在前面：想试试 Agent，很多人卡在同一步：装环境。

Node.js 版本不对、npm 装不上、命令敲完不知道该访问哪个端口、打开浏览器一片白。对开发者只是几分钟的事，对不写代码的人，这就是终点——不是不想用，是进不去门。

DeepSeek 显然看懂了这件事：九月底的 Harness v0.2 预览版，直接把整套东西打成了 macOS 和 Windows 安装包。这篇重点讲三件事——门槛到底降了多少、插件与定时任务怎么用、预览版阶段必须提前知道的坑。

1 这次变的是门槛，不是能力

先把时间线摆清。Harness 八月中旬开源时，标准用法是这样的：

npx @deepseek-ai/dsh web

这行命令背后藏着四个前提：机器上装了 Node.js、npm 能正常拉包、知道怎么开终端、看到端口后知道用浏览器打开。四项里卡住任何一项，流程就断了。

九月底的 v0.2 把这条路换成：去官网下载安装包 → 双击安装 → 登录 → 选工作区。

三个关键减法：

① 不用装 Node。
桌面端内置完整运行环境，Windows 上也不需要单独配 Node 和 pnpm。

② 不用申请 API Key。
登录 DeepSeek 账号就能用账户余额跑任务，界面里能直接看余额和用量。对非开发者，这一步省掉的是最劝退的环节。

③ 不用开浏览器。
它本身就是桌面应用，文件、代码、结果都在窗口里。

💡 一句话记住：能力没变，可进入性变了。

这件事的意义常被低估。Agent 产品真正的竞争对手不是别的 Agent，而是"装不起来"——用户流失最多的环节，永远在第一次启动之前。

2 装完第一眼：四个模式、一个工作区

首次启动会走一遍引导，核心就两个动作：登录（DeepSeek 账号或填 API Key 都行）、选工作区。

工作区就是它被允许读写的文件夹。这里给一条实操建议：专门建一个文件夹给它用，比如 D:\agent-workspace，不要指到桌面、下载目录，更不要指到整个用户目录。原因后面"三个坑"里会说。

进去之后看到的东西：中间是对话与任务执行过程，侧栏是文件预览、代码 diff、插件管理、余额与用量。

工作模式有四个：

🔹 标准：日常开发与文件处理，默认选它
🔹 PTC：偏程序化、需要精确控制执行步骤的任务
🔹 极简：任务单一、想省 token、要快
🔹 创造：实验性，让它自己写插件、改插件

模式不是"高级 / 低级"的关系，是"约束多 / 约束少"的关系。极简模式给它的自由度最小，跑得快、花钱少；创造模式放开权限，能改自己的插件，也最需要盯。

3 插件管理页：把"装插件"搬进界面

Harness 的设计理念是"一切皆插件"——模型适配器、工具、会话、沙箱、界面本身，都可以换成插件。开源版里这件事得靠命令行和配置文件，v0.2 把它做成了界面：

🔹 输入 npm 包名就能装，不用敲命令
🔹 已装的插件可以停用、卸载
🔹 每个插件能看介绍和来源

官方给的数字是：约 60% 的用户在用第三方插件。这个比例不低，说明社区生态已经跑起来了——但同时也意味着，插件质量参差不齐。

还有一个更激进的功能：创造模式。直接用自然语言描述需求，让它自己写一个插件或改一个现有插件，生成后即时生效、持久保存。等于把"扩展能力"这件事也交给模型自己做了——下一节会实际跑一遍，看它到底能做到什么程度。

❌ 看到名字眼熟的包就装
❌ 不看它申请什么能力
✅ 插件本质是跑在本机的代码，能读文件、能执行命令——装来源不明的包，等于给它同等权限。先看来源，再在独立工作区里试

4 自动化任务：AI 开始值班

v0.2 内置了可按需开启的自动化任务插件。开了之后，可以把重复性工作设成定时任务，并且能看每次运行的记录、调整执行频率、修改任务指令。

这是 Harness 从"我提问它回答"变成"它按点自己干活"的分界线。可落地的场景：

🔹 每天早上把指定来源的行业信息汇总成一页纸
🔹 每周固定时间跑一次依赖检查，出问题才叫人
🔹 每月初把上月单据文件夹归档，生成索引台账
🔹 每天定时跑日志，把异常行摘出来

但定时任务的风险比手动任务高一个量级：没人盯着，它按既定权限自己跑。所以设任务时遵守两条——先只读、后写入；写入类任务先让它在副本目录里跑一周，确认行为稳定再放开。

5 一句话实测：5 分半，做出一个悬浮番茄钟

官方给过一个很适合新手的玩法：让它自己写一个插件。我照着试了一遍。

我输入的那句话：帮我写一个「番茄时钟」插件

用时 5 分 24 秒。它回的结果是一行字："番茄时钟悬浮插件已做好、装好并验证通过。"

我没有写一行代码，也没有手动装插件——装插件这一步是它自己做的（对比上一节手动输 npm 包名）。交付的东西就在桌面上：一个悬浮小窗，标题是 🍅 番茄时钟，顶部两个切换「专注 / 短休息」，中间 24:59 的大字倒计时，底部一个「开始专注」按钮。

那五分钟里它干了什么，其实分四段：拆需求（要两档、要倒计时、要悬浮窗）→ 写插件代码 → 装进桌面端 → 自己跑一遍验证。最后那句"验证通过"是它自测的结论，不是我的。

我盯的四个验收点：

① 计时是不是真的在走——不是画了个静态界面

② 两个档位是否按预期——专注 25 分钟、短休息 5 分钟

③ 切换后倒计时是否正确重置

④ 关掉窗口再打开，状态还在不在

前三条这版基本过关，第四条要看具体实现——这也是这类"现场生成的小工具"最常见的短板：界面像样了，状态持久化、多屏缩放、系统通知这些边角还没顾上。截图里的 24:59 是刚启动那一秒，原样贴出来，不做修饰。

这类活的能力边界在哪：

✅ 能做：界面类、单机状态类、交互明确的工具——计时器、便签、悬浮待办、简易计算面板
⚠️ 难做：要账号体系、要后端数据、要大权限（麦克风、屏幕录制）的东西
❌ 别指望：一次出成品级。图标、边界情况、异常处理，通常还要追加两三轮

🎯 这个实测最值得记的一点：不是"5 分钟做了个番茄钟"，而是需求到工具之间的路被压平了。

以前想到一个小工具，得先算一笔"值不值得为它学一门技术、装一套环境"的账；现在这笔账不用算了——先做出来用着，不好用再让它改。

【图4】一句话换来的成品：插件是它自己写好又自己装上的，我只提供了一个需求

6 四项实验功能，现在能用到什么程度

创造模式上一节已经跑过了，这里说剩下四项。v0.2 的插件页里挂了四项实验性功能，成熟度差别不小：

智能体团队：让多个 Agent 分工。方向对，但还处在早期——现在更稳的做法是自己用指令把任务拆开跑。

自动授权审核：给工具调用加一道确认机制。建议默认开着，尤其是涉及删文件、跑脚本、装依赖的动作。

自动化任务：前面讲过了，目前最实用的一项。

语音输入：本地语音识别包，基于 SenseVoice，下载体积约 1GB。好处是识别在本地跑，录音不出机器；代价是首次要占硬盘、老机器上会慢一点。开会记录、口述需求这类场景值得开。

💡 一个判断：四项里只有"自动化任务"现在就能进日常工作流，其余三项建议先当试验田。

7 路线图：哪一步会真正改变用法

官方提了六件事，按"落地后会改变什么"排一下：

① 更强的沙箱与更高的安全性。
这是地基。沙箱够硬，大家才敢让它跑更多命令、碰更多文件。现在很多人的用法还是"小活交给它、大活自己来"，卡的就是这一层。

② 增强的智能体团队。
从"我手动拆任务"变成"它自己组队"，这会直接决定复杂项目的上限。

③ 个性化长期记忆。
跨会话不用重复交代背景。对每天用的人，这一条省下的是最烦的那部分重复劳动。

④ 浏览器与 GUI 自动化。
我认为这是对普通用户影响最大的一条——大量真实工作发生在没有 API 的系统里（后台管理系统、老旧客户端、内部网页）。能操作界面，等于把可自动化的范围扩大一个数量级。

⑤ 远程与移动访问。
手机派活、回家看结果。听起来是便利功能，实际会改变"任务时长"的容忍度——长任务可以在通勤路上启动。

⑥ 多人会话共享。
团队协作的入口，适合把一套跑通的流程直接交接给同事。

另外官方明确说过，会专门针对 Harness 环境调优模型——后续版本说明里"特定框架专项优化"这类表述，就是这个承诺的兑现方式。对使用方来说这意味着：升级 Harness 不只是拿新功能，还关系到模型效果。

8 上手三步和三个坑

三步走：

📅 第 1 步 下载安装，登录账号（或用 API Key），建一个专用工作区文件夹

📅 第 2 步 先给一个"看得见结果"的小活——整理一个文件夹、把一份 PDF 转成表格、给一段代码补测试。目的是摸清脾气，不是压榨性能

📅 第 3 步 再上自动化任务，从只读类任务开始

三个坑：

☐ 坑一：工作区指得太宽——指到用户主目录等于把整个账号的文件都交给它，专用文件夹是唯一正确做法
☐ 坑二：定时任务一上来就写入——无人值守 + 写权限 = 出问题没人拦，先只读跑一周
☐ 坑三：把预览版当稳定版用——官方明说会快速迭代、可能有不兼容改动，重要流程留手工兜底，别在关键节点前升级

写在最后

从 npx 到双击安装，看起来只是打包方式变了，实际是把一类人从"用不上"变成"用得上"。

开源版服务的是愿意折腾的开发者；桌面版服务的是"我只想把活干完"的人。DeepSeek 八月先给前者，九月给后者——这一步走完，Harness 才算真正有了产品形态。

门槛只是入场券，能不能真把活干掉是另一回事

不过要把话说全：上面那个番茄钟，本质还是一个几百行的小工具——界面、计时、状态都在本地，没有依赖任何外部系统。真正的考验在完整项目：多文件、多依赖、跑起来还得跑对。
