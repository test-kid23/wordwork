# 官方公开 7 组提示词：不用写代码，一句话给 Agent 装上新零件

> 创造模式实操——7 个案例各是什么、三条能直接抄的指令、装完要过的五道关。

---

## 写在前面

给 Agent 加功能，过去只有两条路：等官方更新，或者自己写插件。

第一条路要等，第二条路要会。绝大多数人卡在第二条——不是不会写 JS，是不知道一个插件该长什么样、接口怎么接、装在哪、怎么自检。

十一月二日，DeepSeek 把这条路直接铺到了脚下：官方公开了 7 组中英文提示词，覆盖 3D 场景、可视化教具、设计工作台、视频剪辑台这些案例。你要做的只有三件事——打开创造模式、粘进去、按发送。

但它有个前提得先说清：**创造模式不是新功能**。它八月就跟着 Harness 一起发布了。这次新给的是"配方"——把别人试出来的提示词摊开给你看。

这反而更值得写：配方能复现，demo 不能。

## 一、不是新功能，但到了该学的时候

先把时间线摆正，免得被"重磅上线"这类说法带偏。

**八月十三日**，Harness 开源，设计理念是"一切皆插件"——模型适配器、工具、界面、甚至 Agent 循环本身都能换。创造模式（Creator Mode）就在那时候有了：用自然语言描述需求，让它自己写一个插件、装进客户端、即时生效。

**十一月二日**，官方放出一支一分半的演示视频和 7 组提示词。功能没变，变的是**信息差**——以前得自己想明白"怎么描述才能让它写出能跑的插件"，现在有人把答案打印出来了。

**十一月七日**，一批开发者吐槽插件兼容性：DSH 一升级，插件轻则失效、重则让客户端起不来。Harness 负责人当天回应，说兼容性在持续改进，并提到**官方插件市场**正在路上——"有了官方市场，一切才会好起来"。

**十一月十日**，官方披露平台日活突破 154 万，同时启动**插件开发者 Token 激励计划**。

四件事连起来看，结论很清楚：**前三个月解决的是"能不能装"，这个月解决的是"值不值得装"。** 有人用、有回报、有市场，插件这件事才真正立起来。

所以现在学，不算早，也不算晚。

## 二、7 组提示词，各是什么货色

官方给的七个案例，难度和用途差得很远。我按"上手难度"和"适不适合先抄"排了一下：

| 案例 | 它证明的能力 | 上手难度 | 建议 |
|------|------------|---------|------|
| 用量 / 成本仪表盘 | 读自身运行数据 | ★ | **第一个抄这个** |
| 海报设计工作台 | 专业工具型界面 | ★★ | 想做出片效果的选它 |
| 论文阅读器（保留原版式） | 文档解析 + 排版还原 | ★★ | 有论文阅读习惯的选它 |
| 像素风主题 | 改整个客户端界面 | ★★ | 好玩，但别在主力环境试 |
| Transformer 3D 可视化 | 把抽象机制做成可交互教具 | ★★★ | **最出片，适合发朋友圈** |
| 多轨视频剪辑台 | 复杂交互 + 时间线状态管理 | ★★★★ | 别当第一个 |
| 3D 地标馆（铁塔 / 长城 / 紫禁城） | 3D 资源与场景组织 | ★★★★ | 吃显卡，老机器容易卡 |

三个判断：

**先抄仪表盘。** 十一月官方自己新增了一个实验性统计插件，能看上下文占用、缓存命中、工具耗时——说明这类需求是真需求，而且它最容易验证对错（数字对不对一眼就知道）。

**Transformer 可视化是最值得发的一条。** 把注意力机制、层与层的数据流做成能转能点的 3D 模型，这个案例的说服力最强，因为它同时证明了"能写 UI"和"能讲清抽象概念"。

**3D 地标馆别当第一个。** 它不是难在提示词，是难在机器——三个城市级场景，集显笔记本跑起来会明显掉帧，容易让人误判成"插件写得差"。

## 三、三步跑通，五分钟上手

**第一步：确认版本。**

创造模式在 0.2 之后的版本里都有，但为了拿到最好的效果，建议升到最新。十月十七日那次更新要求 Harness ≥ 0.2.1-rc.1 才能吃到模型的完整适配，低于这个版本，生成质量会打折。

**第二步：建一个专用工作区。**

新建一个空文件夹，比如 `D:\dsh-lab`，专门给这类实验用。原因在第六节——插件是本机代码，权限等同于你自己。别在放合同、放代码仓库的目录里跑未知插件。

**第三步：切创造模式，粘提示词，发送。**

模式切换在界面上，选"创造"（Creator）。然后粘贴、回车。它会自己读插件 SDK 文档、写代码、打包、安装、自检——整个过程在对话区可见。

官方提示词库在这里（中英文各一套）：

```
https://cdn.deepseek.com/harness/dsh-creator-mode-prompt-collection-en.html
```

**一个必须注意的点**：官方给的是英文提示词，直接粘也能跑，但产出往往带英文界面。想让它出中文界面，在提示词末尾加一句"所有界面文案用简体中文"即可。

## 四、三条可以直接抄的指令

下面三条不是官方原文，是我按官方思路改的：换了参数、加了验收标准、把界面语言固定成中文。改的原因很简单——官方那版是给"看演示"用的，这三条是给"自己用"用的。

**指令一：用量看板（三十秒见效）**

```
帮我做一个「用量看板」插件，悬浮在窗口右侧，要求：
1. 显示今天和本周的 token 用量、缓存命中率、估算花费
2. 每 30 秒自动刷新，数据从本地会话记录里读
3. 深色底、浅色字，数字用等宽字体
4. 只读，不写任何文件，不调用任何外部接口
5. 所有文案用简体中文

做完后告诉我：它读了哪些文件、怎么算的命中率、刷新失败会怎样。
```

**验收点**：数字会不会动；关掉重开还在不在；它读的文件范围是不是只在会话目录里。

**指令二：Transformer 3D 可视化（出片用）**

```
做一个「Transformer 解剖台」插件：用 3D 方式展示一层 Transformer 的前向过程。
1. 输入一句话后，能看到 token 化 → 位置编码 → 注意力 → 前馈 的动画流程
2. 鼠标可拖动旋转、滚轮缩放，点击某一层能看到该层的张量形状
3. 注意力权重用连线粗细表示
4. 单文件实现，零外部依赖，不加载网络字体和贴图
5. 界面中文

做完先自己跑一遍，确认能正常拖拽和点击，再交给我。
```

**验收点**：随便输一句话能不能跑通；拖动会不会卡死；断网还能不能用（零外部依赖的意义就在这里）。

**指令三：自己的小窗（把每天要看的三件事做成组件）**

```
做一个「今日三件事」小窗插件，常驻桌面角落：
1. 显示三条待办，可以直接点勾选完成
2. 每天零点自动清空勾选状态，内容保留
3. 支持快捷键呼出和隐藏
4. 数据存本地文件，路径放在插件自己的数据目录
5. 界面中文，极简风格

做完告诉我数据存在哪个文件、换机器怎么迁移。
```

**验收点**：勾选后重开是否还在；零点是否真的重置；数据文件位置是否可预期（能不能备份）。

三条指令的共同点：**都写清了"怎么算做完"**。这是让创造模式出活的关键——它靠自检闭环工作，你不给验收标准，它就只能靠猜。

## 五、装完要过五道关

插件装上只是开始，能不能用是另一回事。按这五条过一遍：

| 关卡 | 怎么查 | 不合格的信号 |
|------|--------|------------|
| **持久化** | 关掉客户端重开 | 数据没了、设置恢复默认 |
| **权限边界** | 看它读了哪些目录 | 读了工作区之外的文件 |
| **升级兼容** | 下次 DSH 升级后重开 | 客户端起不来、插件报错 |
| **卸载干净** | 插件页停用并卸载 | 目录里残留文件、设置项还在 |
| **异常提示** | 断网 / 删掉数据文件后重开 | 静默失败、白屏、无任何提示 |

第三条要特别留意。十一月七日那波吐槽，核心就是这一点：DSH 源码页一直标着"会有破坏性更新"，版本一升，插件可能不只是不能用，还会把客户端带崩。官方承诺的插件市场就是为了解决它——但市场还没上线，现在只能自己留个心眼。

**实用做法**：装新插件前，把 `插件目录` 整个复制一份到别处；升级 DSH 后如果起不来，把这份复制回去，至少能恢复工作环境。

## 六、四个真实的坑

**① 插件就是本机代码。**

它能读文件、能执行命令、能联网。装一个来源不明的插件，等于给了它和你一样的权限。判断标准：官方提示词库里的、社区里有人长期维护的、能看清源码的，优先；来路不明的，只在隔离目录里试。

**② 一次生成 ≠ 视频里的效果。**

官方自己在发布说明里写了：视频里部分案例经过多轮对话微调，单次生成可能和演示有细微差异。这句话翻译过来就是——**别拿演示当标准**。第一次跑出来丑一点、少个功能，是正常的，追加两轮修改通常就能补上。

**③ 改动越深，升级越容易挂。**

只加一个侧边面板的插件，升级后大概率还能用；改了整个界面主题、替换了主循环的插件，升级后挂掉的概率极高。想要稳，就做"加法"（多一个窗口），别做"替换"（换掉原来的东西）。

**④ 别在主力工作区跑实验。**

这既是为了数据安全，也是为了排查方便——插件出问题时，一个干净的工作区能让问题定性得快得多。

## 七、什么活值得让它写，什么别

**值得让它写的：**

- 自己每天要重复三次以上的动作——查状态、拼格式、算个数；
- 一次性看板——项目周期内看数据，用完就扔；
- 教学与演示——把抽象概念做成能转能点的东西；
- 内部小工具——只有自己用，不需要文档、不需要多人协作。

**别让它写的：**

- 多人共用的工具——兼容性、权限、升级都是坑，交给正式开发；
- 涉及敏感数据的——插件权限太大，出了问题说不清；
- 需要长期维护的——单文件、少注释、AI 生成的代码，三个月后自己都读不懂；
- 对稳定性要求高的——预览版客户端 + 实验性功能，双重不稳定。

一句话判断：**这个工具如果坏了，会不会耽误正事？** 会，就别用插件扛。

## 八、往后看：官方插件市场意味着什么

十一月七日 Harness 负责人的回应里，有一句信息量很大的话：插件兼容性和版本管理在持续改进，**官方插件市场**是关键一步。

对普通用户，这意味着以后装插件会像装 App：有审核、有版本、有一键更新，不用再自己去 npm 里翻包、也不怕升级把客户端搞崩。

对会写插件的人，十一月十日的 Token 激励计划是第一批变现口——写得好有人用，能换回 Token。至于这条路能走多远，取决于官方市场什么时候真的上线。

顺带一句传闻层面的判断：有分析认为，如果 Harness 出带官方插件市场的重大版本，就意味着 V4.1 Pro 正式版不远了。**这只是推测，官方从未给过时间表**，当参考可以，别当排期依据。

## 写在最后

创造模式真正改变的不是"AI 能不能写代码"——那件事早就有答案了。

它改变的是**"想要一个小工具"到"手上有一个小工具"之间那段路的长度**。以前这段路要走过"值不值得学、值不值得做"两道算术题；现在这段路是五分钟、一次粘贴。

但插件不是软件产品。它是"给自己用的东西"——够用、能改、随时能扔，才是它的正确形态。把它当产品用，就会在第一次升级崩溃时学到教训。
