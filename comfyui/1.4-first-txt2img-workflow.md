# 第一个定制工作流：文生图完整管线

> 从零搭建你的第一个 txt2img 工作流。不是 Ctrl+D 加载默认模板——是从空白画布一步步搭，每一步知道为什么、做什么、能改什么。这个工作流会成为你以后所有复杂流程的底盘。

---

## 别加载默认模板，自己搭

默认模板（`Ctrl+D`）是给你看"ComfyUI 长什么样"用的。它没问题，但你用了它就不会理解"每个节点放在那的原因"。

这一篇我们从空白画布开始，把"文生图"这条完整管线手搭一遍。六个节点、五根线、每步讲清楚。搭完你就知道：一个 txt2img 工作流到底在做什么。

---

## 第一步：加载模型 —— Load Checkpoint

**操作**：双击空白 → 搜 `Load Checkpoint` → 回车。

这个节点是工作流的起点。它加载你的主模型文件（放在 `models/checkpoints/` 下的 `.safetensors` 文件）。

点开节点上的下拉菜单，选你放进去的模型。如果你之前按上一篇的推荐下了 Z-Image-Turbo FP8 或 SDXL，这里就能看到。

**Load Checkpoint 有三个输出口**：
- **MODEL**（蓝色）：核心生成模型
- **CLIP**（黄色）：文本理解模型——用来把你的 prompt 文字转成 AI 能理解的数据
- **VAE**（橙色）：图像编解码器——后续用来把潜空间数据转成图片

这三个输出口，在整个工作流里都会被用到。它就像一个"三合一工具箱"——一次加载，三个组件全拿到了。

**为什么不用分开加载？** 大部分主流模型已经把这三个组件打包在一起了。但如果你的模型比较特殊（比如 VAE 是独立文件），可以用 `Load VAE` 节点单独加载并覆盖。

---

## 第二步：写 Prompt —— CLIP Text Encode

**操作**：双击空白 → 搜 `CLIP Text Encode` → 回车。**做两次**，一个写正 prompt、一个写负 prompt。

CLIP Text Encode 的功能：把你写的文字（"一只猫在桌上喝咖啡"）转换成 AI 模型能理解的数学表示（条件向量）。

**连线**：把 Load Checkpoint 的 **CLIP** 输出口连到两个 CLIP Text Encode 节点的 **CLIP** 输入口。

**一个接正 prompt，一个接负 prompt。**

**正 prompt（你想要什么）**：

```
a cute orange tabby cat sitting on a wooden desk, drinking coffee from a white mug, warm sunlight from window, cozy atmosphere, photorealistic
```

**负 prompt（你不想要什么）**：

```
bad quality, blurry, deformed hands, extra fingers, distorted face, watermark, text, signature
```

实际使用时，写正 prompt 就行了。负 prompt 写一个通用模板存着，大部分场景能复用。不用每次都琢磨"负 prompt 怎么写才精准"——AI 出图的问题大多不是负 prompt 能解决的，是模型和采样参数的事。

---

## 第三步：设分辨率 —— Empty Latent Image

**操作**：双击空白 → 搜 `Empty Latent Image` → 回车。

这个节点创建一张"空白画布"——但不是像素画布，而是**潜空间画布**（latent space）。AI 生图不是在像素空间算的，是在潜空间——一种 AI 内部使用的压缩表示形式。

**参数设置**：
- `width`：宽度。512 起步，不建议直接上 1024（容易爆显存，而且大图一次不一定好看）。**先在小尺寸跑通，再放大。**
- `height`：高度。同上。
- `batch_size`：一次生成几张。默认 1。别改太高，一张一张来。

常见比例：
- **1:1 方形**：512×512、768×768、1024×1024（头像、产品图）
- **3:2 横版**：768×512、1152×768（公众号封面）
- **2:3 竖版**：512×768、768×1152（小红书、手机壁纸）
- **16:9 宽幅**：896×504、1280×720（视频封面）

---

## 第四步：采样 —— KSampler（核心）

**操作**：双击空白 → 搜 `KSampler` → 回车。

KSampler 是整个工作流里最重要的节点。这里面的每一个参数都直接影响出图结果。

**连线**：

```
Load Checkpoint → MODEL 输出口 → KSampler 的 model 输入口（蓝色线）
CLIP Text Encode(+) → CONDITIONING 输出口 → KSampler 的 positive 输入口（绿色线）
CLIP Text Encode(-) → CONDITIONING 输出口 → KSampler 的 negative 输入口（绿色线）
Empty Latent Image → LATENT 输出口 → KSampler 的 latent_image 输入口（紫色线）
```

四个输入都接好之后，KSampler 就拿到了它需要的全部信息：模型、正向 prompt 条件、负向 prompt 条件、潜空间画布。

**参数解释（别背，理解逻辑就行）**：

| 参数 | 作用 | 新手推荐值 |
|------|------|-----------|
| **seed（种子）** | 随机起点。"固定"种子 = 每次生成一模一样的图 | 0（随机）/ 固定值（复现用）|
| **control_after_generate** | 生成后种子自动变化策略 | fixed（固定）/ increment（+1）/ randomize（随机） |
| **steps（步数）** | 采样迭代次数。太少了糊，太多了边际收益递减 | 20-30（SDXL），4-8（Turbo 模型） |
| **cfg（CFG Scale）** | prompt 贴合度。越高越"听话"但也越容易过曝/失真 | 5-7（SDXL），1.5-3（Flux） |
| **sampler_name** | 采样器，不同的"计算方法" | euler_ancestral（SDXL）/ Euler（Flux） |
| **scheduler** | 调度器，控制每一步的噪声水平下降速度 | normal / karras |
| **denoise** | 去噪强度。1.0=从头生成，<1.0=在现有潜空间基础上改 | 1.0（txt2img） |

**几个关键点直接说结论**：

- **seed 设为 0 = 随机**。你不需要理解什么是"种子"，理解"固定它就能复现同一张图"就够了。设为 `fixed`，种子锁死；设为 `randomize`，每次随机。——这是我的常用配置：control_after_generate 设为 `randomize`，这样每次生成是随机的，但万一出了好图我可以记住 seed 回去复现。

- **steps 别盲目拉高。** SDXL 的话 20-30 步就够了，40 步跟 20 步肉眼几乎看不出区别。Turbo 模型（像 Z-Image-Turbo）4-8 步就够。很多人的误区是"步数越高画质越好"——过了临界点之后是纯浪费算力。

- **CFG 是真正的调参重点。** CFG 太低画面偏"自由发挥"（跟你的 prompt 可能差很远），太高画面开始"结晶体化"（过曝、塑料感、生硬）。SDXL 我一般定在 5.5 到 7 之间，Flux 在 1.5 到 3 之间。具体值没有"对"的答案，自己试一组 4、5、6、7、8 五张，看哪张最顺眼——这个实验 5 分钟做完，下次就知道你自己的偏好了。

- **采样器和调度器组合**。新手建议：SDXL 用 `euler_ancestral` + `normal`，Flux 用 `Euler` + `simple`。这两个组合问题最少。等熟练了再试 `dpmpp_2m` + `karras` 之类的进阶方案。

---

## 第五步：解码 —— VAE Decode

**操作**：双击空白 → 搜 `VAE Decode` → 回车。

**连线**：

```
KSampler → LATENT 输出口 → VAE Decode 的 samples 输入口（紫色线）
Load Checkpoint → VAE 输出口 → VAE Decode 的 vae 输入口（橙色线）
```

KSampler 算出来的结果是"潜空间"数据，你看不到它长什么样，它只是一堆数字。VAE Decode 把这堆数字翻译成你能看到的 RGB 像素图。

**这里有个常见的坑**：VAE Decode 的 `samples` 输入的必须是 KSampler 的 LATENT 输出，而不是别的类型的输出。如果你拿错了（比如条件数据），会报一个"type mismatch"的错误。ComfyUI 在类型检查上很严格——这其实是好事，帮你拦住低级错误。

**颜色规则再一次帮到你**：紫色连紫色、橙色连橙色。类型不对，线连不起来。

---

## 第六步：保存图片 —— Save Image

**操作**：双击空白 → 搜 `Save Image` → 回车。

**连线**：

```
VAE Decode → IMAGE 输出口 → Save Image 的 images 输入口（灰色线）
```

`Save Image` 节点几乎不需要改参数。生成结束后，图片默认保存到 `ComfyUI/output/` 目录，同时在节点下方有预览。

`filename_prefix` 可以改前缀，比如改成 `test_run`，文件名就是 `test_run_00001.png`。按项目、按测试批次改前缀很实用。

## 全部连完长这样

```
[Load Checkpoint]───MODEL──────────────────────────────┐
     │                                                  │
     ├─CLIP────[CLIP Text Encode (+)]──CONDITIONING(+)──┤
     │                                                  │
     └─CLIP────[CLIP Text Encode (-)]──CONDITIONING(-)──┤
                                                        ├──[KSampler]──LATENT──[VAE Decode]──IMAGE──[Save Image]
     [Empty Latent Image]────────LATENT─────────────────┘        │
                                                                 │
                               [Load Checkpoint]──VAE─────────────┘
```

六个节点、五根数据线。这就是一个完整、可以投入使用的文生图工作流。

## 跑一次：见证完整的生成过程

点 `Ctrl+Enter`，看右侧队列面板。正常情况下你会看到缓存命中（cache hit）信息——那些没变的节点（比如 Load Checkpoint）会跳过执行。

第一次跑全流程，每个节点都执行。第二次只改 prompt 再跑，你会发现 Load Checkpoint 直接缓存命中了，不会重新加载模型。**这个缓存机制在大型工作流里极其重要**——比如你加了 LoRA、Upscale 节点之后，只改 prompt 不用重新加载整个模型，节省的时间非常可观。

---

## 调参体验：改一个参数，看效果怎么变

搭完工作流之后，最有价值的事情不是"生成一张图"，是**生成一组对比图。**

**实验一：种子对结果的影响**

把 seed 固定为 42（或者任何你喜欢的数字），跑一张。记住结果。然后把 seed 改成 12345，再跑一张。两张 prompt 一模一样、参数一模一样——但出图完全不同。

理解这个之后，你的调试方式就变了：不是"反复改 prompt 试运气"，而是**固定 prompt & 参数 → 换几个 seed → 从中挑最接近目标的 → 再微调 prompt 逼近。**

**实验二：CFG 对画面风格的影响**

同一个 seed，CFG 分别设为 3、5、7、9，跑四张。你会发现低 CFG 的画面"软"、自然但有随机偏离；高 CFG 的画面"硬"、忠实 prompt 但开始失真、过曝。

什么叫"找到自己的偏好"？就是跑完这组对比之后你知道：我这个人更喜欢 CFG 5 还是 6。

**实验三：采样器对画面细节的影响**

euler、euler_ancestral、dpmpp_2m、dpmpp_sde——同一个 seed 同一个 prompt 同一个 CFG，换采样器跑四张。euler_ancestral 会引入随机性所以每张都不一样（即使 seed 相同），dpmpp_2m 更"确定性"。

---

## 保存工作流：这是你最重要的产出

**Ctrl+S** 保存为 JSON 文件。名字起清楚，比如 `txt2img-SDXL-base.json`。

以后你的工作流会越来越多——不同模型、不同场景、不同参数组合。现在这个基础工作流，是你以后所有复杂流程的起点：在上面加 LoRA、加 ControlNet、加 Upscale、加视频生成——都是从这个六个节点的骨架演变出去的。

另外：**你生成的每一张 PNG 图里，都内嵌了生成它的工作流。** 把一张图拖进 ComfyUI 画布，刚才的工作流会自动还原。这意味着你不需要"记住每张图怎么做的"——图本身就是文档。

---

## 写在最后

从空白画布到六节点工作流，你现在有了一个**完全属于你自己的 txt2img 底盘。**

接下来的玩法方向已经很清楚：加一个 LoRA 节点锁风格 → 加一个 Upscale 节点提高分辨率 → 加一个 ControlNet 精确控制构图 → 加一个 IPAdapter 锁角色一致性。每一步都是在今天这个骨架上加一个节点、多连一根线。

别急着一下全加上——先拿这个基础工作流跑 20 张图，感受调 CFG、换 seed、改步数对结果的影响。等你对这个"底盘"完全熟了，下一步加东西的时候你才知道"为什么加、加在哪"。
