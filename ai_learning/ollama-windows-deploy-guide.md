## 一、为什么要本地部署大模型？5 个无法拒绝的理由

### 1.1 数据隐私——你的秘密，只有你的硬盘知道

这是最重要的理由，没有之一。

云端 AI 的原理是：你的输入 → 传到别人服务器 → 模型处理 → 返回结果。整个过程中，你的数据在别人手里。

本地部署后：
- 所有数据在你自己电脑上流转，不经过任何第三方服务器
- 断网了也能用，物理隔离
- 适合处理敏感信息：商业方案、法律文书、医疗记录、个人隐私

**一句话：用别人的 AI，等于把你的秘密交给一个陌生人保管。**

### 1.2 离线可用——飞机上、地下室、台风天，AI 不下线

云端 AI 需要联网。但你有没有遇到过这些情况：
- 出差在高铁上，信号断断续续
- 公司网络限流，连 ChatGPT 都打不开
- 服务器宕机，全公司干等着

本地模型**不需要网络**。只要电脑有电，AI 就随时在线。这对经常出差、网络不稳定、或者需要在安全隔离环境中工作的人来说，是刚需。

### 1.3 零边际成本——用一万次也不多花一分钱

云端 API 是按 token 计费的。如果你每天和 AI 聊几万字、做大量代码生成、批量处理文档——月底账单可能会让你肉疼。

本地部署：
- **一次性硬件投入**（你本来就有电脑）
- **零使用成本**：爱用多少次用多少次
- **无 QPS 限制**：不会触发"请求过于频繁，请稍后再试"
- **无内容审查**：不用看"作为 AI 助手，我无法……"的脸色

### 1.4 完全可定制——你的 AI，你做主

云端 AI 是"一锅端"的通用模型，没法针对你的需求微调。

本地模型可以：
- 选择最适合你场景的模型（编程专用、写作专用、翻译专用……）
- 喂你自己的知识库做 RAG（检索增强生成）
- 调整温度、top-p 等参数，控制 AI 的"性格"
- 甚至用你的数据做微调（Fine-tuning），打造专属 AI 助手

### 1.5 学习 AI 的最好方式

想真正理解大模型怎么工作？最好的方法不是看教程，是**亲手部署一个**。

跑一次本地部署，你会直观地理解：
- 模型参数大小和显存/内存的关系
- 量化是什么，为什么 4-bit 可以让 7B 模型装进 8G 显存
- token 生成速度、上下文长度这些概念是如何受硬件制约的

**这比读 10 篇科普文章管用。**

## 二、清醒认识——本地部署也有代价

吹完优点，必须把丑话说在前头。本地部署不是万能的。

### 2.1 硬件门槛——模型越强，要求越高

| 你的配置 | 能跑什么 | 体验如何 |
|----------|---------|---------|
| 4–8 GB 内存，无独显 | 1B–3B 小模型 | CPU 推理，速度较慢，可以日用 |
| 16 GB 内存，无独显 | 1B–7B 模型 | 7B 用 CPU 跑会很慢，3B 以内还行 |
| 8 GB 显存（RTX 4060 等） | 7B–8B 量化模型 | GPU 推理，流畅，40-60 token/s |
| 16 GB 显存 | 14B 量化模型 | 接近云端中级模型体验 |
| 24 GB 显存 | 32B 量化模型 | 接近 GPT-4 级别体验 |

### 2.2 能力差距——本地模型 ≠ 云端旗舰

实话实说：你在本地跑的 1B 或 7B 模型，和 ChatGPT-4、Claude 3.5 Sonnet 这些云端旗舰比，能力上还是有差距。

- **1B 模型**：能做基本问答、翻译、摘要，但复杂推理会翻车
- **7B 量化模型**：日常对话、写作辅助、简单编程够用，复杂任务吃力
- **14B+ 模型**：大部分场景很能打，但需要更好的显卡

**但——对 80% 的日常使用场景来说，7B 模型已经足够好了。**

### 2.3 需要一点动手能力

虽然这篇教程已经尽量傻瓜化，但你还是需要：
- 会用命令行（就是那个黑窗口，别怕）
- 会下载文件
- 大概知道自己的电脑配置

如果你完全不会这些……学一下也不亏，这是 AI 时代的必备技能。

### 2.4 维护成本

模型会更新，Ollama 会升级，可能会遇到兼容性问题。但相比云端服务突然涨价或关停，这点维护成本微不足道。

## 四、第一步：在 Windows 上安装 Ollama

### 4.1 下载安装

1. 打开浏览器，访问 Ollama 官网：**https://ollama.com**
2. 点击首页大大的 **"Download for Windows"** 按钮
3. 下载完成后，双击 `OllamaSetup.exe` 安装
4. 一路点"下一步"，完成安装

安装完成后，你的任务栏右下角会出现一个小羊驼图标 🦙——说明 Ollama 已经在后台运行了。

> **验证安装**：按 `Win + R`，输入 `cmd` 回车，打开命令提示符，输入：
> ```
> ollama --version
> ```
> 如果显示版本号（如 `ollama version is 0.x.x`），说明安装成功。

### 4.2 【重要】修改模型存储路径

Ollama 默认把模型下载到 C 盘（`C:\Users\你的用户名\.ollama`）。一个 7B 模型大概 4–5 GB，多下几个 C 盘就爆了。

**建议把存储路径改到其他盘。** 方法：

1. 在任务栏右下角找到 Ollama 图标，右键 → **Quit Ollama**（退出）
2. 按 `Win + R`，输入 `sysdm.cpl` 回车 → 打开系统属性
3. 点击 **"高级"** 标签页 → **"环境变量"**
4. 在"用户变量"区域，点击 **"新建"**
5. 变量名填：`OLLAMA_MODELS`
6. 变量值填：你想存模型的路径，比如 `D:\OllamaModels`
7. 确定保存，重新启动 Ollama

> **小提示**：如果你不知道去哪找 Ollama 启动程序，直接按 Win 键搜 "Ollama" 点开就行。

### 4.3 基础命令速成

以下命令在命令提示符（cmd）或 PowerShell 中运行：

```bash
# 查看已安装的模型列表
ollama list

# 下载并运行一个模型（以 qwen2.5:1.5b 为例）
ollama run qwen2.5:1.5b

# 下载模型但不运行
ollama pull qwen2.5:7b

# 删除一个模型
ollama rm qwen2.5:1.5b

# 查看 ollama 帮助
ollama help
```

好了，基本功学会，下面进入实战。

## 六、实战二：7B 量化模型——8G 显卡性能全开

> **适用人群**：拥有 8 GB 及以上显存的 NVIDIA 显卡（RTX 2060 / 3060 / 4060 / 3070 / 2080 等）

### 6.1 什么是"4bit 量化"？

先解释一个关键概念：**量化**。

一个 7B 参数的模型，如果按原始的 FP16（16 位浮点数）存储，需要 **约 14 GB 显存**。一张 8 GB 的显卡根本装不下。

但研究发现：把模型参数从 16 位"压缩"到 4 位（精度从 65536 级降到 16 级），**输出质量损失极小，体积却能缩到原来的 1/4**。这就是 **Q4_K_M 量化**，是目前性价比最高的选择。

> **类比**：就像一张照片，PNG 原图 20 MB，转成高质量 JPEG 只要 2 MB，肉眼几乎看不出区别。量化就是大模型的"高质量 JPEG 压缩"。

Ollama 默认下载的就是 Q4_K_M 量化版本，你什么都不用操心。

### 6.2 推荐模型：Qwen2.5:7b

| 项目 | 详情 |
|------|------|
| 模型名称 | **Qwen2.5:7b**（通义千问 2.5，70 亿参数，Q4_K_M 量化） |
| 开发者 | 阿里巴巴 |
| 模型文件大小 | 约 4.4 GB |
| 运行时显存占用 | 约 5.3 GB |
| 剩余显存（8G 卡） | 约 2.7 GB，可支持 8K–16K 上下文 |
| 中文能力 | ★★★★★ 顶级开源水平 |
| 推理速度 | 40–60 token/s（RTX 4060） |
| 显卡要求 | NVIDIA 8 GB 显存及以上 |

备选升级方案（如果你有 12–16 GB 显存）：
- **Qwen3:8b**（更新更强的 8B 模型，约 4.9 GB）
- **Qwen2.5:14b**（14B 参数，能力跃升，约 8.3 GB）

### 6.3 部署步骤

同样只需一行命令：

```bash
ollama run qwen2.5:7b
```

首次下载大约需要 5–15 分钟（视网速而定）。模型约 4.4 GB，建议在 WiFi 环境下操作。

下载完成后，你会进入对话模式。先试试它的"真功夫"：

```
>>> 请你扮演一个资深产品经理，帮我分析一下：我想做一款面向小商家的进销存 SaaS 产品，国内市场还有机会吗？请给出分析框架。
```

```
>>> 用 Python 写一个函数，输入一个字符串，判断它是不是有效的 IPv4 地址。要求处理边界情况并加上注释。
```

```
>>> 把以下这段会议记录整理成结构化的会议纪要，包含：会议主题、参与人员（如果有）、讨论要点、决议事项和待办事项。
[粘贴一段模拟会议记录]
```

### 6.4 性能实测

以 RTX 4060 8GB + Qwen2.5:7b 为例：

| 测试场景 | 表现 |
|----------|------|
| 日常聊天（短问答） | 秒回，几乎无等待感 |
| 文案写作（800 字文章） | 约 15–20 秒完成 |
| Python 代码生成（50 行） | 约 10–15 秒 |

**体感总结**：日常使用完全跟手，不会让你想摔键盘。

### 6.5 它能做什么？

**✅ 做得很好的**：
- 日常对话、知识问答
- 中英文写作（文章、邮件、报告、方案）
- 文本润色、改写、翻译
- 代码生成与解释（Python、JavaScript、SQL 等常见语言）
- 头脑风暴、创意发散
- 角色扮演、模拟面试
- 长文档的理解与摘要
- 配合知识库做 RAG 问答

**⚠️ 勉强能做的**：
- 复杂的算法设计与数学证明
- 超长代码（200 行以上）一次性生成
- 多文档联合分析

**❌ 做不了的**：
- 图像识别（纯文本模型）
- 联网搜索最新信息
- GPT-4 级别的顶级推理

### 6.6 一个小技巧：如何检查是否在用 GPU

运行模型后，开一个新的命令行窗口，输入：

```bash
ollama ps
```

你会看到类似这样的输出：

```
NAME            ID              SIZE      PROCESSOR    UNTIL
qwen2.5:7b      abc123def456    5.3 GB    100% GPU     4 minutes from now
```

看到 `100% GPU`，就说明显卡正在全力工作中。如果显示 `100% CPU`，那说明模型没加载到显卡上——这种情况需要检查你的 NVIDIA 驱动和 CUDA 是否正常。

## 八、进阶玩法——这只是起点

跑通命令行对话只是第一步。Ollama 还支持更强大的玩法：

### 8.1 安装 Open WebUI——像 ChatGPT 一样用本地模型

命令行聊天太硬核了？装个 Open WebUI，几行命令就能拥有一个**长得跟 ChatGPT 几乎一模一样的本地聊天界面**。

它支持：
- 多轮对话、对话历史管理
- Markdown 渲染、代码高亮
- 多模型切换
- 上传文档做 RAG 问答

（具体教程见后续系列文章）

### 8.2 对接编程工具

如果你写代码，可以把 Ollama 接到你的 IDE 里：

- **Continue**（VS Code / JetBrains 插件）：本地代码补全 + 对话
- **Cursor**：在设置中配置 Ollama API（`http://localhost:11434`）
- **Cline**：VS Code 的 AI 编程 Agent

API 地址统一是：`http://localhost:11434/v1`

### 8.3 搭建本地知识库

用 Ollama + AnythingLLM / Dify，把你的公司文档、个人笔记喂给本地模型，打造一个**只属于你的私有知识库问答系统**。

这是本地部署最核心的落地场景之一，后续文章会详细展开。
