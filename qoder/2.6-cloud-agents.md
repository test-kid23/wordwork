# Agent 在云上跑，你在手机上摸鱼——Cloud Agents 把最后一块短板补上了

**写在前面：**

你有没有遇到过这种情况——发起一个 Agent 任务，它说"这要跑大概 30 分钟"。然后你只能对着屏幕发呆，看它一行行刷日志。想切出去干点别的，又怕任务跑完了一直停在那等着你确认。不切出去吧，风扇狂转，电脑卡得连浏览器都打不开。

Qoder 在 2026 年 5 月 28 号上线的 Cloud Agents 就是来解决这个问题的。简单说：把 Agent 任务推到阿里云上跑，**不占你电脑的一分一毫资源。**

我最初对这个功能的态度是"哦，有个云端选项"。用了一个月之后——Cloud Agents 是我认为 Qoder 产品线里最被低估的一项基础设施。它的价值不在于"不用我电脑跑"，而在于它解锁了一种完全不同的使用方式。

---

## 一、Cloud Agents 在解决什么——不仅仅是"省资源"

先说最直观的价值：

**你的电脑不再被 Agent 任务绑架。**

一个稍微复杂点的 Quest 任务——比如重构一个模块、给 20 个接口加缓存层——跑 20-40 分钟是常有的事。在这段时间里：
- CPU 和内存被 Agent 占满
- 风扇噪音大到没法开免提会议
- 你想开个浏览器查资料，标签页的加载速度都明显变慢

这只是第一层。

第二层价值更关键：**你不需要守在电脑前盯着了。**

把任务推到 Cloud Agents 之后，你可以合上电脑去开会、去吃饭、通勤回家。任务在云端自己跑，你随时可以在手机上打开 Qoder Mobile 看进度。跑完之后自动推回结果——你到家打开电脑，任务已经完成了。

这改变的不仅是"省资源"，而是**时间利用模式**。以前串行的"发起任务 → 等 → 审查"变成了并行的"发起任务 → 做别的事 → 随时查看 → 完成后审查"。中间那段等待时间被释放出来了。

---

## 二、怎么用——三步，比想象的简单

### 第一步：在 IDE 里发起任务

跟普通 Agent 任务一样发起。区别是在任务设置里打开"Cloud Run"开关。

### 第二步：任务自动上传到云端执行

任务被推送到阿里云服务器上跑。你可以合上电脑了。

**电脑断电也没关系**——任务在云端跑，不依赖你的电脑。这是跟本地 Agent 最大的区别。本地跑的话，电脑休眠任务就断了。

### 第三步：在任意设备上查看结果

任务跑完之后会在 Qoder 的界面里标志完成。你可以：
- 回到 IDE 里接受变更文件
- 在手机上用 Qoder Mobile 预览结果
- 继续在 IDE 里审查和微调

**审批模式下**，Cloud Agent 在关键操作前会暂停，要求你确认。这个确认可以在手机上完成——远程审批，不用回电脑前。

---

## 三、跟 Qoder Mobile 的三角协同——解锁移动办公

Cloud Agents + QoderVoice + Qoder Mobile 这三个东西放在一起，形成了一条完整的使用链：

**场景举例：**

1. 早上出门前，在电脑上发起一个 Cloud Agent 任务——"给支付模块做性能优化，重点解决慢查询"
2. 开车去公司的路上，打开 QoderVoice："看一下早上发的 Cloud Agent 任务跑到哪了？"——AI 语音报告进度
3. Agent 跑到一半，建议增加一个 Redis 缓存层——这个操作影响较大，需要你审批。手机上收到通知，在 Qoder Mobile 里看方案摘要，点"批准"
4. 到公司打开电脑——任务已经完成，所有变更文件在 IDE 里等着你 review

**从头到尾，你只有两个动作：发起任务 + 审查结果。中间的过程完全不用操作。**

这就是 Cloud Agents 解锁的"三个产品协同"——没有云端运行，Voice 和 Mobile 发起的任务就没法在后台跑。缺一个，另外两个的价值都大打折扣。

## 四、限制和成本——不全是免费午餐

### 限制一：Cloud Agent 消耗额外 Credits

这是最需要说清楚的。云端运行 Agent 不是免费的——你消耗的 Credits 比本地运行多。

具体多多少？根据我这几个月的使用：
- 本地跑一个中等复杂度的 Quest 任务，大概消耗 15-30 Credits
- 同样任务在云端跑，大概消耗 20-50 Credits

**多出来的部分主要来自：**
- 上传项目上下文的网络传输开销
- 云端模型调用的算力成本（自研模型免费、三方模型收费）
- OSS 临时存储费用（很小，可以忽略）

**值不值？** 如果任务只有 5-10 分钟——不值，本地跑就行。如果任务要跑 30 分钟以上——值得，多花的十几 Credits 换你半小时自由时间，太值了。

### 限制二：高峰期排队

这是阿里云资源池化带来的问题。工作日白天（10:00-17:00）Cloud Agent 的排队时间明显更长。我遇到过最长等了 15 分钟才开始执行。

**避开高峰期使用**是经验之谈。把大任务安排在早上 8 点前或晚上 8 点后发，响应快很多。Qoder 本身也支持错峰调度——你可以在白天标记"晚上 20:00 开始执行"，任务会自动排队。

### 限制三：网络波动导致的中间中断（极少见）

Cloud Agent 在极少数情况下会因为云端网络波动而中断。这种情况我遇到过 2 次（使用两个月里），每次任务中断后 Qoder 会自动保存中间状态，重新发起时可以从中断点继续——等于自动 checkpoint。

**中断不是灾难，但如果你的任务有时效性要求（比如要在下次 CI 打包前完成），建议留出余量。**

## 五、什么人最需要 Cloud Agents

### 强烈推荐：

**1. 笔记本电脑用户（非台式机）。**

笔记本散热差，Agent 本地跑起来风扇直接起飞。推给 Cloud Agents，世界安静。

**2. 碎片化工作者。**

如果你的工作方式不是连续几小时坐在电脑前，而是频繁切换场景——开会、吃饭、通勤——Cloud Agents 是你的时间倍增器。

**3. 跑 ML 相关任务的开发者。**

Qoder 能做一些轻量的模型训练数据处理。如果你的任务涉及大文件处理或数据清洗——这些在云端跑比在你的 16GB 内存笔记本上跑强太多了。

### 暂时用不上的：

**1. 只用 Editor 模式的开发者。**

如果你只用内联补全和聊天模式，不动 Quest——Cloud Agents 对你的增益几乎为零。它只在 Agent 执行复杂任务时有价值。

**2. 有高性能台式机的开发者。**

如果你的电脑是 64GB 内存 + M3 Ultra / i9 + 水冷——本地跑 Agent 不觉得卡。那 Cloud Agents 的优势只有"可以不用守着电脑"，要不要用取决于你的工作习惯。
