# 花了15分钟装好Qoder，我让它修的第一个Bug就省了我2小时

**写在前面：**

上一篇文章讲完Qoder是什么之后，有人后台留言问：说再多Agent牛逼也没用，装不装得上还不一定。

这话对。AI工具最大的坎不是"它能不能干"，是"我能不能让它跑起来"。我装Qoder的时候也踩了几个坑——不算大，但没遇到过的人确实会卡住。今天这篇就是把从零到让它干完第一个活的整个过程写下来。

网上那些官方安装教程我看了，教人"下一步→下一步→完成"——这种文章等于没写。能把人卡住的从来不是下一步，是那些官方文档没写的边角料。

---

## 一、选哪个入口？别纠结，大部分人装这一个就够了

Qoder现在四个入口：**VS Code插件、JetBrains插件、独立桌面IDE、CLI**。

先说结论——90%的人装VS Code插件就行了。别一上来四个全装，又不是搞评测的。

我用VS Code居多，偶尔用CLI跑CI任务。JetBrains插件我装过但用得少——JetBrains里Agent模式会卡（这个后面说），独立桌面IDE装了两次都卸了，原因等下聊。

**VS Code装Qoder：三条路，最快的一条**

1. 打开VS Code，左边点扩展（Ctrl+Shift+X），搜「Qoder CN」→ 安装。注意搜「Qoder CN」不是「Qoder」，不带CN那个是海外版，账号跟国内不互通。
2. 去Qoder官网（qoder.cn）点下载，会自动跳到VS Code扩展页。
3. 如果上面两条都打不开——关掉梯子。Qoder国内服务器对代理不友好，直连反而更快。我就在这卡了十分钟，一直以为是我VS Code的问题，后来把代理关了秒进。

装完之后右下角弹一个「登录」按钮，点它。用**阿里云账号**登——微信、支付宝扫码都能登，不用注册新账号。如果没有阿里云账号，扫码之后自动注册一个，不用填手机号不用验证邮箱，阿里系一贯的丝滑。

登录完右上角出现一个Qoder图标，点开，弹出一个聊天面板——恭喜，到这一步就装好了。

**JetBrains用户注意一个坑**

PyCharm/IDEA/GoLand里装Qoder流程一样，搜插件安装→登录。但它有个跟VS Code版完全不同的表现：Agent模式在JetBrains里执行任务时，偶尔会出现文件写入卡住的情况。表现在界面上就是——AI说"我已经修改了XX文件"，打开一看，文件没变。

我遇到的解决方式是：重新触发一次同一个任务——第二次它就能正常写了。这个不太优雅，但管用。如果介意这个体验，可以在JetBrains里只做代码补全，Agent任务切到VS Code做。

**独立桌面IDE：为什么我装了两次都卸了**

Qoder Desktop是一个基于VS Code fork出来的独立IDE，装完自带Qoder插件，开箱就能用。

我卸它的原因很简单——我已经有一个配好的VS Code了，装了三十多个插件、自定义了快捷键、主题也调好的。再装一个单独的IDE等于让我重新配一遍。对于手头已经有成熟开发环境的人，独立IDE的"开箱即用"优势不存在——本来就有箱。

**建议：** 如果还没装过VS Code，或者就想搞一个专门给AI写代码用的"干净"环境，那Qoder Desktop反而是最好的选择。但如果已经有VS Code了，直接装插件就行，独立IDE纯属跟自己过不去。

**CLI：不是用来手敲命令玩的**

Qoder CLI装法看官方文档就行，npm install一下的事情。

但我要说清楚CLI的定位：它不是"给喜欢命令行的开发者的另一个入口"。它是给**自动化流程**用的——写CI/CD脚本的时候，在GitHub Actions或者Jenkins里调Qoder CLI，让AI自动审查代码、自动跑测试、自动生成报告。日常开发别用CLI，纯找罪受。

如果只是为了耍酷用CLI——建议省省。老老实实装插件，IDE里看着AI干活比终端里看日志舒服一百倍。

## 二、第一个任务：让它搞清楚项目

装好之后，别急着让它修Bug。先让它认识项目。

打开一个项目文件夹——随便哪个，自己写的项目、github上clone的、甚至一个只剩readme的空文件夹都行。在Qoder聊天框里输入：

> 帮我分析一下这个项目的目录结构，告诉我每个目录是干什么的。

回车。

Qoder会开始读项目文件树，逐层分析每个目录和关键文件的用途。它会生成一个总结，说明这个项目大概是干什么的、用了什么技术栈、入口文件在哪。

这一步的意义不是"获取信息"——自己当然知道自己的项目结构。意义是**让Qoder建立对项目的初步认知**。它后面帮人修Bug、写功能、重构代码的时候，都会基于这次分析的结果。跳过这一步直接让它干活，它不是不能干，但会干得比较笨——因为每次都要重新摸一遍目录。

> **一个细节：** 如果用的是VS Code版的Qoder，右键点击项目根目录，选"Qoder → Add to Context"，能让它把整个项目结构加入对话上下文中。JetBrains版目前没有这个右键菜单。这是另一个我在日常用VS Code更频繁的原因。

它分析完之后，还能追加问题——"核心业务逻辑在哪个文件里"、"这个项目里有没有没用到的代码"、"哪个文件的耦合最严重"。这些追问比第一轮分析更有价值，相当于让一个刚入职的同事帮忙做了第一轮代码摸底。

## 三、第一个Agent任务：让它替你改一个Bug

现在来真的。

在项目里找一个确定需要的改动——最好是那种"逻辑简单但需要改好几个文件"的活儿。这种活最适合第一次试Agent模式，因为：
- 难度不高，AI不太会出错
- 跨文件手动改很烦，AI恰好擅长
- 改完之后能快速验证对不对

我的第一个Agent任务是：把项目里所有 import 路径从相对路径改成绝对路径（项目配了路径别名）。这个事情我自己改要15-20分钟——逐个文件打开、看清楚相对路径层级、算对alias、修改、保存。烦，且容易漏。

在Qoder聊天框里，先切换到Agent模式（聊天面板顶部有个下拉，选"Agent"），然后输入：

> 把src目录下所有文件的import相对路径改成@/绝对路径，项目已经在tsconfig里配置了@映射到src。改完后不要运行代码，列出你修改了哪些文件。

回车之后能看到——Agent面板里出现了一个"任务计划"。它不是直接改代码，而是先列几步：
1. 扫描src目录，找到所有使用相对路径import的文件
2. 确定每个import对应的@/路径
3. 逐个替换
4. 列出修改清单

这一步要确认——点"执行"。然后它会开始一个个文件打开、替换、保存。能在编辑器里实时看到文件在变。不是那种"AI生成了代码块复制粘贴"的感觉，是"有人在另一边键盘上帮忙改文件"的感觉。

改了大概四十多个文件，花了不到两分钟。我检查了前五个——全对。又抽查了十个——全对。全部改完之后它给我列了一个清单，文件路径 + 修改行数 + 改动内容。

**这就省了我至少20分钟的纯手工劳动。** 不是AI写得比我好，是它比我快。

这个任务为什么适合作为"第一个Agent任务"：
- 需求明确：不用AI猜目的
- 范围可控：限定目录，不会改炸其他代码
- 可验证：改完搜一下相对路径看还有没有漏的

**不建议第一次就让AI做的：** 改核心业务逻辑、重构数据库schema、跨模块改数据结构。不是说它做不了——是做完了验证起来太累，第一次体验容易变差。先用小活建立信任，熟了再交大活。

## 四、常见卡住的情况和怎么绕过去

**1. 网络"正在连接…"一直转**

前面说过：关代理试直连。如果直连也不行——检查公司/学校网络有没有网关限制阿里云的某些端口。Qoder用的是阿里云内网链路，部分企业网络环境会拦截。遇到这种情况切手机热点试一下，能排障。

**2. Agent任务执行到一半停了，提示"上下文过长"**

这是因为当前对话里塞了太多文件。Qoder一个会话的上下文是有限的——把整个项目十几个文件全扔进去，聊七八轮之后必然溢出。

解法：新开会话，只把当前任务相关的文件加进去。别一次性塞十个文件给AI，面试新人也不会一次给十个需求。

**3. 登录之后插件没反应**

VS Code里：Ctrl+Shift+P → 输入"Qoder: Sign In" → 回车，重新触发登录。

JetBrains里：File → Settings → Tools → Qoder → Sign Out → 重新登录。

**4. JetBrains里Agent改了文件但没生效**

前面说了——重试一次同样的任务。如果重试也不行，切到VS Code做Agent任务（JetBrains的代码补全不受影响）。

**5. 阿里云实名认证？**

Qoder个人版免费使用不需要实名认证。只有开Pro版或者用Ultimate档位需要开通阿里云账号的付费能力（不一定是付费，是需要有能付费的资格）。

## 五、装完第一次用，快速自查清单

- [ ] 装VS Code插件「Qoder CN」（不是Qoder）
- [ ] 登录阿里云账号（微信/支付宝扫码）
- [ ] 打开一个真实项目，让Qoder分析项目结构
- [ ] 找一个"逻辑简单但跨文件"的改动，切到Agent模式让它做
- [ ] 改完后自己验证前三个文件——别全信AI
- [ ] 记笔记：这次AI改得满意的点和不满意的点

最后一条不是凑数。AI编程工具就是个搭档，跟人一样——第一次合作得知道它哪里靠谱、哪里爱糊弄。以后就知道什么活给它、什么活自己做。

## 写在最后

装Qoder真正花的时间不到15分钟——但装完之后的第一个小时，决定了以后会不会继续用。

我的经验：第一次别拿它做太难的事，也别做太简单的事。太难了觉得它傻，太简单了觉得它没用。找一个"自己懒得做但它做得很好"的活——比如批量改import路径、比如统一变量命名、比如补一个模块的单元测试。做完了会觉得：这15分钟装得值。

下一篇聊真正让我决定日常用Qoder的原因——四个编程模式。大部分工具只给一种模式：补全。Qoder给了四种，但说实话，我大部分时候只用一个。下一篇聊聊哪个模式值得用、哪个模式是噱头。
