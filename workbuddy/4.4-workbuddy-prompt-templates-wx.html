先说清楚一件事：这些模板不是"话术"，不是靠花言巧语骗 AI 听话。

它们的作用只有一个——把你脑子里那些默认的要求，变成它能看见的要求。

你不说"给谁看"，它就只能按平均来；你不说"不许编数字"，它就真会编。

1 先记住一个通用骨架

如果这篇你只记一条，记这个：

要什么 + 给谁用 + 什么感觉

对比一下就明白了：

❌ 帮我写一篇介绍产品的文章

✅ 写一篇产品介绍，给第一次听说我们的中小企业老板看，语气实在、别用营销腔，800 字以内

区别不在礼貌，在它有没有判断标准。

这条骨架适用于 80% 的需求——写东西、做页面、出图、做方案，都能套。

2 分场景模板（照抄就行）

📌 ① 做网站

骨架：给谁看 + 放什么 + 什么感觉

"做一个落地页，给我的公众号导流；读者是 30–45 岁职场人；首屏要有：一句话介绍 + 一个二维码位置；风格干净、留白多、主色黑白灰。"

多页站再加一层页面地图：

"要做 4 个页面：首页 / 文章列表 / 文章详情 / 关于我。导航在每页顶部，点击可以互相跳转；风格要统一。"

📌 ② 出图 / 做设计

骨架：用在哪 + 画什么 + 什么感觉 + 文字放哪

"做一张公众号封面图，横版；主体是工作台场景的插画；氛围专业但不冷，主色深蓝；画面右下角留出放标题的位置，文字我自己加。"

记住一个附加要求：要放字的图，明确说"只出背景，不要生成文字"。

📌 ③ 做调研

快查骨架：对象 + 范围 + 格式 + 要求

"帮我查一下国内 AI 办公工具的市场情况；只看近一年的公开信息；输出成一页要点；每一条都标来源。"

系统调研再加三条硬要求：

"写一份决策调研报告。要求：① 先给结论，再给依据；② 所有数据必须标注来源，没有可靠来源的一律留【待核实】占位，不许自己编；③ 最后给我 3 条明确建议，别只说'视情况而定'。"

📌 ④ 写文档（周报 / 方案 / PRD）

写之前先答三个问题：给谁看 + 要达成什么 + 希望他看完做什么。

两段式（推荐）：

第一轮："我要写一份 XX 方案，先只给我大纲，每个章节配一句话说明，不要展开。"

第二轮："按这个大纲写第一章，其他章节先不动。"

去 AI 味的三个要求：

"① 不要用'随着……的发展'这类开头；② 语气像跟同事当面说；③ 所有数字如果不确定，留【待补】占位，不许编。"

📌 ⑤ 做小程序

关键前提：需求里必须明确写"微信小程序"，否则它会给你生成网页。

"帮我做一个'活动报名'微信小程序；用户是公司同事；要保存报名数据；流程是：打开 → 填表 → 提交 → 看到自己的报名结果。"

📌 ⑥ 同时开多个任务（并行）

拆任务的三条标准：能独立验收 + 输入输出不重叠 + 各有明确交付物。

每条需求后面都加一句输出目录：

"……所有文件输出到 content/ 目录。"
"……所有文件输出到 design/ 目录。"

这句话能避免一个很常见的翻车：两条线生成同名文件，后写的把先写的覆盖掉。

📌 ⑦ 造专属专家

五块内容：角色定义 + 核心能力（3–5 条）+ 工作流程 + 输出规范 + 注意事项。

其中"注意事项"最值钱，写的是禁区：

"不许编数据；不许用'赋能、抓手、闭环'这类词；不许在结尾喊口号。"

用的时候一行搞定："用写作专家，把这段润色一下。"

3 三条"保命句"，加在任何需求后面

这三句话，我建议你做成固定结尾，每次加上：

① "没有可靠来源的数据，一律留【待核实】占位，不许自己编。"
这是最重要的一句。AI 最危险的错不是答错，是答得像对的。

② "信息不够就直接问我，别自己假设。"
防止它替你脑补关键前提。

③ "所有文件输出到 xxx/ 目录。"
防止文件被覆盖，也方便你回头找。

4 一份反面清单：这些话等于没说

同样重要的，是知道什么话别讲：

❌ "帮我做个好看的"
"好看"不是标准，它只能给平均答案。

❌ "写得专业一点"
给谁看的专业？专业到什么程度？

❌ "多加点数据"
数据从哪来？没说清就等于让它编。

❌ "你自己看着办"
它不会知道你的偏好，只会给你最常见的那种。

❌ "先随便做一版，不行再改"
改一轮的成本，往往比说清楚一次高。

说白了：凡是不能用"给谁、做什么、什么样"回答的要求，都是无效要求。

写在最后

这份清单不是让你每次都抄一遍，而是当个起点。

最好的做法是：你抄一次，然后按自己的情况改一改，存到备忘录里。改过两三次，它就是你自己的模板了。

如果你连"改"都嫌麻烦，还有更省事的办法：把这五块写进一个专属专家里（我讲专属专家那篇讲过），以后一句话就够了。
