## 第19篇 · 📦 测试变量三层作用域是啥？这张图让你秒懂

家人们谁懂啊😭

我带过一个实习生
写登录测试的时候
把 token 直接写死在套件顶上
结果三个用例抢着改这个值
最后谁也不知道 token 到底是哪来的💀

那天我才意识到
变量作用域这事
不讲清楚真的会出人命（bug）

📌 今天就说三件事：
✅ 三层作用域到底是啥
✅ 谁能覆盖谁
✅ 一条业务链怎么传值

---

🧠 先记住三层

🔸 套件级
整个文件里的用例共享
比如 base_url、环境配置

🔸 用例级
单个用例自己用
比如这条用例专属的用户名

🔸 步骤级
单次请求临时用
比如刚提取出来的 token

一句话记：
范围越小
优先级越高

---

📐 覆盖规则（重点）

从高到低是这样👇

步骤提取的值
＞ 用例变量
＞ 环境变量
＞ 套件全局变量

同名的时候
小范围永远赢

我踩过的坑：
套件里定义 base_url 指向 dev
某条用例偷偷改成了 staging
我找了半小时
才发现是用例级把它盖掉了

不是 bug
是我不懂规则😤

---

🔗 一条业务链感受一下

注册 → 登录 → 查用户 → 改信息

🔸 base_url 放套件级
四个步骤都用同一个

🔸 登录拿到的 token
放步骤级提取出来
自动传给"查用户"

🔸 每条用例专属的手机号
放用例级
互不干扰

变量各就各位
整条链路才不会打架

---

🎯 一句话记住

作用域不是知识点
是你排查"谜之 bug"的地图

不想改一个值崩一片
就先把这三层刻进脑子里

💬 你有没有因为变量覆盖
排查过莫名其妙的 bug？
评论区吐槽一下～

⭐ 收藏这篇
下次写多用例的时候翻出来对照

## 第20篇 · 🧰 内置函数让测试"自己动起来"，最后一个我最常用

说个反常识的观点😏

测试数据
根本不该是你手编的

我早年写用例
用户名清一色 test001、test002
跑第二遍就唯一约束冲突
失败一片
还以为接口有 bug💢

后来学会用内置函数
数据自己生成
这烦恼直接消失

📌 今天盘几个真香的：

---

⏱️ 时间类

🔸 生成秒级时间戳
订单号、请求 ID 后缀常用

🔸 生成毫秒时间戳
要更细粒度时用

🔸 格式化当前时间
日期查询参数直接塞

好处：
每次跑都不一样
测试数据天然唯一

---

🎲 随机类

🔸 生成随机整数
不重复的 ID 就靠它

🔸 生成随机字符串
用户名、邮箱前缀

🔸 生成 uuid
全局唯一，永不撞车

我现在建用户
名字都是随机拼的
连续跑 100 遍都不冲突

---

🔐 编码 / 哈希类

🔸 md5 / sha256
接口要签名时直接算

🔸 base64 编解码
处理 token、加密串

🔸 读系统环境变量
密钥不写进文件
从环境里取

这几个
是对接有签名的接口时
救命的存在

---

⚠️ 一个不推荐的用法

别在断言里嵌一堆函数
把期望值算得七拐八绕

🔸 数据生成 → 用函数，香
🔸 断言比对 → 尽量写死期望值

不然测试挂了
你都不知道是接口错
还是你函数算错了

---

🎯 一句话记住

数据懒得编
就让函数自己动起来

你省下的不是几分钟
是"数据冲突"这类假 bug 的排查时间

💬 你最常用哪个内置函数？
uuid 党还是时间戳党？
评论区报到～

⭐ 收藏备用
下次数据冲突就想起它们

## 第21篇 · 🌐 一行命令切环境！开发/测试/生产无缝切换

周五下午的老朋友又来了😮‍💨

领导：
staging 跑一遍没问题就上线

我：改代码里的 base_url
点运行
然后连环报错👇
❌ 连接超时
❌ 404
❌ token 不对

半小时过去测试还没起跑
群里已经开始 @我了

那次之后我立了个规矩：
切环境
绝对不许改代码

📌 今天讲怎么做到：

---

🗂️ 配置和代码分开

把环境信息
全塞进一个配置里
代码里一个都不写死

🔸 dev 环境
base_url 指本地
超时给 60 秒

🔸 staging 环境
base_url 指预发
库连预发的

🔸 production 环境
base_url 指线上
超时收紧到 30 秒

测试逻辑不动
只有环境配置在变

---

⚡ 切换就一行

跑的时候带上环境名
比如指定 staging
框架自动用那套配置

再想切回 dev
把环境名一换就行

不用改代码
不用重新部署
不用担心误提交

我第一次这么切的时候
是真的爽到

---

🔐 密钥千万别裸奔

生产的数据库密码、Secret
这种东西
死都不能进配置文件

🔸 本地开发
放本地专属配置
加进 gitignore

🔸 CI 环境
用环境变量注入
统一前缀自动读

🔸 生产
走密钥管理
配置里只写引用

记住一条：
该看到的人看得到
不该看到的永远看不到

---

⚠️ 我不推荐的做法

别为了图省事
把所有环境写在同一份配置里
用注释切换

今天注释 dev
明天注释 prod
迟早有一天
你会带着 prod 配置
去 dev 跑一遍脏数据😱

---

🎯 一句话记住

配置和代码分离
不是"最佳实践"
是基操

💬 你切环境踩过最惨的坑是啥？

⭐ 学会这招
以后切环境 10 秒搞定

## 第22篇 · 🔗 用例间的数据串联术：上一步的 token 传给下一步

先问你个问题🤔

登录接口返回的 token
你是怎么给后面的请求用的？

我见过最离谱的做法：
先手动跑一次登录
把 token 复制出来
粘到后面每个用例里

token 一过期
全部重来😭

其实框架早就能自动串了

📌 今天讲清楚：

---

📤 上一步：把值提取出来

登录成功后
用 extract 把 token 挖出来

🔸 指定字段路径
比如 data 下的 token
🔸 给它起个名字
比如 token

这一步做完
token 就变成了变量
后面随便用

---

📥 下一步：直接引用

后续请求要带认证
就在请求头里引用这个变量
拼成 Bearer 加 token

框架跑到这一步
自动把真实值填进去
你一个字都不用手动复制

---

🔗 不止是 token

能传的东西多了去👇

🔸 登录 → token
🔸 下单 → 订单 ID
🔸 建用户 → user_id
🔸 开会话 → session_id

只要是上一步返回的
下一步都能接着用

---

🧩 一整条业务链

注册 → 登录 → 查用户 → 改信息 → 退出

每一步提取自己产出的值
下一步接着往下传

整条链自己就跑通了
中间不需要人工插手

我第一次把这条链跑通的时候
真的有种搭积木搭上瘾的感觉😌

---

⚠️ 一个容易踩的坑

提取的字段路径写错
下游拿到的是空值
请求带着空 token 出去
返回 401
你还以为是权限问题

排查顺序记住：
先确认上一步真的提取到了
再去查下游

---

🎯 一句话记住

好的测试链
数据自己流
你只负责设计流程

💬 你写业务链最长串过几步？
评论区比比～

## 第23篇 · 🎲 随机数据生成术：告别"test123"这种硬编码

来个灵魂拷问💢

你的测试数据
是不是还在用 test123？

我以前就是
用户名 test
密码 123456
邮箱 test@test.com

第一遍跑得好好的
第二遍
唯一约束冲突
直接挂

我盯着报错看半天
最后才反应过来
不是接口的锅
是我数据没变

📌 今天治好这个病：

---

💣 硬编码的三宗罪

🔸 罪一：重复冲突
同名用户建第二次
数据库直接拒绝

🔸 罪二：数据污染
一堆 test 开头的垃圾
留在库里没人清

🔸 罪三：假 bug
测试挂了你查半天
其实是数据撞了

---

🎰 随机生成三件套

🔸 随机整数
生成不重复的 ID
范围自己定

🔸 随机字符串
拼用户名、邮箱前缀
每次都不一样

🔸 uuid
要绝对唯一就用它
撞车概率约等于零

---

🧪 组合起来更香

想要一个唯一邮箱？
用 uuid 取前 8 位
拼上固定后缀
一个不重复的邮箱就有了

想要唯一手机号？
固定前缀
加随机数字段

数据库的唯一约束
再也拦不住你了

---

⚠️ 我不推荐的偷懒

别用当前时间当唯一值
然后又开并行跑

并行下同一毫秒
可能生成一样的值
照样冲突

要唯一
就老老实实上 uuid

---

🎯 一句话记住

测试数据不是拿来省事的
是拿来"每次都不一样"的

硬编码省的是打字时间
花的是排查假 bug 的时间
稳赔不赚

## 第24篇 · ⏱️ 时间戳、UUID、MD5——测试老手常用的几个函数

上一篇讲了随机数据😏

这篇往深了挖
讲几个测试老手
天天在用的函数

不是炫技
是真能救命的那种

📌 挨个说用途：

---

⏱️ 时间戳

🔸 秒级时间戳
最常见的用法
订单号、请求 ID 的后缀
保证每次都不撞

🔸 格式化日期
比如取到年月日
直接塞进日期查询参数
测"查今天的数据"很方便

---

🆔 UUID

🔸 全局唯一 ID
建资源时首选
要绝对不重复就用它

🔸 取前几位
不需要那么长时
截一段当短标识

我建测试数据
基本都靠它兜底

---

🔐 MD5 / 哈希

🔸 密码要哈希时
直接算出来对比
🔸 接口要签名时
按规则拼串再算

对接有签名校验的接口
没这个真寸步难行

---

📦 Base64

🔸 编码
处理需要编码的 token
🔸 解码
把返回的编码串还原

Basic 认证那类场景
经常用到

---

🗝️ 读环境变量

🔸 从系统环境读密钥
不写进任何文件
CI 里最常用

密钥这东西
写进代码就是事故
用它读才安全

---

🧩 组合技

这些函数能嵌套用👇

🔸 时间戳 + 随机数
拼一个几乎不可能撞的单号
🔸 uuid + 固定后缀
拼一个唯一邮箱

但提醒一句：
嵌套别超过两层
不然出错你都看不懂

---

🎯 一句话记住

这几个函数
不是让你显得专业
是让你少熬夜排查数据问题

## 第25篇 · 📐 变量覆盖优先级：到底谁说了算

第3章最后一篇
讲个最容易踩坑的点😤

同一个变量名
在好几个地方都定义了
最后到底用哪个？

搞不清这个
你迟早会遇到
"我明明改了怎么没生效"的灵异事件

📌 今天一次讲透：

---

🪜 优先级从低到高

记住这个顺序👇

内置函数默认值
＜ 全局配置
＜ 环境变量
＜ 套件变量
＜ 用例变量
＜ 提取出来的值

越往后
越有话语权

同名的时候
后面的盖前面的

---

🧪 实战感受一下

套件里定义：
base_url 指 dev

某条用例里改：
base_url 指 staging

这条用例跑的时候
用的是 staging
因为用例级更高

其他用例
还是老老实实用 dev

这不是 bug
这是设计

---

⚡ 一个特例要记牢

带特定前缀的环境变量
优先级往往拉到最高

CI 上想临时覆盖某个值
不用改任何文件
注入一个环境变量就行

这招在流水线里
特别好使

---

⚠️ 最坑的"谜之 bug"

我真实踩过的坑👇

全局配了一个超时时间
某条用例又配了一遍
两个值不一样

我改全局的
怎么改都不生效
折腾一下午
才发现用例级早把它盖死了

🔸 教训：
改值没生效
先看有没有更高优先级
在偷偷覆盖它

---

🎯 一句话记住

变量覆盖不是玄学
是有明确顺序的

你只要记住一句：
范围越小
优先级越高

搞懂它
"改了没生效"这种鬼故事
就再也吓不到你

💬 你被变量覆盖坑过吗？
最离谱的一次查了多久？
评论区抱团取暖～

⭐ 收藏这张优先级顺序
下次值不生效时
