先讲个丢人的事😑
有次我用同一套查询接口
拿三个 user_id 各测一遍

改 id 改到手抖

结果第二个 id 改漏了
测试全绿
其实压根没测到😭

后来才知道有 data_driven
直接打开了新世界👇


📌 它是啥

一句话解释：
一条用例模板
配一组数据列表
框架帮你渲染成 N 条

不用复制粘贴
不用手动改参数
一行配置搞定


🔹 举个例子

同一个查询接口
用不同 user_id 测三遍

❌ 以前做法：
→ 复制三个 case
→ 改三处 id
→ 加一个 id 加一个 case
→ 维护噩梦

✅ data_driven 做法：
→ 定义 parameters 列表
→ 一个模板自动渲染
→ 加 id 就加一行
→ 永远不担心改漏


🆚 差距有多大

50 个测试数据
🔸 以前：复制 50 份 case
🔸 现在：一行配置

不是省复制粘贴
是省"改漏了还不知道"的坑
那才是真翻车😮‍💨


🎯 真实能用在哪

分页参数批量测
搜索关键词轮着测
用户 ID 批量测
环境变量多值覆盖

只要"同一逻辑不同输入"
全都可以这么玩


💡 我的用法

我现在连边界值都塞进去
正常值 最大值 最小值 空值
一组 parameters 全覆盖
比手写好十个 case 踏实✅


⚠️ 注意别踩这个坑

别把 data_driven 当万能
逻辑本身不同的用例
硬塞一个模板 反而看不懂
那种就老老实实分开写


🎯 一句话记住：

复制 case 是在复制 bug
data_driven 是让一个模板替你跑
