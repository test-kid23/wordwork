01
⏱️ 响应耗时也能存成变量
📦
提取什么
每个接口调完都有响应时间（毫秒）。这个值本身就是一种变量类型，不用JSONPath，不用正则。
🔄
怎么存
框架内置的耗时字段 → 直接提出来起个名 → 扔进变量池 → 跟其他变量一样用。
提完之后干什么
断言、日志、收集报告，三种玩法
响应耗时 → 存为 {{resp_time}}
不需要额外工具、不插入代码、不打点
框架自带的响应时间就够了

02
🎯 第一招：断言慢接口
📏
数据驱动断言
Assert: resp_time < 500ms。每次回归自动拦慢接口，不用人盯着看。
🔔
分级告警
<500ms=正常 / 500-1000ms=警告 / >1000ms=报错。不同接口不同阈值，灵活配。
🟢 正常 < 500ms
🟡 偏慢 500-1000ms
🔴 超时 > 1000ms
⚠️ 不同接口阈值不能一刀切！导出报表当然比查ID慢，区分设置

03
📊 第二招：攒数据做报表
📋
每次回归录一版
跑完一轮回归 → 所有接口的耗时自动输出 → 粘进Excel → 趋势图有了
📈
横向对比
今天 vs 昨天 vs 上周 → 发现"这版本登录变慢了500ms" → 定位到新上代码
🔍
定位慢SQL
列表接口变慢 → 提耗时 → 发现从200ms涨到2s → 查库→ 少了个索引
⚠️ 网络波动一天跑下来数据会抖。取中位数看趋势，别盯一次的值
