💀 换环境 = 改代码？这是反模式
🔸 代码里写死 BASE_URL = localhost:8080
🔸 代码里写死 DB_HOST = 127.0.0.1
🔸 代码里写死 API_KEY = dev-key-123
🔸 切环境 → 改代码 → 可能误提交到 Git
🔸 别人拉下来跑不通 → 开始互相甩锅
💢 测试代码里出现环境信息
就像衣服上沾了饭粒——不专业
✅ 正确姿势：配置与代码分离
🔹 dev 环境
base_url: localhost:8080
db_host: 127.0.0.1
🔹 staging 环境
base_url: staging-api.xx.com
db_host: staging-db.internal
🔹 production 环境
base_url: api.xx.com
db_host: prod-db.internal
🌟 pytest --env=staging → 切到预发布
🌟 pytest --env=dev → 切回开发

不需要改代码 · 不需要重新部署 · 不用担心误提交

🔐 密钥和敏感信息怎么管
💻
本地开发
放到本地配置文件

（加入 .gitignore）

提交时不会被上传
🔄
CI/CD 环境
用环境变量注入

统一前缀自动读取

不硬编码任何密钥
🏭
生产环境
走密钥管理服务

配置中只引用 key

密码永不出现在代码中
🔒 记住最小的安全原则：
该看到的人能看到
不该看到的人永远看不到
