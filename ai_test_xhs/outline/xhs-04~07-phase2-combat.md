# xhs-04 · 用 AI 写接口测试，效率翻 10 倍

> 实战教程类 · 约 900 字

## 📋 直接复制区（以下内容可直接粘贴到小红书发布）

一个接口的测试用例，以前要写半个小时。现在呢？10 秒。

不是夸张，是真的。今天就手把手教你怎么用 AI 写接口测试👇

━━━━━━━━━━━━━━━━━━

📌 第一步：把接口文档准备好

不需要你手写任何东西，直接从 Swagger / YAPI / Postman 把接口定义复制下来就行。

像这样👇

"""
POST /api/user/login
Content-Type: application/json
请求体：
{
  "username": "string",
  "password": "string"
}
返回：
{
  "code": 0,
  "token": "string",
  "userId": "long"
}
"""

就这一小段，够 AI 用了👌

━━━━━━━━━━━━━━━━━━

📝 第二步：把这个 Prompt 贴给 AI

这是我打磨了半年的接口测试 Prompt👇

"""
你是一个资深后端测试工程师。

根据以下接口文档，用 Python + pytest + requests 生成完整的测试用例。

要求：
1. 每个用例一个 def test_xxx 函数
2. 覆盖正常场景、参数缺失、参数类型错误、边界值（空字符串、超长、null）
3. 每个用例用中文注释说明测试意图
4. 使用 assert 做断言
5. 封装 requests 调用，方便维护

接口文档：
[在这里贴接口文档]
"""

贴上去，回车，看 AI 表演⚡

━━━━━━━━━━━━━━━━━━

🔍 第三步：检查这 3 个地方

AI 生成的代码不能无脑跑，先看这三处：

✅ 检查 1：断言对不对
→ AI 有时搞反 expected 和 actual，每个 assert 扫一眼

✅ 检查 2：请求地址对不对
→ 基础 URL 可能拼错，统一替换成你的测试环境地址

✅ 检查 3：状态码预期对不对
→ 异常场景应该返回 400/401，别让 AI 写成了 200

三步查完一般就能跑了。微调不超过 5 分钟💪

━━━━━━━━━━━━━━━━━━

🎯 效率对比

❌ 以前：看文档 5 分钟 → 设计场景 10 分钟 → 写代码 10 分钟 → 调试 10 分钟 = 35 分钟

✅ 现在：贴文档 30 秒 → 抄 Prompt 30 秒 → AI 生成 10 秒 → 检查微调 5 分钟 = 7 分钟

35 分钟 → 7 分钟，效率翻 5 倍🔥

而且 AI 覆盖的边界场景比你手动想的还全——空值、null、超长字符串、SQL 注入字符……这些边界你手动写可能漏，AI 不会。

━━━━━━━━━━━━━━━━━━

💡 进阶玩法

接口多了以后，让 AI 帮你重构：
→ "把请求逻辑抽成 BaseAPITest 基类"
→ "加上 token 自动获取和刷新"
→ "生成一个 conftest.py"

你只管描述需求，AI 帮你搭架子🧠

# xhs-05 · UI 自动化测试：让 AI 写 Selenium / Playwright 脚本

> 实战教程类 · 约 950 字

## 📋 直接复制区（以下内容可直接粘贴到小红书发布）

"描述一下页面操作，AI 帮你生成完整脚本。"

以前觉得这句话是科幻。现在是真的😭 今天就教你怎么搞👇

━━━━━━━━━━━━━━━━━━

🤔 为什么 UI 自动化用 AI 特别爽

UI 自动化代码其实很"模板化"：找元素 → 操作 → 等结果 → 断言。

这种模式化的事情，恰恰是 AI 最擅长的。你不用记 Selenium 的 find_element 语法、不用查等待策略、不用纠结 CSS selector 怎么写——描述你要干什么，AI 写代码。

━━━━━━━━━━━━━━━━━━

📋 通用 UI 自动化 Prompt

"""
你是一个 UI 自动化测试专家。

请用 Python + Playwright 帮我生成自动化测试脚本。

页面：登录页面（https://example.com/login）
测试场景：
1. 打开登录页面，验证页面标题包含"登录"
2. 输入用户名 admin，密码 123456，点击登录按钮
3. 验证登录成功后跳转到首页，页面包含"欢迎"
4. 输入错误密码，验证提示"用户名或密码错误"

要求：
- 使用 Playwright sync API
- 每个场景写一个 def test_xxx 函数
- 添加合理的等待策略
- 使用 fixture 管理浏览器实例
"""

把这段贴给 AI，它会把页面元素定位、等待、断言——一次性全部生成出来🔥

━━━━━━━━━━━━━━━━━━

🐛 元素定位怎么办？不用手写 selector

这是新手最头疼的问题——不会写 CSS selector / XPath。

但用 AI 的时候，你根本不需要知道 selector 怎么写👇

🤖 你："页面上有个 class 叫 login-btn 的按钮"
AI：→ page.locator(".login-btn").click()

🤖 你："用户名输入框，placeholder 是'请输入用户名'"
AI：→ page.get_by_placeholder("请输入用户名").fill("admin")

🤖 你："第三个表格里，第 5 行的删除按钮"
AI：→ page.locator("table tr").nth(4).locator(".delete-btn").click()

你用人话描述，AI 翻译成 selector。这才是 AI 的正确用法👌

━━━━━━━━━━━━━━━━━━

⏱ 等待策略不用操心

手写 UI 自动化最烦的就是等元素出现、等页面加载。

用 AI 的时候直接说：

"添加智能等待，不要写死 sleep" → AI 自动用 wait_for_selector / expect().to_be_visible()

"网络慢的话等久一点，超时 30 秒" → AI 自动设 timeout

━━━━━━━━━━━━━━━━━━

⚖️ AI 生成 vs 手写，质量对比

我拿同一个登录场景测了一下——

🔹 手写（我自己的水平）
→ 15 分钟写了 3 个用例，30 行代码
→ 只覆盖了正常登录和错误密码

🔹 AI 生成
→ 10 秒生成 8 个用例，60 行代码
→ 覆盖了正常/错误密码/空输入/超长密码/多次失败锁定的场景

不是说 AI 比人聪明，是它没有"偷懒"的概念——你让它全覆盖，它就老老实实全写出来。

你负责想"测什么"，AI 负责"怎么测"。分工明确💪

━━━━━━━━━━━━━━━━━━

⚠️ 一个忠告

UI 自动化最值钱的不是代码，是"稳定性"。

AI 生成的脚本第一版肯定能跑，但跑 10 次可能挂 3 次。你需要加的是：
→ 弹窗处理
→ 网络重试
→ 数据清理（teardown）

这些让 AI 加就行："帮我在每个用例末尾加上数据清理逻辑"

# xhs-06 · 10 秒生成压测脚本，性能测试不再痛苦

> 实战教程类 · 约 850 字

## 📋 直接复制区（以下内容可直接粘贴到小红书发布）

JMeter 脚本写了一下午，跑起来还各种报错……

现在用 AI，10 秒出脚本。不开玩笑👇

━━━━━━━━━━━━━━━━━━

😤 压测最痛苦的不是跑，是写脚本

做过性能测试的都懂：
→ JMeter 的 GUI 界面点来点去，手酸
→ 参数化 CSV 要手动配，烦
→ 断言要一个个加，漏了就是白压

这些脏活，全部交给 AI 干。

━━━━━━━━━━━━━━━━━━

📋 JMeter 脚本生成 Prompt

"""
你是一个性能测试专家。

请帮我生成一个 JMeter 5.x 测试计划的完整配置，压测以下接口：

接口：POST /api/order/create
请求体：
{
  "userId": "${userId}",
  "productId": "${productId}",
  "quantity": ${quantity}
}

压测要求：
- 并发用户数：从 50 递增到 200，每 30 秒加 50
- 持续时间：10 分钟
- 需要参数化：userId、productId 从 CSV 读取
- 添加响应断言：code=0 才算通过
- 添加 Duration Assertion：响应时间 > 2000ms 标记失败
- 输出监听器：聚合报告 + 查看结果树

请给出 JMeter 的 jmx 配置说明和推荐执行命令。
"""

把这个贴给 AI，它会告诉你每个组件怎么配、线程组参数怎么设、CSV 怎么关联——比你自己在 JMeter 里点半天快太多了⚡

━━━━━━━━━━━━━━━━━━

🐍 更好用的方案：让 AI 写 Locust 脚本

说实话，JMeter 学习成本不低。我现在的组合是——

AI 写 Python 压测脚本 + Locust 跑。

Prompt 超简单👇

"""
用 Python + Locust 写一个压测脚本。

测试接口：POST /api/order/create
请求体包含 userId、productId、quantity 三个字段
userId 从预定义的 1000 个用户列表中随机取
并发 100 用户，每秒孵化 10 个
压测 5 分钟

请生成完整可运行的 locustfile.py
"""

10 秒出代码，改一下接口地址就能跑🔥

━━━━━━━━━━━━━━━━━━

📊 别忘了让 AI 帮你分析报告

压测跑完了，一堆数据看不懂？继续问 AI：

"""
以下是我的压测聚合报告，帮我分析：

[粘贴 JMeter 聚合报告 / Locust 输出]

请分析：
1. 吞吐量在哪个并发数达到瓶颈
2. 哪些接口响应时间最长
3. 有没有异常率飙升的点
4. 给出 3 条优化建议
"""

AI 帮你读报告、找瓶颈、给建议。一条龙服务👌

━━━━━━━━━━━━━━━━━━

🧪 压测数据生成：一句话的事

压测需要 1000 个不同的 user，以前要写脚本生成，现在：

"生成 1000 条测试用户数据，JSON 格式，包含 userId（6 位数字）、name（中文名）、phone（11 位手机号）"

AI 秒出 1000 条，直接喂给压测脚本。

━━━━━━━━━━━━━━━━━━

🎯 一句话记住：

压测的核心是"设计场景"，不是"写脚本"。

场景设计交给你，脚本交给 AI。

# xhs-07 · AI 生成测试数据，比手造快 100 倍

> 实战教程类 · 约 880 字

## 📋 直接复制区（以下内容可直接粘贴到小红书发布）

你还在一条条造测试数据吗？

手机号要编、身份证要编、地址要编……一个下午就没了😤

用 AI，一句话解决👇

━━━━━━━━━━━━━━━━━━

📊 基础数据：一句话生成 1000 条

随便举几个例子——

🤖 "生成 50 条用户注册数据，JSON 数组"
→ 秒出，每一条包含姓名、手机号、邮箱、年龄、地址

🤖 "生成 100 条订单数据，包含订单号、商品名、价格、数量"
→ 价格合理、商品名真实、订单号不重复

🤖 "生成 20 个真实格式的身份证号，18 位"
→ 全部符合校验规则，拿来就能做身份证校验测试

你描述格式，AI 填充内容。一条变一千条，秒级。

━━━━━━━━━━━━━━━━━━

📦 多格式输出，随便挑

同一个 Prompt，换个结尾就行👇

→ "输出为 SQL INSERT 语句" → 直接刷数据库
→ "输出为 JSON 数组" → 喂给接口测试
→ "输出为 CSV" → 导进 JMeter 做参数化
→ "输出为 Python list[dict]" → 粘到代码里

格式在你这，体力活在 AI 那👌

━━━━━━━━━━━━━━━━━━

🧪 边界数据：专测"不正常输入"

正常数据谁都会造，边界数据才是测试工程师的核心竞争力。

但手写超长字符串、null 值、emoji 很烦。AI 不会烦👇

🔹 "生成测试用户名的边界值集合：空字符串、1 字符、255 字符、含 SQL 注入字符、含 emoji、含 HTML 标签"

🔹 "生成手机号的异常格式：少一位、多一位、含字母、含中文、含特殊符号"

🔹 "生成金额字段的边界值：0、0.01、99999999.99、负数、非数字字符串"

一次性生成，保存下来，以后每个接口都能复用💪

━━━━━━━━━━━━━━━━━━

🔒 进阶：AI 做数据脱敏

生产环境导数据做测试是刚需，但直接把真实用户数据拿来用，合规风险巨大。

把敏感字段丢给 AI：

"""
帮我把以下用户数据脱敏，规则：
- 姓名：保留姓，名用 * 替代
- 手机号：保留前 3 后 4，中间用 **** 替代
- 身份证：保留前 6 后 4，中间用 ******** 替代
- 邮箱：@ 前只保留首字母，其余用 *** 替代

[粘贴需要脱敏的数据]
"""

AI 一条条帮你处理，比写正则快多了🔐

━━━━━━━━━━━━━━━━━━

🎯 三个保姆级 Prompt 总结

收藏这三个就够了👇

📋 Prompt 1（基础数据）：
"生成 N 条 [数据描述] 的测试数据，[格式]"

📋 Prompt 2（边界数据）：
"为 [字段名] 生成边界值测试集，包括空值、超长、特殊字符、null"

📋 Prompt 3（脱敏）：
"将以下数据的 [字段名] 脱敏，保留 [前X后Y]，其余用 [符号] 替代"

━━━━━━━━━━━━━━━━━━

从"造数据造一下午"到"一句话搞定"，差距就是这三个 Prompt。
