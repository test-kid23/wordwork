## 第50篇 · 🔌 WebSocket接口怎么测？一个YAML搞定发消息+收验证

先问个扎心的🤔

你们测 WebSocket

开着两个终端
一个发

测完一脸懵
到底对没对

其实 WS 也能
用一个 YAML 编排
发 + 收 + 验

📌 今天讲基本流程：

---

🔧 先配连接

WS 的配置
指定地址
带上必要的头
比如认证信息

和 HTTP 配置
长得差不多

---

📤 发消息

编排里写
要发的消息内容

比如发个聊天文本
或者订阅指令

框架自动发过去

---

📥 收消息 + 验

发完
框架等返回
把收到的消息
做 JSON 断言

内容对不对
字段齐不齐
一把验

---

⏱️ 超时别忘设

连接超时
关闭超时
都得配

不然卡住了
一直等

我第一次没设
用例挂了三分钟

## 第51篇 · 📡 先HTTP登录拿Token，再用WS发消息：混合协议实战

真实场景来了😎

很多系统
登录是 HTTP
收发消息是 WS

两件套
少一个都不行

我做过一个在线客服
就是这么测的

📌 今天讲混合编排：

---

🔑 前半段 HTTP

先发登录请求
拿到 token

用之前讲的提取
把 token 存成变量

这一步
和测普通接口一样

---

🔌 后半段 WS

WS 连接配置里
引用刚才的 token

带认证连上去
才发得了消息

变量在两种协议间
无缝传递

---

🧩 一个 YAML 搞定

前半 HTTP
后半 WS
写在同一份编排里

框架自动识别
该用哪种协议
路由到对应执行器

你不用切工具

---

💬 实战例子

在线客服系统：
HTTP 登录拿身份
WS 发一条咨询
收一条自动回复
断言回复内容对

端到端
一把跑通

---

⚠️ 一个提醒

WS 测试
通常要额外装依赖

别跑了报错
才发现没装
那个库

装好再跑
省得白折腾

---

🎯 一句话记住

HTTP 拿身份
WS 干实事
变量串起来
一套写完

## 第52篇 · ⚠️ WebSocket测试的3个隐藏坑，踩过2个算你厉害

上篇留的坑😤
这篇一次讲完

WS 测试
比 HTTP 娇气
坑也更隐蔽

三个坑
我全踩过
含泪总结

📌 今天排雷：

---

🕳️ 坑一：连接不关

忘了设关闭超时
连接一直不释放

跑多了
端口被耗尽
后续全连不上

🔸 必设 close_timeout

---

🕳️ 坑二：收消息超时

异步消息
来得晚一点

你超时设太短
没收到的瞬间
就判失败了

其实消息随后就到

🔸 超时给足余量

---

🕳️ 坑三：握手失败

WS 握手失败
但 HTTP 返回 200

你以为是通的
其实升级头没对

🔸 看升级头
🔸 别被 200 骗了

---

✅ 检查清单

测 WS 前
确认这三样：

🔸 关闭超时设了没
🔸 接收超时够不够
🔸 握手头对不对

三样齐
才开跑

---

🎯 一句话记住

WS 比 HTTP 娇气
三个坑排完
才测得稳

💬 三个坑你踩过几个？
评论区报数～

⭐ 收藏这份清单
测 WS 前照着查

## 第53篇 · 🆚 HTTP vs WebSocket：同一框架，两套协议，一套写法

第8章压轴😏
讲个让我得意的设计

以前测 WS
得换工具
写法全变
人都要学两遍

现在
同一套框架
HTTP 和 WS
写法一模一样

📌 今天讲价值：

---

🧩 同一套断言

WS 返回的消息
用的还是那套断言语法

JSONPath 也好
操作符也好
和 HTTP 没区别

你不用重学

---

🔗 同一套变量

WS 提取的值
和 HTTP 提取的
进同一个变量池

混合场景
天然打通

---

📊 同一套报告

WS 用例
和 HTTP 用例
出同一份报告

趋势、通过率
一起看

不用两边对账

---

🏗️ 架构理念

框架自动识别协议
路由到对应执行器

写法不变
协议可扩展

今天加 WS
明天加 gRPC
你都不用学新写法

---

⚠️ 我不推荐

别为 WS 单独
搞一套测试工具

两套系统
两套维护
迟早崩一个

🔸 统一框架
🔸 一套写法管全部

---

🎯 一句话记住

会写 YAML
就会测 WS
协议变了
写法不变

💬 大家测 WS 用啥工具？
还是手动硬刚？
评论区见～

⭐ 收藏

一套写法就够了
