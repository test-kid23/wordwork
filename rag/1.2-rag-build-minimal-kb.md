## 开篇：30 分钟，从零到跑通

上一篇文章我们讲清楚了 RAG 是什么。但"知道"和"做到"之间，隔着一整条鸿沟。

这篇文章就是填平鸿沟的——**你不需要 GPU，不需要付费 API，不需要折腾 Docker**。一台普通的 Windows 或 Mac 电脑，30 分钟，就能跑通一个完全可用的 RAG 问答系统。

我们会用到的技术栈（全部免费、全部本地）：

| 组件 | 选型 | 为什么 |
|------|------|--------|
| **大模型** | Ollama + Qwen2.5:7B / DeepSeek-R1 | 免费、本地运行、中文能力强 |
| **嵌入模型** | nomic-embed-text / BGE | 轻量、免费、效果够用 |
| **向量数据库** | ChromaDB | 零配置、Python 原生、持久化简单 |
| **应用框架** | LangChain | 把以上组件串起来，代码量最小 |

> **2026 年 6 月语境**：这套本地全链路方案（Ollama + ChromaDB + LangChain）已成为入门 RAG 的事实标准。过去跑 RAG 要搞定 Docker、Kubernetes、云向量库、付费 API，现在一台笔记本全搞定。

## 一、准备工作：你需要什么

### 硬件要求

| 配置项 | 最低要求 | 推荐配置 |
|--------|----------|----------|
| 内存 | 8GB | 16GB+ |
| 硬盘 | 10GB 空闲 | 20GB+（多存几个模型） |
| 显卡 | 不需要 | 有 NVIDIA 更流畅 |
| 系统 | Windows 10/11 / macOS / Ubuntu | 任意 |

如果内存只有 8GB，选 1.5B 参数的模型（如 `deepseek-r1:1.5b`），照样能跑。

### 你需要有的前置知识

- 能在终端/CMD 里敲命令
- 电脑上装了 Python（建议 3.10 或 3.11）
- 会用 pip 装包

**不会 Python 编程？没关系。** 本文所有代码都是完整可运行的，你只需要复制粘贴，改一两处配置就行。

## 二、环境搭建：三步就绪

### 第一步：安装 Ollama

> Ollama 是一个本地大模型运行工具，相当于"你电脑上的大模型服务器"。

去 [ollama.com](https://ollama.com) 下载安装包，双击安装。安装完成后，打开终端（CMD / PowerShell / Terminal），拉取两个模型：

```bash
# 对话模型（回答问题用）
ollama pull qwen2.5:7b

# 嵌入模型（把文字转成向量用）
ollama pull nomic-embed-text
```

> 两个模型大约 5GB，首次下载需要几分钟。之后全离线运行，不花一分钱。

验证安装：

```bash
ollama list
# 应该看到 qwen2.5:7b 和 nomic-embed-text

ollama run qwen2.5:7b "你好"
# 能正常回复就说明 OK
```

### 第二步：安装 Python 依赖包

打开终端，执行：

```bash
pip install langchain langchain-community langchain-ollama \
            chromadb langchain-chroma pypdf python-docx \
            unstructured
```

> **Windows 用户注意**：安装 `chromadb` 如果报错缺少 C++ 编译工具，可以改用 `pip install chromadb --only-binary=:all:` 安装预编译版。如果仍有问题，安装 [Microsoft C++ Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)。

> 国内用户如果下载慢，加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` 换清华镜像。

### 第三步：创建项目目录

```bash
mkdir my-rag
cd my-rag
mkdir docs        # 用来放你的文档
```

把你要检索的文档（PDF、Word、TXT）放到 `docs` 文件夹里。比如放几篇公司制度、技术文档、或者你收藏的文章。

## 三、准备文档：你的知识原料

RAG 的效果取决于你喂给它什么。几条建议：

**格式支持：**
- `.txt` — 最可靠，推荐优先用
- `.pdf` — 支持，但复杂排版（双栏、表格）可能解析不好
- `.docx` — 支持
- `.md` — 重命名为 `.txt` 使用

**文档质量建议：**
- 每篇文档聚焦一个主题，不要把所有内容塞进一个大文件
- 确保文档是 UTF-8 编码（特别是中文 TXT）
- 图文混排的 PDF 建议先提取纯文本再放入

**快速测试用：** 创建一个 `docs/公司制度.txt`，随便粘贴几段规则、流程文档。或者就用本文附带的示例内容。

## 四、核心代码：五步搭建 RAG

现在开始写代码。创建一个 `rag.py` 文件，逐步往里加。

### 步骤 1：加载文档

```python
from langchain_community.document_loaders import DirectoryLoader, TextLoader

# 自动加载 docs 目录下所有 .txt 文件
loader = DirectoryLoader(
    "./docs",
    glob="**/*.txt",
    loader_cls=TextLoader
)
documents = loader.load()

print(f"✅ 加载了 {len(documents)} 个文档")
for doc in documents:
    print(f"   📄 {doc.metadata['source']} — {len(doc.page_content)} 字符")
```

### 步骤 2：文本分块（Chunking）

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,      # 每个块 500 字符
    chunk_overlap=50,    # 块与块之间重叠 50 字符，避免信息割裂
    separators=["\n\n", "\n", "。", "！", "？", "，", " ", ""]
    # 优先按段落切，再按句子，再按逗号——中文友好
)

chunks = text_splitter.split_documents(documents)
print(f"✅ 切成了 {len(chunks)} 个文本块")
```

> **为什么要分块？** 大模型一次能处理的文字有限（上下文窗口），而且检索时太长的块会掺杂无关信息。500 字符是一个经验值，大约一个中等段落。

### 步骤 3：向量化并存入 ChromaDB

```python
from langchain_ollama import OllamaEmbeddings
from langchain_chroma import Chroma

# 用 Ollama 的嵌入模型把文字变成向量
embeddings = OllamaEmbeddings(
    model="nomic-embed-text",
    # 显式指定 Ollama 地址（默认就是 localhost:11434，写出来更清晰）
    base_url="http://localhost:11434"
)

# 创建向量数据库并持久化到磁盘
vector_store = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db"  # 数据存在这里
)

print(f"✅ 向量数据库已创建，共 {vector_store._collection.count()} 条记录")
```

> **首次运行会慢一些**，因为每条文本都要通过嵌入模型转成向量。下次运行时会直接加载 `chroma_db` 目录里的数据，不再重复计算。

### 步骤 4：构建检索器

```python
retriever = vector_store.as_retriever(
    search_type="similarity",   # 语义相似度搜索
    search_kwargs={"k": 4}      # 每次返回最相关的 4 个文本块
)
```

`k=4` 意味着每次检索返回 4 个最相关的文档片段。太少可能漏掉关键信息，太多会塞入噪声。

### 步骤 5：接入 LLM 完成问答

```python
from langchain_ollama import ChatOllama
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

# 初始化对话模型
llm = ChatOllama(
    model="qwen2.5:7b",
    temperature=0.3,  # 低温度 = 更严谨，少创造性发挥
    base_url="http://localhost:11434"
)

# RAG 专用 Prompt 模板
prompt = ChatPromptTemplate.from_messages([
    ("system", """你是一个专业的知识库助手。请严格根据以下参考资料回答问题。

规则：
1. 如果参考资料中有答案，请直接引用并注明来源
2. 如果参考资料中没有答案，请明确说"知识库中未找到相关信息"，不要编造
3. 回答要简洁、准确、有条理

参考资料：
{context}"""),
    ("human", "{question}")
])

# 格式化检索结果的辅助函数
def format_docs(docs):
    return "\n\n---\n\n".join(
        f"[来源：{d.metadata.get('source', '未知')}]\n{d.page_content}"
        for d in docs
    )

# 组装 RAG 链
rag_chain = (
    {
        "context": retriever | format_docs,
        "question": RunnablePassthrough()
    }
    | prompt
    | llm
    | StrOutputParser()
)

print("✅ RAG 链构建完成！开始问答（输入 quit 退出）\n")
```

### 运行问答循环

```python
while True:
    question = input("🙋 你的问题：").strip()
    if question.lower() == "quit":
        print("👋 再见！")
        break
    if not question:
        continue

    print("🤖 正在检索...")
    answer = rag_chain.invoke(question)
    print(f"\n📝 回答：\n{answer}\n")
    print("-" * 50)
```

## 五、完整代码：复制即用

把以上所有代码合并成一个 `rag.py` 文件：

```python
"""
最小可用 RAG 知识库
Ollama + ChromaDB + LangChain
保存为 rag.py，放在 my-rag/ 目录下运行
"""

from langchain_community.document_loaders import DirectoryLoader, TextLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from langchain_ollama import OllamaEmbeddings, ChatOllama
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough
import os

# ========== 配置区 ==========
DOCS_DIR = "./docs"              # 文档目录
CHROMA_DIR = "./chroma_db"       # 向量库持久化目录
CHUNK_SIZE = 500                 # 分块大小
CHUNK_OVERLAP = 50               # 分块重叠
TOP_K = 4                        # 检索数量
EMBED_MODEL = "nomic-embed-text" # 嵌入模型
CHAT_MODEL = "qwen2.5:7b"        # 对话模型
OLLAMA_URL = "http://localhost:11434"
# =============================

def load_documents(docs_dir):
    """加载文档目录"""
    if not os.path.exists(docs_dir):
        os.makedirs(docs_dir)
        print(f"⚠️ 已创建 {docs_dir} 目录，请放入文档后重新运行")
        return []

    loader = DirectoryLoader(docs_dir, glob="**/*.txt", loader_cls=TextLoader)
    docs = loader.load()
    print(f"✅ 加载了 {len(docs)} 个文档")
    return docs

def split_documents(docs):
    """文本分块"""
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=CHUNK_SIZE,
        chunk_overlap=CHUNK_OVERLAP,
        separators=["\n\n", "\n", "。", "！", "？", "，", " ", ""]
    )
    chunks = splitter.split_documents(docs)
    print(f"✅ 切成了 {len(chunks)} 个文本块")
    return chunks

def build_or_load_vectorstore(chunks):
    """构建或加载向量数据库"""
    embeddings = OllamaEmbeddings(model=EMBED_MODEL, base_url=OLLAMA_URL)

    if os.path.exists(CHROMA_DIR) and os.listdir(CHROMA_DIR):
        print("📂 检测到已有向量库，直接加载...")
        vector_store = Chroma(
            persist_directory=CHROMA_DIR,
            embedding_function=embeddings
        )
    else:
        print("🔨 首次运行，正在构建向量库（可能需要几分钟）...")
        vector_store = Chroma.from_documents(
            documents=chunks,
            embedding=embeddings,
            persist_directory=CHROMA_DIR
        )
    print(f"✅ 向量库就绪，共 {vector_store._collection.count()} 条记录")
    return vector_store

def create_rag_chain(vector_store):
    """创建 RAG 问答链"""
    retriever = vector_store.as_retriever(
        search_type="similarity",
        search_kwargs={"k": TOP_K}
    )

    llm = ChatOllama(model=CHAT_MODEL, temperature=0.3, base_url=OLLAMA_URL)

    prompt = ChatPromptTemplate.from_messages([
        ("system", """你是一个专业的知识库助手。请严格根据以下参考资料回答问题。

规则：
1. 如果参考资料中有答案，请直接引用并注明来源
2. 如果参考资料中没有答案，请明确说"知识库中未找到相关信息"，不要编造
3. 回答要简洁、准确、有条理

参考资料：
{context}"""),
        ("human", "{question}")
    ])

    def format_docs(docs):
        return "\n\n---\n\n".join(
            f"[来源：{d.metadata.get('source', '未知')}]\n{d.page_content}"
            for d in docs
        )

    chain = (
        {"context": retriever | format_docs, "question": RunnablePassthrough()}
        | prompt | llm | StrOutputParser()
    )
    return chain

def main():
    print("=" * 50)
    print("  🧠 本地 RAG 知识库")
    print("=" * 50)

    docs = load_documents(DOCS_DIR)
    if not docs:
        return

    chunks = split_documents(docs)
    vector_store = build_or_load_vectorstore(chunks)
    chain = create_rag_chain(vector_store)

    print("\n" + "=" * 50)
    print("  🎉 问答就绪！输入 quit 退出")
    print("=" * 50 + "\n")

    while True:
        question = input("🙋 你的问题：").strip()
        if question.lower() == "quit":
            print("👋 再见！")
            break
        if not question:
            continue

        answer = chain.invoke(question)
        print(f"\n📝 {answer}\n")
        print("-" * 50)

if __name__ == "__main__":
    main()
```

### 运行方式

```bash
cd my-rag
python rag.py
```

**首次运行**会自动：加载文档 → 切块 → 向量化 → 存入 ChromaDB。
**第二次及之后**运行会直接加载已有向量库，秒级启动。

## 七、调优方向

跑通只是第一步。根据实际效果，你可以在几个方向调整：

### 7.1 分块策略

| 场景 | chunk_size 建议 | 说明 |
|------|-----------------|------|
| FAQ / 规章制度 | 300-500 | 短文本，精确匹配 |
| 技术文档 / 长文 | 500-800 | 保留更多上下文 |
| 法律合同 / 学术论文 | 800-1200 | 需要完整逻辑链 |

> `chunk_overlap` 一般设为 `chunk_size` 的 10%，保证跨块信息不丢失。

### 7.2 检索数量

- `k=3`：适合简单事实问答
- `k=4-6`：适合一般场景（推荐）
- `k=8+`：适合复杂推理，但会增加噪声

### 7.3 模型选择

```bash
# 轻量级（8GB 内存）
ollama pull qwen2.5:1.5b        # 对话模型
ollama pull nomic-embed-text     # 嵌入模型（269MB，始终推荐）

# 标准级（16GB 内存）
ollama pull qwen2.5:7b          # 对话模型
ollama pull deepseek-r1:7b      # 推理能力强，适合复杂分析

# 重量级（32GB+ 内存）
ollama pull qwen2.5:14b         # 效果更好
ollama pull bge-m3              # 更强的嵌入模型，支持多语言
```

### 7.4 支持更多文档格式

```python
from langchain_community.document_loaders import PyPDFLoader, Docx2txtLoader

# 加载 PDF
pdf_docs = PyPDFLoader("report.pdf").load()

# 加载 Word
docx_docs = Docx2txtLoader("memo.docx").load()
```

> **提示**：PDF 解析可能依赖 `unstructured` 库，安装命令 `pip install unstructured pdf2image`。

### 7.5 从纯向量检索走向混合检索

当你的知识库超过 100 篇文档后，纯向量检索可能不够精准。这时可以加入 BM25 关键词匹配 + RRF 融合，让召回的精确率和召回率同时提升。这个我们在后续文章里展开。
