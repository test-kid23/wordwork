2 准备工作：你需要什么

📌 硬件要求

内存：最低 8GB，推荐 16GB+

硬盘：10GB 空闲（存模型），推荐 20GB+

显卡：不需要！有 NVIDIA 更流畅，没有也能跑

系统：Windows 10/11 / macOS / Ubuntu 都可以

小提示：如果内存只有 8GB，选 1.5B 参数的轻量模型（如 deepseek-r1:1.5b），照样能跑。

📌 你需要有的前置知识

✅ 能在终端 / CMD 里敲命令

✅ 电脑上装了 Python（建议 3.10 或 3.11）

✅ 会用 pip 安装 Python 包

💡 不会 Python 编程？没关系。本文所有代码复制粘贴即可运行，改一两处配置就行。

3 环境搭建：三步就绪

📌 第一步：安装 Ollama

Ollama 是一个本地大模型运行工具，相当于"你电脑上的大模型服务器"。

去 ollama.com 下载安装包，双击安装。然后打开终端，拉取两个模型：

# 对话模型（回答问题用）
ollama pull qwen2.5:7b

# 嵌入模型（把文字转成向量用）
ollama pull nomic-embed-text

两个模型约 5GB，首次下载需要几分钟。之后全离线运行，不花一分钱。

📌 验证安装

ollama list
# 应该看到 qwen2.5:7b 和 nomic-embed-text

ollama run qwen2.5:7b "你好"
# 能正常回复就说明 OK

📌 第二步：安装 Python 依赖包

pip install langchain langchain-community langchain-ollama \
            chromadb langchain-chroma pypdf python-docx \
            unstructured

⚠️ Windows 用户注意：安装 chromadb 如果报错缺少 C++ 编译工具，改用：
✅ pip install chromadb --only-binary=:all:
国内用户下载慢，加 -i https://pypi.tuna.tsinghua.edu.cn/simple 换清华镜像

📌 第三步：创建项目目录

mkdir my-rag
cd my-rag
mkdir docs        # 用来放你的文档

把你要检索的文档（PDF、Word、TXT）放到 docs 文件夹里。

4 准备文档：你的知识原料

RAG 的效果取决于你喂给它什么。几条建议：

📌 格式支持

📝 .txt — 最可靠，推荐优先用

📄 .pdf — 支持，但复杂排版（双栏、表格）可能解析不好

📃 .docx — 支持

📋 .md — 重命名为 .txt 使用

📌 文档质量建议

✅ 每篇文档聚焦一个主题
✅ 确保文档是 UTF-8 编码（特别是中文 TXT）
✅ 图文混排的 PDF 建议先提取纯文本再放入

💡 快速测试用：创建一个 docs/公司制度.txt，随便粘贴几段规则文字，或者用本文第六节的示例内容。

5 核心代码：五步搭建 RAG

现在开始写代码。创建一个 rag.py 文件，逐步往里加。

📌 步骤 1：加载文档

from langchain_community.document_loaders import DirectoryLoader, TextLoader

# 自动加载 docs 目录下所有 .txt 文件
loader = DirectoryLoader("./docs", glob="**/*.txt", loader_cls=TextLoader)
documents = loader.load()

print(f"✅ 加载了 {len(documents)} 个文档")
for doc in documents:
    print(f" 📄 {doc.metadata['source']} — {len(doc.page_content)} 字符")

📌 步骤 2：文本分块（Chunking）

from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,      # 每个块 500 字符
    chunk_overlap=50,    # 块与块之间重叠 50 字符
    separators=["\n\n", "\n", "。", "！", "？", "，", " ", ""]
)

chunks = text_splitter.split_documents(documents)
print(f"✅ 切成了 {len(chunks)} 个文本块")

💡 为什么要分块？大模型一次能处理的文字有限，且太长的块会掺杂无关信息。500 字符 ≈ 一个中等段落，是实测效果最好的值。重叠 50 字符保证跨块信息不丢失。

📌 步骤 3：向量化并存入 ChromaDB

from langchain_ollama import OllamaEmbeddings
from langchain_chroma import Chroma

embeddings = OllamaEmbeddings(
    model="nomic-embed-text",
    base_url="http://localhost:11434"
)

# 创建向量数据库并持久化到磁盘
vector_store = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db"
)

print(f"✅ 向量数据库已创建，共 {vector_store._collection.count()} 条记录")

💡 首次运行会慢一些——每条文本都要转成向量。第二次运行直接加载 chroma_db 目录里的数据，秒级启动。

📌 步骤 4：构建检索器

retriever = vector_store.as_retriever(
    search_type="similarity",   # 语义相似度搜索
    search_kwargs={"k": 4}      # 每次返回最相关的 4 个文本块
)

📌 步骤 5：接入 LLM 完成问答

from langchain_ollama import ChatOllama
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

llm = ChatOllama(model="qwen2.5:7b", temperature=0.3, base_url="http://localhost:11434")

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个专业的知识库助手。请严格根据以下参考资料回答问题..."),
    ("human", "{question}")
])

# 组装 RAG 链
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)

💡 五步全链路：加载 → 分块 → 向量化 → 检索 → LLM 生成。这就是 RAG 的核心流水线。

8 调优方向

跑通只是第一步。根据实际效果，你可以在几个方向调整：

📌 分块策略

FAQ / 规章制度：chunk_size=300-500  |  短文本，精确匹配

技术文档 / 长文：chunk_size=500-800  |  保留更多上下文

法律合同 / 学术论文：chunk_size=800-1200  |  需要完整逻辑链

📌 检索数量

k=3：简单事实问答  |  k=4-6：一般场景（推荐） |  k=8+：复杂推理，可能引入噪声

📌 模型选择建议

💻 8GB 内存：对话用 qwen2.5:1.5b / deepseek-r1:1.5b  |  嵌入始终用 nomic-embed-text（仅 269MB）

💻 16GB 内存：对话用 qwen2.5:7b / deepseek-r1:7b（推理能力强，适合复杂分析）

💻 32GB+ 内存：对话用 qwen2.5:14b  |  嵌入升级为 bge-m3（多语言更优）

📌 支持更多文档格式

from langchain_community.document_loaders import PyPDFLoader, Docx2txtLoader

pdf_docs = PyPDFLoader("report.pdf").load()
docx_docs = Docx2txtLoader("memo.docx").load()
