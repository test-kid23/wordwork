# 「帮我分析一下数据库」，AI 说做不到——我只多做了这一步，它就真去查了

> 系列：CodeBuddy 入门教程 · 第 4 篇
>
> 读完这篇你能：理解 MCP 是什么、知道怎么配、看完三个实战场景就能自己试试。

---

有天我想让 CodeBuddy 帮我分析一下数据库里上个月的销售数据。

它的回答是："抱歉，我无法访问你的数据库。"

这句话让我愣了两秒。我想起来——它再聪明，也只是一个大模型，知识有截止日期、没有手、没有眼睛、连不了外部系统。它能写操作数据库的代码，但它自己没法"真的去查"。

这就是 AI 的"信息围墙"。Skills 解决的是"怎么做得好"的问题。但如果你需要 AI 真正动手——访问数据库、上网查东西、操作浏览器——你需要这个：**MCP。**

---

## MCP 是什么——史上最接地气的解释

**MCP**，全称 Model Context Protocol（模型上下文协议）。

我知道，这名字听着就想关页面。别。

最准确的类比：**MCP 是 AI 的 USB 接口。**

你插 U 盘 → 电脑能读文件。插打印机 → 电脑能打印。插麦克风 → 电脑能录音。MCP 就是一样的道理：你接入数据库 → AI 能查数据。接入搜索引擎 → AI 能上网。接入文件系统 → AI 能直接读你的本地文件。

这个协议是 Anthropic（Claude 的母公司）在 2024 年底提出来的，现在已经成了 AI 工具的"行规"——Cursor、Claude Code、CodeBuddy 都在用。

> *知识引用：MCP 由 Anthropic 于 2024 年 11 月发布，目的是建立 AI 与外部工具之间的标准化通信协议。*

---

## 内置能力：不需要配就能用的部分

在讲怎么接入外部 MCP 之前，先说 CodeBuddy 已经自带的能力——这些不需要你配任何东西：

| 内置能力 | 实际效果 | 是否需要确认 |
|---------|---------|------------|
| 文件系统 | 读你项目里的文件、搜索代码、写入修改 | 写入需要确认 |
| Shell 终端 | 执行终端命令（npm install、pip install 等） | 需要确认 |
| Web 搜索 | 实时搜索互联网信息 | 自动 |
| 图片生成 | 根据文字描述生成图片 | 自动 |

这些能力已经够你玩一阵子了。但真正的"开挂"，是从接入外部 MCP 开始的。

## 接入外部 MCP——三大实战场景

### 场景 1：接入数据库，让 AI 帮你查数据

你有一个业务数据库，经常需要临时查点东西——"上周哪个产品的退货率最高""这个月新增了多少用户"。以前你要么自己写 SQL，要么找数据分析同事。

接入数据库 MCP 之后，在 CodeBuddy 里直接问就好。

**配置方法**（以 PostgreSQL 为例）：

1. 在你的项目根目录找到或新建 `.mcp.json` 文件
2. 写入配置：

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]
    }
  }
}
```

3. 重启 CodeBuddy，AI 就多了一个"数据库工具"

然后你就可以这么问：

> 查一下 orders 表里上个月的订单总额，按产品分类汇总，列出 Top 5。

CodeBuddy 会自己写 SQL → 自己执行 → 自己整理结果。

**安全问题说在前头**：上面的连接字符串里直接写了密码，这很危险。正确做法是用环境变量：

```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "${DATABASE_URL}"]
    }
  }
}
```

把 `DATABASE_URL` 设到系统环境变量里。另外——**不要把 `.mcp.json` 提交到 GitHub，尤其里面写了密码的话。**

---

### 场景 2：接入浏览器，让 AI 自动操作网页

这是我踩过坑之后才真正弄明白的能力。

你装上 Playwright MCP（浏览器自动化工具）之后，AI 能打开浏览器、浏览网页、点击按钮、提取内容。

**什么时候用**：你需要从某个网页上批量抓数据、自动填表单、或者测试某个网页功能。

**配置方法**（Playwright MCP）：

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@anthropic-ai/mcp-playwright"]
    }
  }
}
```

**实操演示**：

> 打开 https://example.com/reports，把页面上的所有表格数据整理成 Markdown 格式。

AI 的实际执行过程：
1. 打开浏览器（后台，你看不到窗口）
2. 访问目标网址
3. 用选择器定位表格元素
4. 提取数据
5. 把结果输出为 Markdown 表格

**这个能力的真正价值**：你不需要学爬虫、不需要学 Selenium、不需要处理反爬。把需求描述清楚就行。

**局限**：涉及到登录的网页会比较麻烦（需要输密码或验证码），不是所有网站都适合这种操作。

### 场景 3：接入知识库，让 AI 变成"内部通"

你们公司肯定有一些散落在各个地方的知识——飞书文档里的报销流程、Confluence 上的技术方案、钉钉里的通知。

这些信息 AI 本来完全不知道。但如果你把公司的知识库通过 MCP 接入，AI 就能直接搜了。

**实际体验**：

> 公司最新的差旅报销标准是多少？

接入内部知识库 MCP 之后，AI 会检索飞书文档 → 找到最新的报销政策 → 返回给格式化的答案。

这不是"AI 记住了"，是"AI 能实时检索你们的知识库"。信息更新了，AI 的答案也跟着更新。

这种 MCP 通常需要你们公司的技术同学帮忙搭建一个 MCP Server，或者用已有的内部搜索 API 封装。接入方式和上面类似，只是配置指向内网地址。

## 配置文件就长这样——复制即用

所有 MCP 配置都写在项目根目录的 `.mcp.json` 里。文件结构长这样：

```json
{
  "mcpServers": {
    "服务器名1": {
      "command": "运行的命令",
      "args": ["参数1", "参数2"]
    },
    "服务器名2": {
      "command": "python",
      "args": ["-m", "my_mcp_server"]
    }
  }
}
```

**全局 MCP vs 项目 MCP**：
- 放在项目目录（`.mcp.json`）→ 只在这个项目里生效
- 放在用户目录（`~/.codebuddy/.mcp.json`）→ 所有项目通用

建议：通用的（比如 Web 搜索、数据库连接）放全局。跟具体项目相关的（比如公司内部 API）放项目目录。

---

## 四条安全红线

MCP 是 AI 的"手"，既然有手了，就要管住它。

**红线 1**：永远不要在配置文件里写明文密码。用环境变量代替。

**红线 2**：不要把包含内网地址或密钥的 `.mcp.json` 提交到公开仓库。加到 `.gitignore` 里。

**红线 3**：只接入你了解和信任的 MCP Server。第三方 MCP 可能比你想象的"权限大"——它也许能读你电脑上的任意文件。

**红线 4**：涉及到生产数据库时，给 MCP 用的数据库账号只给**只读权限**。别让 AI 有删库的"手"。
