## 总体定位

这是 CodeBuddy 系列的第一部分——**入门教程**。五篇递进，从"这是什么"到"能干什么"到"怎么上手"。

**核心命门**：不能让读者觉得"又是一篇AI味的产品说明书"。每篇都要有**真实场景、真实感受、真实踩坑**。

## 1.1 CodeBuddy 是什么？——你的 AI 工作搭档

### 核心信息
| 项目 | 内容 |
|------|------|
| **一句话价值** | 让读者明白 CodeBuddy 不是"又一个程序员工具"，而是"每个人的AI搭档" |
| **情绪曲线** | 好奇→怀疑→"原来还能这样"→跃跃欲试 |
| **人均阅读时间** | 约5分钟（微信平台） |

### 内容框架

```
【开篇钩子】我用了十几个AI编程工具后，最后为什么留在了CodeBuddy
  - 不是因为它最好，而是因为它最"对味"
  - 从Cursor到Claude Code到Copilot到Qoder，每个都试过
  - "选工具跟选老婆差不多，光看参数没用，得看处不处得来"

【写在前面】这篇写给：
  - 听说过CodeBuddy但不知道值不值得试的人
  - 用过别的AI编程工具，好奇CodeBuddy有什么不同的人
  - 完全不懂编程，但想用AI提升工作效率的人

【正文核心模块】

模块1："一个工具，三种形态"——CodeBuddy 到底是什么
  - 插件版：装进VS Code，像给编辑器加了大脑
  - IDE版：独立的AI编程环境，开箱即用
  - CLI版（CodeBuddy Code）：命令行里的AI搭档，懂行的人最爱上手的版本
  - 我的使用习惯：IDE用来做大项目，CLI用来做快速任务

模块2：三大模式——不是所有AI编程工具都这么设计
  - Ask模式：问就完事了，适合理解代码、学新技术
  - Craft模式：指哪改哪，局部修改利器
  - Plan模式：你描述目标，它自己规划步骤→确认→执行
  - 为什么要三种模式？因为"一次性做对"和"边聊边改"是两种完全不同的场景

模块3：跟竞品比，到底差在哪
  - Claude Code：最强AI脑力，但纯CLI，没图形界面对新手不友好
  - Cursor：编辑器体验好，但AI能力依赖外部模型
  - GitHub Copilot：代码补全王者，但不能像Plan模式那样"接大活"
  - 通义灵码（Qoder）：阿里系，Agent模式强，但是另一个生态
  - CodeBuddy的独特位置：形态最全+生态集成（CloudBase、CloudStudio）+腾讯云背书的免费额度
  - > 知识引用：关于竞品对比，基于我本人2025-2026年对多款工具的长期使用体验

模块4：说点别人不敢说的——它不是万能的
  - 什么情况下CodeBuddy好用：Web开发、脚本工具、文档写作、数据分析
  - 什么情况下不适合：超大型项目（10万行以上）、对精确计算有强需求的场景、做游戏开发
  - 我的真实翻车经历：[具体例子]
  - "别把它当神，把它当人——一个脑子很快但偶尔会犯糊涂的同事"

【说到最后】
  - 一句话总结
  - 下篇预告：1.2 安装与第一次对话——从零到第一个任务
```

### 关键调性要求
- **不要说**："CodeBuddy是新一代AI编程助手的标杆产品，代表了AI辅助开发的前沿方向"
- **要说**："我用了半年，最大的感受就是——它不像工具，更像一个坐在你旁边、随时能帮你干活的搭档"
- 用"我"的视角，而不是"官方"视角
- 可以稍微吐槽竞品，但要客观（说出真实体验）
- 结尾要自然，不用"综上所述"

## 1.2 安装与第一次对话——从零到第一个任务

### 核心信息
| 项目 | 内容 |
|------|------|
| **一句话价值** | 手把手带读者完成第一次使用，消除"不知道怎么开始"的恐惧 |
| **情绪曲线** | "好像不难"→第一次成功（爽感）→"我还能干嘛"（期待） |
| **人均阅读时间** | 约6分钟 |

### 内容框架

```
【开篇钩子】装了三天没打开，你不是一个人
  - 工具装上了、账号注册了，然后呢？对着空白的界面发呆
  - "AI时代最大的障碍不是技术，是迈出第一步的勇气"
  - 这篇不讲理论，跟着做就行

【写在前面】
  - 三个入口你选一个：IDE（推荐新手）/ VS Code 插件（已有VS Code的人）/ CLI（喜欢命令行的）
  - 需要的：一个腾讯云账号（微信登录就行）+ 一个想解决的问题

【正文核心模块】

模块1：选对你的入口——三种安装方式
  - IDE版：去 codebuddy.ai 下载 → 安装 → 微信扫码 → 完事
  - 插件版：VS Code → 扩展商店搜"CodeBuddy" → 安装 → 登录
  - CLI版（进阶）：npm install -g @tencent-ai/codebuddy  → codebuddy login
  - 我的建议：如果你不知道选哪个，就用IDE版，安装包大点但省心

模块2：界面没那么可怕——5分钟看懂
  - 左边：对话区，你跟AI聊天的地方
  - 右边：代码/文件编辑区
  - 底部：终端（暂时可以不管）
  - 左上角三个模式按钮：Ask / Craft / Plan
  - 配图（用最清晰的界面截图标注）

模块3：Ask模式——第一个问题，别问太难的
  - 实操："帮我解释一下这个项目是干什么的"（打开一个项目文件夹）
  - CodeBuddy会读取文件结构→理解代码→用大白话给你讲
  - 读完你就会觉得："卧槽，它真看懂了"
  - 一个小技巧：加上"用口语化的方式解释，当我是个刚入行1年的开发"

模块4：Craft模式——让它改个东西试试
  - 实操："把首页标题的字号调大一点，颜色改成深蓝色"
  - 看它怎么定位文件→修改代码→给你看对比
  - 你可以接受或拒绝修改
  - "这感觉像在跟一个很听话的程序员结对编程"

模块5：Plan模式——第一次"接大活"
  - 实操："帮我做一个简单的每日待办小工具，能在浏览器里用的"
  - 它先给你列出要做的事情（Plan）→ 你确认 → 它开始咔咔干活
  - 整个过程你只需要点"确认"和看它表演
  - 最后真跑起来了——就是这种"卧槽"的瞬间让你上瘾
  - 这个过程实际录制截图，做成分步展示

【防坑提醒】
  - 第一个任务不要贪大，控制在3-5个文件以内
  - 养成随手保存的习惯（虽然CodeBuddy会自动保存Craft的修改）
  - Plan模式执行时别切走，看着它做——出了问题你能及时发现

【说到最后】
  - 你已经完成了"从0到1"
  - 下篇预告：Skills机制——让你的CodeBuddy"学会专业技能"
```

### 关键调性要求
- 像师傅带徒弟，每一步都说清楚"为什么这么做"
- 多配图（实际截图），文字+图结合
- 给读者信心："别怕，我当初也啥都不会"

## 1.3 Skills 机制：给AI装上"专业技能包"

### 核心信息
| 项目 | 内容 |
|------|------|
| **一句话价值** | 理解Skills是正确使用CodeBuddy的转折点——大多数人卡在这里 |
| **情绪曲线** | "原来还有这个"→"怪不得我之前用着一般"→"现在我懂了" |
| **人均阅读时间** | 约6分钟 |

### 内容框架

```
【开篇钩子】我用了3个月CodeBuddy，才发现自己一直在"裸奔"
  - 之前只是把它当成一个高级ChatGPT在代码编辑器里
  - 直到有一次，加载了"python-best-practices"这个Skill
  - 同样的需求，代码质量天差地别
  - "Skills就像给AI换了一个脑子——不，应该说换了整个认知框架"

【写在前面】
  - 这篇是你从"CodeBuddy能用"到"CodeBuddy好用"的分水岭
  - Skills是CodeBuddy最被低估的功能，官方宣传也不多
  - 但懂Skills和不懂Skills的用户，效率差5倍不止

【正文核心模块】

模块1：Skill到底是个啥——用你能理解的方式说
  - 类比1：给AI安装App，每个App让AI精通一个领域
  - 类比2：就像你给新同事发了一份"工作手册"，告诉他公司规范、流程、术语
  - 类比3：足球教练——没有战术板就是野球，有了战术板才叫战术
  - 技术本质：Skill是一组预定义的提示词+工具+流程的组合包
  - > 知识引用：Skill机制的概念最早来自Claude的System Prompt设计，CodeBuddy将其产品化为可插拔模块

模块2：Skills藏在哪——两层存储，意义不同
  - 用户级Skills（~/.codebuddy/skills/）：所有项目通用
  - 项目级Skills（.codebuddy/skills/）：只在这个项目里生效
  - 什么该放用户级：通用技能如"文章写作""代码审查"
  - 什么该放项目级：跟具体项目相关的如"api-endpoint-creator"

模块3：值得一试的内置Skills（分类推荐）
  - 写作类：article-writing、content-engine
  - 编程类：python-best-practices、kotlin-best-practices、backend-api-design
  - 调试类：diagnose、service-debugging
  - 设计类：design-workflow、design-intelligence、ui-ux-pro-max
  - 项目管理类：brainstorm、to-issues、to-prd
  - 个人最爱推荐 TOP 5：[基于我使用频率的真实排名]

模块4：A/B对比实验——同一个任务，有无Skills的差距
  - 任务：用Python写一个API接口，包含数据校验和错误处理
  - 无Skills版：能用，但代码风格松散，缺少边界处理，没有类型标注
  - 加载 python-best-practices + python-api-endpoint-creator：
    - 自动按分层架构（Router→Service→Repository）
    - 加入Pydantic v2数据校验
    - 异步处理+完善的错误返回
    - 连单元测试都给你写好了
  - 展示对比截图（代码片段），让读者直观感受

模块5：Skills + 自定义Agent = 真正的"AI员工"
  - 自定义Agent可以指定默认加载哪些Skills
  - 比如创建"代码审查员"Agent：自动加载 security-checklist + testing-strategies
  - "你可以给每个Agent配不同的技能组合，像组建一支专业团队"

【避坑】
  - 不是Skills越多越好，同时加载的Skill建议不超过3个
  - 加载Skill需要消耗上下文（Context Budget），加多了反而变笨
  - 有些Skill的提示词相互冲突（比如python和kotlin最佳实践同时加载）

【说到最后】
  - 给一个"第一天就能用的Skills组合建议"
  - 下篇预告：MCP——让AI突破信息茧房
```

### 关键调性要求
- 因为是"颠覆认知"的一篇，要有"恍然大悟"的设计感
- A/B对比部分是最有力的说服，要重点写
- 避免写成"Skills列表大全"（那像产品文档）

## 1.4 MCP 协议：让 AI 连接真实世界

### 核心信息
| 项目 | 内容 |
|------|------|
| **一句话价值** | 让读者理解"AI能联网查资料、能读你电脑上的文件、能连数据库"到底是怎么实现的 |
| **情绪曲线** | "AI还能这样？"→"原来这么简单"→"我也可以搭一个" |
| **人均阅读时间** | 约7分钟 |

### 内容框架

```
【开篇钩子】一个让我彻底服气的Moment
  - 某天我想让CodeBuddy帮我查一下某个数据库里的用户数据
  - 它说："我需要连接数据库权限"
  - 我配了一个MCP连接，三行配置
  - 然后它直接查了数据库，分析了数据，给我出了一份报表
  - "那一刻我感觉它不是工具，是一个懂代码的同事"

【写在前面】
  - MCP是"让AI从聊天机器人变成可操作工具"的关键协议
  - 不需要理解底层实现，会配置就行
  - 4个开箱即用的场景+具体配置方法

【正文核心模块】

模块1：MCP是什么——史上最接地气的解释
  - 完整名称：Model Context Protocol（模型上下文协议）
  - 类比：USB接口——你插什么设备，电脑就能用什么功能
  - MCP就是AI的USB接口，接数据库=AI能查数据库，接搜索引擎=AI能上网
  - 为什么需要MCP：因为大模型的知识有截止日期，而且不能"动手"
  - > 知识引用：MCP由Anthropic于2024年底提出，已被多家AI工具采纳为标准协议

模块2：CodeBuddy内置的MCP能力
  - 文件系统：读取/写入/搜索你的项目文件（默认开启）
  - Web搜索：让AI实时搜索互联网（需配置）
  - 终端命令：执行Shell命令（需确认）
  - 图片生成：通过自然语言描述生成图片
  - 这些不需要额外配置，开箱即用

模块3：接入外部MCP——三大实战场景

  场景1：接入数据库
  - 装个PostgreSQL MCP → 配置连接信息 → AI就能查数据了
  - 实际效果演示：让AI"查一下上个月的销售额TOP10产品"
  - 配置代码示例 + 注意事项（别把生产库密码写在明处）

  场景2：接入浏览器自动化
  - 装个Playwright MCP → AI能操作浏览器了
  - 实际效果："帮我把这个网页的内容抓下来整理成表格"
  - CodeBuddy实际执行：打开浏览器→访问网页→提取内容→输出Markdown表格

  场景3：接入知识库搜索
  - 企业微信/飞书知识库 or 你们公司的内部Wiki → 接入后AI就能搜了
  - "帮我查一下公司最新的报销流程"
  - 这才是"私有知识库"的正确打开方式

模块4：配置文件其实就长这样
  - `.mcp.json` 的结构拆解
  - 几个常用MCP的配置模板（复制即用）
  - 全局配置 vs 项目配置的区别

【安全红线】非常重要，必须单列
  - 别把包含密码的配置文件提交到GitHub
  - 用环境变量代替硬编码的密钥
  - 内网服务（数据库等）慎重通过MCP暴露
  - 我只连我信任的MCP Server

【说到最后】
  - MCP真正的价值不在"连上"，而在"连上之后能干什么"
  - 下篇预告：自动化的终极形态——让CodeBuddy自己按时干活
```

### 关键调性要求
- MCP最容易写成技术文档，必须克制——用场景和故事驱动
- 配置文件那段要写得像"抄作业"一样容易
- 安全部分要严肃但不说教

## 1.5 Automations：让 CodeBuddy 替你跑腿

### 核心信息
| 项目 | 内容 |
|------|------|
| **一句话价值** | 让读者学会设置定时任务，实现"AI替你干活"的自动化体验 |
| **情绪曲线** | "还能定时？"→"设一个试试"→"真香"→"我都设了好几个了" |
| **人均阅读时间** | 约5分钟 |

### 内容框架

```
【开篇钩子】早上9点，另一个"我"已经干完了活
  - 我每天到公司第一件事：打开CodeBuddy，看昨晚设的定时任务结果
  - 日报草稿生成好了、代码库巡检报告躺在那、连今天要发的公众号初稿都写完了
  - "Automations是那种你用之前觉得'还好吧'、用之后觉得'怎么没早点发现'的功能"

【写在前面】
  - 这是入门系列最后一篇，也是最"懒人"的一篇
  - 10分钟设好，每天自动干活——投入产出比最高的功能
  - 不需要编程知识，填个表单就行

【正文核心模块】

模块1：Automations到底是什么
  - 一句话：给AI设个闹钟，到点自己起来干活
  - 两种模式：循环任务（每天/每周）和一次性任务（到指定时间做一次）
  - 和Skills/MCP的区别：Skills决定AI"做得好不好"，MCP决定AI"能操作什么"，Automations决定AI"什么时候做"
  - "三者合体才是完全体"

模块2：创建第一个Automation——每天早上8点生成今日工作简报
  - 分步截图演示：
    1. 打开CodeBuddy → 找到Automations面板
    2. 新建 → 输入名称："每日工作简报"
    3. 输入提示词："总结今天的工作重点，列出优先级..."
    4. 设置调度：每天上午8:00 → FREQ=DAILY;BYHOUR=8;BYMINUTE=0
    5. 选择工作目录（在哪个项目里执行）
    6. 保存 → 开启
  - 第一次跑完的结果展示

模块3：调度规则速查——你需要的5个模板
  - 每天早上9点：FREQ=DAILY;BYHOUR=9;BYMINUTE=0
  - 每周一上午10点：FREQ=WEEKLY;BYDAY=MO;BYHOUR=10;BYMINUTE=0
  - 每周一三五下午3点：FREQ=WEEKLY;BYDAY=MO,WE,FR;BYHOUR=15;BYMINUTE=0
  - 每2小时：FREQ=HOURLY;INTERVAL=2
  - 一次性的（比如明天下午2点提醒你开会）：scheduledAt=2026-06-13T14:00
  - 复制粘贴就能用

模块4：实用场景——我的6个真实Automation
  - 每日日报草稿（每天早上8点半）
  - 每周一生成周报初稿
  - 每周五代码库质量巡检
  - 每日早上整理行业新闻摘要
  - 每隔4小时检查一次服务是否正常（配合MCP）
  - 写公众号时，每晚自动推进更新进度
  - 每个场景说清楚：什么提示词 + 什么调度 + 为什么这样设

模块5：进阶技巧——有效期和权限
  - validFrom / validUntil：给任务设有效期，防止临时任务一直跑
  - maxDurationMinutes：防止AI跑太久（默认30分钟够了）
  - 暂停/恢复：休假时可以暂停所有定时任务
  - "不要设太多同时跑的任务，3-5个是甜区"

【写到最后的真心话】
  - Automations真正好用的地方不是"能定时"，而是"定时之后你忘掉它的存在，但它一直在帮你干活"
  - 这是CodeBuddy从"工具"到"同事"的质变
  - 入门五篇结束，下个系列预告：实战场景系列（2.x）
```

### 关键调性要求
- 强调"不用编程就能设"——这是很多非技术读者的心理障碍
- 多用"我设了一个..."这种个人体验，增加信任感
- 调度规则那段做成速查表，实用优先

## 整体写作规范

### 语言风格
| ❌ 禁用 | ✅ 使用 |
|--------|--------|
| "首先、其次、最后、综上所述" | 自然口语，少用过渡标记 |
| "让我们来看看..." | "你看..." / "来，试一下..." |
| "显而易见" / "不言而喻" | 不说废话，直接讲 |
| "在某种程度上" / "从某种意义上" | 去掉，直接说 |
| "值得注意的是" / "值得一提的是" | 去掉，直接说 |
| 每段开头用"此外""另外""同时" | 段落之间用空行自然隔开 |
| 空洞的总结句 | 每段最后一句必须是信息增量 |

### 引用规范
- 涉及第三方数据/研究 → 标注来源
- 涉及个人体验 → 明确标注"我的体验""我自己试过"
- 涉及技术术语 → 第一次出现时给大白话解释
- 涉及竞品 → 客观陈述，基于可核验的公开发布信息

### 章节标题偏好
- 用问句："MCP是什么？——史上最接地气的解释"
- 用对比："我用了三个月，才发现自己一直在裸奔"
- 用悬念："一个让我彻底服气的Moment"
- 避免用："第一节：概述" / "第二部分：核心功能"
