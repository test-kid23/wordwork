1 CLAUDE.md 是什么

官方说法：CLAUDE.md 是 Claude Code 的项目级记忆文件。放在项目根目录，Claude Code 启动时会自动加载。

说人话：

💡 一句话记住：它就是你给 AI 程序员写的入职文档。

跟新同事聊项目，你会告诉他：代码这么结构的、命名这么规范的、测试这么跑的。CLAUDE.md 就是把这些话写成文件，Claude Code 每次启动都会读一遍。

它长什么样？就是一个普通的 Markdown 文件，放在项目根目录：

your-project/
├── CLAUDE.md ← 这个
├── src/
├── tests/
└── ...

内容完全由你决定——你想让 AI 知道什么，就往里写什么。

2 没有它的时候，Claude Code 在猜什么

我用同一个真实需求做对比，看差距有多明显。

📝 需求："给用户模块加一个修改密码的接口"

🔹 没有 CLAUDE.md 时

它看你是 Python 项目，用了 Flask 风格——但你的项目是 FastAPI。
它看文件都在 src/ 下，就在 src/ 新建了——但你的 API 约定放 src/api/。
它写了 unittest.TestCase——但你的测试框架是 pytest + fixture。
它 import 了 from src.models.user——但你的路径是 from app.models.user。

代码能跑，功能对。但要并入主分支，需手动调整 4 处。

🔹 有 CLAUDE.md 时

它知道项目用 FastAPI，直接用 APIRouter，文件放 src/api/。
它知道代码风格要过 ruff format，格式跟你项目完全一致。
它知道测试框架是 pytest，自动创建 fixture，放 tests/api/ 下。
它知道 import 路径是 app.xxx，所有引用都对。
写完代码后，还自动跑了一遍 pytest。

零返工。

🎯 同一个需求。没有 CLAUDE.md 返工 4 处，有它零返工。
不是 AI 变聪明了，是你把规矩告诉它了。

3 一份好 CLAUDE.md 的骨架（附模板）

下面是一份可以直接复用的模板。前几项必须写，后面的按你项目情况来。

# 项目名称

## 项目简介
一句话说清楚这个项目是干什么的。比如：
"这是一个电商后台管理系统，负责商品管理、订单处理和用户管理。"

## 技术栈
- 后端：Python 3.11 + FastAPI
- 数据库：PostgreSQL + SQLAlchemy
- 测试：pytest + httpx
- 前端：React + TypeScript

## 项目结构
src/
├── api/ # API 路由层
├── models/ # 数据模型
├── services/ # 业务逻辑层
├── schemas/ # Pydantic 模型
└── utils/ # 工具函数

## 编码规范
- 使用 ruff 进行代码格式化和 lint
- 类型注解：所有函数必须注明参数类型和返回值
- 命名：文件名小写下划线，类名大驼峰
- import 路径：使用 app.xxx 格式

## 命令
- 启动：uvicorn app.main:app --reload
- 测试：pytest tests/ -v
- 检查：ruff check .

## 注意事项
- 敏感信息从环境变量读取
- 新增接口必须在 tests/api/ 下写测试
- commit 前必须 run ruff check 和 pytest

📌 每个部分的写法要点

① 项目简介
一句话就行。Claude Code 需要知道"这个项目是卖货的还是做社交的"，这决定了代码的整体倾向。

② 技术栈
精确到版本号。不同版本的 API 差异很大，Python 3.10 的 Union 写法和 3.11 的 X | Y 写法不一样。

③ 项目结构
这是最值钱的部分。Claude Code 虽然能自己翻目录，但它不知道你的命名约定——到底是 src/api/ 还是 src/routes/？是 utils/ 还是 helpers/？写明白了，它新建文件就不会放错地方。

④ 编码规范
告诉它你的 lint 工具是什么、命名风格是什么。这样它写出来的代码就能直接通过 lint 检查，你不用手动调格式。

⑤ 命令
把常用命令写上。Claude Code 在跑测试、装依赖的时候会自动用这些命令，不用你每次都手敲一遍。

⑥ 注意事项
把你项目里的"潜规则"写下来。比如"数据库密码从环境变量读"、"commit 前要跑测试"。这些都是新同事最容易犯的错，AI 也一样。

4 上下文管理的三个层次

有了 CLAUDE.md 之后，Claude Code 的知识来源有三个层次，越精确定位越准：

第 1 层：会话内临时说明 → 当前对话 → 说完就忘 → 比如"这次重构别动 user 模块"

第 2 层：CLAUDE.md → 整个项目 → 永久 → 上面模板里的所有内容

第 3 层：工作区文件 → AI 实时读取 → 实时 → 你 @ 引用的文件、AI 自己翻到的代码

💡 关键原则：不同信息放不同层。

举个例子：你要重构订单模块，但特意嘱咐它"别碰 login.py，那个文件有坑"。

✅ 会话里说一句就行——这是临时约束，不是项目级规则。
❌ 不用写到 CLAUDE.md——CLAUDE.md 只放通用的、持久的信息。

很多人 CLAUDE.md 写得又长又杂，就是因为把会话级约束也塞进去了。保持精简，只放长期有效的信息。

5 Hook 机制：让它自动做规矩

这是 CLAUDE.md 里一个被严重低估的功能。Hook 就是在特定事件发生时，Claude Code 自动执行你设定好的行为。

✅ 每次写完代码，自动跑 ruff 格式化一遍。

✅ 每次 commit 之前，自动跑一遍全部测试。

✅ 每次启动对话，自动检查当前分支是否是最新的。

这些行为你不需要每次都手动提醒它。写在 CLAUDE.md 的 Hook 区域里，它就自动执行。

📌 基础 Hook 写法

## Hooks

### 保存文件时
- 自动执行：ruff format {file_path}

### commit 之前
- 自动执行：pytest tests/ -v
- 自动执行：ruff check .

📌 一个很实用的进阶配置

## Hooks

### 启动对话时
- 自动执行：git status # 先告诉我当前分支状态

### 每次修改文件后
- 如果没有对应测试文件，提醒我是否要创建

### 准备 commit 时
- 自动跑一次项目全部测试
- 如果有失败，禁止 commit

💡 这个配置的效果：你再也不会说"糟了忘跑测试就 push 了"——AI 替你记住了。

写在最后

CLAUDE.md 可能是 Claude Code 里"投入产出比"最高的东西。

写它只需要 10 分钟。但写完之后，Claude Code 对你项目的理解从"猜"变成了"知道"。每一次跟它交互，你的时间都花在业务逻辑上，而不是纠正格式、调整路径、改命名规范。

🚀 建一个 CLAUDE.md 吧。就现在。
把技术栈、项目结构、编码规范、注意事项填进去。
然后让 Claude Code 重新做一件它之前做过的事，看看差别。
