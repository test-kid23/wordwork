1 进场第一步：别打开代码，先让它画地图

大多数人拿到新项目的习惯：点开文件夹 → 看到几十个目录 → 随便点一个 → 看不懂 → 关掉 → 焦虑。

停。别自己翻了。

Claude Code 最擅长的事之一，就是快速理解和总结项目结构。让它替你做地毯式扫描。

📌 实操：一句话获取项目全景

在项目根目录打开终端，敲 claude，然后：

"分析一下这个项目的整体结构。列出所有一级和二级目录，说明每个目录的作用。然后告诉我这个项目的技术栈和主要依赖。"

它会做什么：

• 扫描 package.json / requirements.txt / go.mod 等依赖文件，告诉你用了什么技术
• 遍历目录树，根据文件命名推断各目录的职责
• 找到 README、配置文件、构建脚本，提取关键信息

整个过程大概 30 秒。你什么都不用干——它读文件，你等结果。

📌 它会给你什么

类似这样的输出：

这个项目是一个基于 React + Express 的全栈 Web 应用：

技术栈：
- 前端：React 18 + TypeScript + Vite + Ant Design
- 后端：Express + TypeScript + Prisma ORM
- 数据库：PostgreSQL（通过 Prisma 管理）
- 测试：Jest（前端）/ Vitest（后端）

目录结构：
src/
├── client/          # React 前端代码
│   ├── components/  # 可复用 UI 组件
│   ├── pages/       # 页面级组件
│   ├── hooks/       # 自定义 React Hooks
│   └── utils/       # 前端工具函数
├── server/          # Express 后端代码
│   ├── routes/      # API 路由定义
│   ├── services/    # 业务逻辑层
│   ├── models/      # 数据模型
│   └── middleware/   # 中间件
└── shared/          # 前后端共享的类型定义

你花 30 秒得到的这页信息，自己翻可能要 20 分钟——而且还不一定准确。

📌 扩展：生成模块依赖关系

基础地图有了，接下来看模块之间的关系：

"分析各模块之间的依赖关系。哪些模块被引用最多？哪些是核心基础设施模块？有没有循环依赖？"

它会做更深入的事情——追踪 import 语句、分析文件引用频率、找出"中枢模块"。

💡 一句话记住：你知道改动一个文件会波及哪些模块，这是接手陌生项目最关键的信息。老员工脑子里都有这张地图，新人没有——但现在你有了。

2 定位核心：找到"第一行代码"在哪

项目结构看过一遍了，但你还是不知道"这个系统的入口在哪"。

一个项目有几十个入口候选：main.go、app.ts、server.py、App.jsx……哪个才是真正的起点？

📌 实操：让 Claude Code 定位入口

"找到这个项目的所有入口文件——哪个文件是启动入口、哪个是前端入口、哪个是路由入口、哪个是数据库入口。按启动顺序排列。"

它会做的事情：

• 搜索 main、bootstrap、start、listen 等关键词定位启动文件
• 从启动文件出发，追踪 import 链，绘制启动流程
• 列出每个入口的路径和作用

📌 输出示例

启动链路（从前到后）：

1. server/src/index.ts（服务器启动）
   - 加载环境变量
   - 初始化数据库连接
   - 注册中间件
   - 挂载路由
   - 监听 3000 端口

2. client/src/main.tsx（前端入口）
   - 渲染 React 根组件
   - 加载全局样式
   - 初始化路由

3. server/src/routes/index.ts（路由入口）
   - 汇总所有子路由
   - /api/auth  → auth.router
   - /api/users → users.router
   ...

到这里，你已经知道了：

• 按什么顺序读代码（从启动文件开始，沿 import 链走）
• 每个文件在整体架构中的位置（是入口、中间层、还是工具）
• 要加新功能应该先找哪个文件

3 追踪链路：一个用户请求走过了哪些文件

这是我最推荐的一步——挑一个最核心的业务功能，让 Claude Code 追踪完整的执行链路。

比如一个用户登录：从前端表单提交 → API 调用 → 身份验证 → 数据库查询 → 返回 Token。这条链路穿过了多少个文件？

📌 实操：端到端链路追踪

"追踪用户登录功能的完整执行链路。从前端点击登录按钮开始，到后端返回 JWT Token 并写入前端存储结束。列出这条链路上经过的每一个文件，标注每个文件做了什么。"

Claude Code 会做的事：

• 从前端搜索跟登录相关的组件和 API 调用
• 从后端搜索 auth/login 路由和处理函数
• 追踪数据库查询（查用户表、验证密码）
• 追踪中间件（比如密码加密、JWT 签发）
• 把所有环节串成一条线

📌 为什么这一步特别值钱

你接手别人代码时，最崩溃的体验不是"代码看不懂"，而是"改一个地方，不知道会影响到哪"。

知道登录功能经过了 8 个文件之后——你改第 3 个，就知道第 5、第 7 个可能受影响。这是老员工的肌肉记忆，你用 3 分钟就拿到了。

更进一步，你还可以问：

"如果我要把这个项目的数据库从 PostgreSQL 换成 MySQL，哪些文件需要改？"

它会告诉你所有涉及数据库查询的文件——不用你自己满世界搜 import prisma。

4 看懂难点：让 AI 解释你不理解的代码

你一定会遇到这种情况：找到一段代码，每个字都认识，连起来不知道在干什么。

可能是复杂的递归、绕来绕去的状态管理、一看就是写了三手的中间件。

📌 实操：解释任意一段代码

"解释 server/src/services/order.service.ts 中的 calculateRefund 函数在做什么。包含它的输入、输出、边界条件、以及为什么这样设计。"

Claude Code 会做：

• 逐行解析代码逻辑
• 标注变量含义和类型
• 识别算法的意图（不只看代码做了什么，还看为什么这样做）
• 指出潜在的边界条件问题

📌 进阶：从特殊到一般

弄懂了一个函数，还想理解整个模块的设计模式：

"server/src/services/ 目录下的服务层用了什么设计模式？跟 server/src/utils/ 的区别是什么？为什么要把逻辑拆到 services 而不是直接写在 routes 里？"

它不只是回答你"用了 Service 模式"，还会结合这个项目的实际代码举例说明。这种理解速度，你自己啃代码可能需要一周才能悟出来。

5 交付一份"新人入职文档"

前面四步做完，你对这个项目的理解和老员工的差距已经缩小了一大截。

但这些都是临时对话——换一台机器、换一个会话，就没有了。最后一步：把前面的分析沉淀成文档。

📌 实操：让它帮你写一份项目概览文档

"基于前面的分析，帮我写一份 PROJECT_OVERVIEW.md，包含：1）项目简介和技术栈 2）目录结构说明 3）启动方式 4）核心业务链路 5）常见开发任务指引（比如怎么加一个新 API、怎么改前端页面）"

Claude Code 会：

• 把前面分析的所有内容汇总
• 用 Markdown 格式输出
• 补充你的项目特有的信息

这份文档有两个用途：

① 当下：是你自己理解项目的笔记，后续开发随时查阅
② 以后：下一个新人入职，不用再从零开始——直接看这份文档就能上手

如果你觉得不够，还可以追加：

"在这个目录里搜索所有的 TODO、FIXME、HACK 注释，汇总成一份 TECH_DEBT.md。"

几分钟拿到一份技术债清单。这件事手动做有多痛苦，做过的人都知道。

✦ 一小时复盘

这一小时你做了什么：

📅 0-15min 项目结构+技术栈+模块依赖
传统 1-2 天 → 现在 30 秒

📅 15-30min 定位入口+启动链路
传统 半天 → 现在 15 分钟

📅 30-45min 追踪核心业务链路
传统 2-3 天 → 现在 15 分钟

📅 45-55min 理解复杂代码+设计模式
传统 1 周以上 → 现在 10 分钟

📅 55-60min 生成项目文档+技术债清单
传统 半天 → 现在 5 分钟

💡 一句话记住：60 分钟，完成了传统方式可能需要两周的信息收集工作。

不是说你用它就能跳过所有学习曲线——理解代码还是需要你自己看、自己改、自己踩坑。但它帮你把"找代码"的时间压缩到了极限，把时间真正花在"理解代码"上。

━━━━━━━━━━━━━━

写在最后

这一篇的内容其实回应了很多人对 AI 工具的一个质疑："用 AI 写代码的人看不懂自己的代码。"

对，如果你让 AI 直接帮你写代码而你不过脑子，你确实看不懂。但如果你让 AI 帮你理解别人的代码，你是在加速学习，不是在跳过学习。

接手陌生项目的关键瓶颈不是"看不懂"，而是"找不到"。你不知道哪段代码值得看、哪段代码先看、哪段代码跟哪段有关系。

💡 关键洞察：Claude Code 帮你解决的是"找"的问题，"懂"的问题还是你自己的功课。
