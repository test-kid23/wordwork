# Claude Code 写代码全靠猜？因为你没给它这份「入职文档」

> 同一个需求，有 CLAUDE.md 和没有 CLAUDE.md，AI 的输出质量差了一个级别——不是它能力不够，是你没告诉它规矩。

---

你有没有遇到过这种情况：Claude Code 帮你写了段代码，功能是对的，但风格跟你项目里其他文件完全不一样。命名规范不对、目录放错了、import 的路径也跟项目惯例不同。

你叹口气，手动改回去。心里想的是"AI 也就这样了"。

**问题不在 AI。问题在你没给它"入职培训"。**

你招一个新同事进来，会不会让他直接看代码就干活？你会给他一个 Onboarding 文档，告诉他项目是干什么的、技术栈是什么、代码风格怎么约定、测试命令怎么跑。

Claude Code 也一样。只不过那份文档不叫 Onboarding，叫 **CLAUDE.md**。

我第一次知道这个文件的时候已经用了 Claude Code 快一个月了。回头看之前让它写的那些代码，好多返工都是因为同一个原因：**我默认它"应该知道"，但它并不知道。**

## 一、CLAUDE.md 是什么

官方说法：CLAUDE.md 是 Claude Code 的**项目级记忆文件**。放在项目根目录，Claude Code 启动时会自动加载。

说人话：**它就是你给 AI 程序员写的入职文档。**

跟新同事聊项目，你会告诉他：我们的代码是这样的结构、我们遵循这个命名规范、测试命令跑这条、数据库配置在这里看。CLAUDE.md 就是把这些话写成文件，Claude Code 每次启动都会读一遍。

它长什么样？就是一个普通的 Markdown 文件，放在项目根目录：

```
your-project/
├── CLAUDE.md          ← 这个
├── src/
├── tests/
└── ...
```

内容完全由你决定——你想让 AI 知道什么，就往里写什么。

## 二、没有它的时候，Claude Code 在猜什么

为了让你直观感受差异，我用同一个真实需求对比一下。

**需求：** "给用户模块加一个修改密码的接口"

### 没有 CLAUDE.md 时的输出

Claude Code 会从项目代码里"猜"你的套路。但它猜得不一定对：

- 它看你是 Python 项目，就用了标准的 Flask 风格。但你的项目用的是 FastAPI。
- 它看你的文件都放在 `src/` 下，就在 `src/` 里新建了一个文件。但你的 API 文件约定放在 `src/api/` 下。
- 它写了一个测试，跑的通。但你的项目用的是 pytest + fixture，它写了 unittest.TestCase。
- 它 import 了 `from src.models.user import User`。但你的项目 import 约定是 `from app.models.user import User`。

代码能跑，功能对。但你要把它并入主分支，需要手动调整四处。

**这不是它能力不行，是它不知道规矩。**

### 有 CLAUDE.md 时的输出

同一段需求，有了 CLAUDE.md 之后：

- 它知道这项目用的是 FastAPI，直接在 `src/api/` 下创建 `user_password.py`，用 FastAPI 的 `APIRouter`。
- 它知道代码风格要遵循 `ruff format`，写出来的代码格式跟你项目完全一致。
- 它知道测试框架是 pytest，自动创建 fixture，放在 `tests/api/` 下。
- 它知道 import 路径约定是用 `app.xxx`，所有引用都对。
- 写完代码之后，它还自动跑了一遍 `pytest tests/api/test_user_password.py`。

**同一个需求。没有 CLAUDE.md 时返工 4 处，有 CLAUDE.md 时零返工。**

这个差距不是 AI 变聪明了，是你把规矩告诉它了。

## 三、一份好 CLAUDE.md 的骨架

下面是一份**可以直接复用的模板**。前几项必须写，后面的按你项目情况来。

```markdown
# 项目名称

## 项目简介
一句话说清楚这个项目是干什么的。比如：
"这是一个电商后台管理系统，负责商品管理、订单处理和用户管理。"

## 技术栈
- 后端：Python 3.11 + FastAPI
- 数据库：PostgreSQL + SQLAlchemy
- 测试：pytest + httpx
- 前端：React + TypeScript

## 项目结构
src/
├── api/          # API 路由层，每个模块一个文件
├── models/       # SQLAlchemy 数据模型
├── services/     # 业务逻辑层
├── schemas/      # Pydantic 请求/响应模型
└── utils/        # 工具函数
tests/
├── api/          # API 测试
└── unit/         # 单元测试

## 编码规范
- 使用 ruff 进行代码格式化和 lint
- 类型注解：所有函数必须注明参数类型和返回值
- 命名：文件名小写下划线，类名大驼峰，函数名小写下划线
- import 路径：所有内部引用使用 `app.xxx` 格式

## 命令
- 启动开发服务器：`uvicorn app.main:app --reload`
- 运行测试：`pytest tests/ -v`
- 代码检查：`ruff check .`
- 数据库迁移：`alembic upgrade head`

## 注意事项
- 敏感信息（API Key、数据库密码）从环境变量读取，不要硬编码
- 新增接口必须在 tests/api/ 下写对应测试
- commit 之前必须运行 ruff check 和 pytest
```

### 每个部分的写法要点

**项目简介** —— 一句话就行。Claude Code 需要知道上下文，它要知道"这个项目是卖货的还是做社交的"，这决定了代码的整体倾向。

**技术栈** —— 精确到版本号。不同版本的 API 差异很大，比如 Python 3.10 的 Union 写法和 3.11 的 `X | Y` 写法不一样。你写了版本号，它就按那个版本的写法来。

**项目结构** —— 这是最值钱的部分。Claude Code 虽然能自己翻目录，但它不知道你的**命名约定**。到底是 `src/api/` 还是 `src/routes/`？是 `utils/` 还是 `helpers/`？写明白了，它新建文件就不会放错地方。

**编码规范** —— 告诉它你的 lint 工具是什么、命名风格是什么。这样它写出来的代码就能通过 lint 检查，你不用手动调格式。

**命令** —— 把常用命令写上。Claude Code 在跑测试、装依赖的时候会自动用这些命令，不用你每次都手敲一遍。

**注意事项** —— 把你项目里的"潜规则"写下来。比如"数据库密码从环境变量读"、"commit 前要跑测试"。这些都是新同事最容易犯的错，AI 也一样。

## 四、上下文管理的三个层次

有了 CLAUDE.md 之后，Claude Code 的知识来源有三个层次，越精确定位越准：

| 层次 | 作用范围 | 管多久 | 写什么 |
|------|----------|--------|--------|
| **会话内临时说明** | 当前对话 | 说完就忘 | "这次重构别动 user 模块" |
| **CLAUDE.md** | 整个项目 | 永久 | 上面模板里的所有内容 |
| **工作区文件** | AI 实时读取 | 实时 | 你 @ 引用的文件、AI 自己翻到的代码 |

**理解这个分层很重要，因为不同信息放在不同层，效果完全不同。**

举个例子：你要重构订单模块的代码，但特别嘱咐它"别碰 login.py，那个文件有坑"。

- 放在会话里说一句就行。"这次别动 login.py"——这就够了。
- 不用写到 CLAUDE.md 里。"别动 login.py" 是一个临时的、针对本次任务的约束，不是项目级规则。
- CLAUDE.md 放的是**通用的、持久的**规则，比如"所有 API 路由放在 src/api/ 下"。

很多人的 CLAUDE.md 写得又长又杂，是因为把会话级的约束也塞进去了。保持 CLAUDE.md 精简，只放长期有效的信息。

## 五、Hook 机制：让它自动做规矩

这是 CLAUDE.md 里一个被严重低估的功能。

**Hook** 就是在特定事件发生时，Claude Code 自动执行你设定好的行为。比如：

- **每次写完代码，自动跑 ruff 格式化一遍。**
- **每次 commit 之前，自动跑一遍测试。**
- **每次启动对话，自动检查当前分支是否是最新的。**

这些行为你不需要每次都手动提醒它。写在 CLAUDE.md 的 Hook 区域里，它就自动执行。

在 CLAUDE.md 里加 Hook 的写法：

```markdown
## Hooks

### 保存文件时
- 自动执行：`ruff format {file_path}`

### commit 之前
- 自动执行：`pytest tests/ -v`
- 自动执行：`ruff check .`
```

Hook 写好了之后，你不用再每次说"格式化一下代码"或"跑一下测试"。它会在对的时机自动做对的事。

**一个很实用的 Hook 示例：**

```markdown
## Hooks

### 启动对话时
- 自动执行：`git status`  # 先告诉我当前分支状态

### 每次修改文件后
- 如果没有对应测试文件，提醒我是否要创建

### 准备 commit 时
- 自动跑一次项目全部测试
- 如果有失败，禁止 commit
```

这个配置的效果是：你再也不会说"糟了忘跑测试就 push 了"这种事。AI 替你记住了。

## 写在最后

CLAUDE.md 可能是 Claude Code 里"投入产出比"最高的东西。

写它只需要 10 分钟。但写完之后，Claude Code 对你项目的理解从"猜"变成了"知道"。每一次跟它交互，你的时间都花在业务逻辑上，而不是纠正格式、调整路径、改命名规范。

**建一个 CLAUDE.md 吧。就现在。把技术栈、项目结构、编码规范、注意事项填进去。然后让 Claude Code 重新做一件它之前做过的事，看看差别。**

下一期聊 Claude Code 的权限模型与安全边界——怎么放心地把文件系统和命令行交出去，而不用担心它搞出生产事故。
